# HWP 차트 제목·데이터 실물 검증

이 기록은 HWP 5 바이너리의 GSO OLE 컨트롤이 참조하는 내장 `OOXMLChartContents`에 한정한다. 동일 문서의 HWPX 출력과, XML 원문을 별도로 읽어 얻은 값·명시적 제목·종류·계열 이름을 정답으로 삼았다. 독립 판독은 DTD·엔티티 선언을 사전 거부한 뒤 표준 라이브러리로 파싱하며, dochan 차트 파서를 사용하지 않는다. 검증 명령은 `python -m scripts.verify_hwp_charts "$HWP_PUBLIC_DIR" "$HWPX_PUBLIC_DIR" --internal "$HWP_PAIR_DIR"`이다. 세 변수에는 각 코퍼스 디렉터리 경로를 전달한다.

| 칸 | 표본 파일 | 정답 근거 | 기대 | 실제 | 판정 |
| --- | --- | --- | --- | --- | --- |
| 차트 제목/데이터 · HWP | `2차원원형.hwp`와 같은 이름의 HWPX | HWPX 차트 문단·표 및 내장 `OOXMLChartContents`의 `c:pt/c:v`, `c:ser/c:tx`, `c:plotArea` | 원형 종류·제목·범주·값이 같은 위치와 형식으로 나온다. | HWP/HWPX 차트 출력이 일치했고, XML 원문 대조도 일치했다. | 통과 |
| 차트 제목/데이터 · HWP | `chart_01_single_column.hwp`와 같은 이름의 HWPX | HWPX 계열별 표 및 내장 XML 원문 | 세 계열 표의 열 이름과 값, 차트 종류가 일치한다. | HWP/HWPX 차트 출력이 일치했고, XML 원문 대조도 일치했다. | 통과 |
| 차트 제목/데이터 · HWP | 공개 코퍼스의 참조된 OOXML 차트 전체 | 내장 XML 원문을 독립 판독하고 같은 이름의 HWPX 출력을 대조 | 계열·범주·값·명시적 제목·종류를 보존한다. | 차트 38/38개에서 원문 값과 종류가 일치했다. 명시적 제목 6/6개와 계열 이름 89/89개가 일치했다. HWP/HWPX 짝은 26/26문서에서 차트 제목·캡션·표가 일치했다. | 검증 범위 통과 |
| 차트 제목/데이터 · HWP | 공개 코퍼스의 `Contents` 전용 OLE | 내장 CFB의 스트림 목록과 원시 바이트 관찰 | OOXML 차트 XML이 없으면 값을 추측하지 않는다. | 참조된 `Contents` 전용 OLE 스트림 38개를 집계했다. 이 안에는 일반 OLE도 섞여 있어 차트만의 개수는 확정하지 않았다. 손상 OLE 스트림 1개도 별도로 집계했다. | 해석 대상 밖 |

공개 HWP 5,363개를 수정 전후에 읽어 Markdown의 SHA-256 해시만 비교했다. 변경된 문서는 35개이며, 모두 `BinData`에 OLE가 있는 문서였다. 문서 단위 예외는 수정 전후 모두 0개이고 기존 `ERR` 4개는 그대로였으며 새 `ERR`는 0개였다. 새 `WARN`은 9개로, 8개는 빈 범주 캐시를 번호로 채웠다는 알림이고 1개는 없는 BinData 참조 알림이다. 압축 해제 크기·CFB 길이·OLE 개체 수 제한과 손상 입력의 경고 강등은 합성 단위 테스트로 확인했다.

내부 실물 HWP/HWPX 짝 76개의 기존 비교 지표는 수정 전후 동일했다. 내부 짝에서는 이 작업의 OOXML 차트 양성 표본을 찾지 못했다. 내부 표본 이름과 내용은 기록하지 않았다.

작업 의뢰의 사전 집계는 차트 OLE 42문서, OOXML 35문서, `Contents` 전용 차트 7문서, HWP/HWPX 짝 27문서였다. 이번 전수 판독은 OOXML 차트가 있는 문서 35개와 XML 차트 38개를 확인했지만, XML 차트가 있고 같은 이름의 HWPX도 있는 짝은 26개였다. `Contents`라는 스트림 이름만으로는 차트와 일반 OLE를 구별할 수 없어 7개라는 차트 전용 수치를 독립적으로 재현하지 않았다. 이 차이는 지원 범위 판정에서 제외하지 않고 한계로 남긴다.
