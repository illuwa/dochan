# 지원 표 각주

README `Supported Elements` 표의 칸별 범위와 한계다. ✅ 는 단위 테스트와 실물 문서 검증을 모두 통과한 칸에만
붙인다. 검증 표본·정답 근거·수치는 `docs/benchmarks/` 의 날짜별 기록에 있다(2026-10-02·03 기록이 1.7.0 분).
실물 표본은 공개 자료(Apache POI·LibreOffice·Apache Tika 테스트 문서, pdf.js 테스트 PDF, 공개 HWP/HWPX)와
저장소 밖 내부 실물 짝이며, 내부 문서의 이름·내용은 기록하지 않는다.

## 암호화 문서

- **HWP**: 한컴 배포용 문서(복사·인쇄 제한용으로 본문을 암호화한 문서)를 한컴 공개 명세대로 복호화한다(공개 27파일·65섹션
  검사값 일치). 열기 암호로 보호된 HWP 는 지원하지 않으며 명확한 오류로 거부한다.
- **HWPX**: ODF 매니페스트에 기록된 SHA-256 시작 키, PBKDF2-HMAC-SHA1, AES-256-CBC, raw deflate 및
  압축 해제 본문의 앞 1 KiB SHA-256 검사값을 쓰는 열기 암호를 읽는다. 공개 `encrypt.hwpx`의 암호화 항목 6개와
  본문·그림 2개를 확인했다. 암호가 없거나 틀리면 명확한 오류로 거부한다. 한컴 배포용 HWPX 두 개도 암호가
  필요하다고 진단하지만, 공개되지 않은 키 도출 방식은 복호화하지 않는다. 다른 암호 알고리즘과 손상된
  암호화 메타데이터는 지원하지 않는 HWPX 암호화 오류로 거부한다. 키 유도는 고유 salt·반복 횟수 조합의
  합계 100만 회, AES 복호화는 문서당 16 MiB로 제한한다. 사용하지 않는 Preview·BinData는 복호화하지 않는다.
- **DOC**: RC4·RC4 CryptoAPI 는 공개 실물로 검증했다. XOR 난독화(방법 2)는 공개 실물 표본이 없어(POI·LibreOffice·Tika
  WordDocument 358개 중 0개) 합성 문서로만 검증했다.
- **PPT**: RC4 CryptoAPI(`CryptSession10Container`)이며 슬라이드와 그림 스트림을 함께 복호화한다. 암호를 주지 않으면
  [MS-OFFCRYPTO] 의 기본 암호를 시도한다.
- **XLS**: XOR 난독화(방법 1)·RC4·RC4 CryptoAPI. 암호를 주지 않으면 Excel 기본 암호(`VelvetSweatshop`)를 시도한다.
- **DOCX·PPTX·XLSX**: [MS-OFFCRYPTO] Standard·Agile(AES-CBC). 인증서 기반 키, AES-CBC 가 아닌 Agile 암호, 암호화된
  XLSB 는 오류로 거부한다. 암호 패키지는 16 MiB 까지 받는다(키 유도·복호화 작업량에 결정적 상한). PPTX 는 공개 실물
  1개(Standard)로 확인했고 Agile 은 같은 엔진으로 DOCX·XLSX 실물에서 확인했다.
- **PDF**: 표준 보안 핸들러 R2–R6(RC4·AES-128·AES-256)의 빈 암호와 사용자 암호. 비표준 보안 핸들러는 오류.
- 공통: 암호는 `Dochan(path, password=...)`, CLI 는 `--password-stdin` 또는 `DOCHAN_PASSWORD` 로만 받는다(명령줄 인자로는
  받지 않는다). `batch` 는 문서마다 암호가 달라 암호를 받지 않는다. 암호 값은 오류·경고·출력에 쓰지 않는다.

## 표·캡션

- **표 (중첩 텍스트) · PPT·PPTX (—)**: PowerPoint 표 셀은 다른 표를 담는 구조가 없다. 셀 안 여러 문단은 보존한다.
- **텍스트 · PDF Form XObject**: 페이지가 Form XObject(`Do`)로 그린 글자도 읽는다(행렬·자원 상속·텍스트 상태 상속·BBox 클립·MCID 격리). 공개 pdf.js 983개 중
  Form 글자가 있는 39개에서 PDFium 대비 읽을 수 있는 문자 재현율 95.8%→98.5%. 순환·깊이·반복 호출·Form 바이트(페이지당 16 MiB)·Form 해제 예산(문서당 200 MiB,
  페이지 본문 예산과 별도)에 상한을 둔다. 주석 외관 스트림(/AP)과 Form 안 이미지는 읽지 않는다([검증 기록](benchmarks/2026-10-02-pdf-forms-fix-real-docs.md)).
- **텍스트 · PDF CID 폰트**: ToUnicode가 없으면 Identity-H/V와 Adobe의 미리 정의된 CMap에서 코드→CID를 찾고, Adobe CID→Unicode 표 또는 내장 TrueType의 CIDToGIDMap·Unicode cmap을 확인해 복원한다. 표 118의 59개와 `90pv-RKSJ-V`·`KSCpc-EUC-V` 2개를 포함한다. 내장 Encoding CMap 스트림의 코드 공간·CID 범위·본문 `usecmap`과 사전 `/UseCMap` 부모도 읽는다. ToUnicode가 있으면 원래 코드 바이트로 조회하며, 폭은 CID를 기준으로 계산한다. 내장 Unicode cmap이 없는 글꼴은 CIDFont의 Registry·Ordering이 Adobe CID 대응표와 일치하고 해당 CID가 표에 있을 때만 복원한다. 내장 CIDFontType2가 CID를 GID로 직접 쓰고 명시적 CIDToGIDMap 스트림이 없으면 Adobe 표를 적용하지 않는다. Encoding 스트림의 `bfchar`·`bfrange`는 코드→CID 연산자가 아니므로 해석하지 않는다. 제어 문자·사설 영역·비문자 대응은 버리고 변형 선택자는 떼어 내 기본 글자만 내며, 근거가 없는 코드는 경고와 함께 생략한다([기존 검증](benchmarks/2026-10-03-pdf-cid-unicode-real-docs.md), [CMap 검증](benchmarks/2026-10-04-pdf-predefined-cmap-real-docs.md)).
- **표 (중첩 텍스트) · PDF (⬜)**: 셀 안에 따로 그려진 표와, 부모 셀의 한 변만 공유하는 닫힌 연결형 중첩 표를 복원한다(내부 실물 66개 중 26개 일치,
  중첩 없는 음성 66문서·공개 983개 오탐 0). 여러 변을 공유하는 연결형과 한 성분 안의 복수 후보는 원형대로 둔다.
- **표 병합 span · PDF**: 1pt 미만 반복 점선으로 그린 경계를 기존 격자 축 안에서 보강한다(내부 병합 span 216→218/235). 페이지 경계에서 잘린 셀의 결합과
  괘선 없는 1×1 글상자는 실물 근거가 부족해 구현하지 않았다.
- **표/그림 캡션 · PPT·PPTX (—)**: PowerPoint 에는 표·그림에 딸린 캡션 요소가 없다. 캡션처럼 보이는 글상자는 일반 텍스트로 나온다.
- **표/그림 캡션 · DOC·DOCX**: Caption 스타일(지역화 이름·내장 스타일 34 포함)이나 SEQ 필드 문단이 최상위 흐름에서 표·그림
  바로 앞/뒤에 있을 때만 결합한다. 셀 안·같은 문단 안·그룹 도형 안 캡션은 일반 문단으로 남고, 숨김 스위치가 있는 SEQ 는
  근거로 쓰지 않는다. DOC 는 아래쪽 캡션 실물 7/7, 위쪽 캡션은 합성 검증이다.

## 서식·스타일·제목

- **스타일 상속 · PPT**: 문서 기본(Environment) → 마스터 수준별 기본 서식 → 특수 텍스트 유형 → 개별 런 순서로 글자 크기·굵게·기울임·밑줄·첨자를 정한다
  (속성별 마스크 비트가 켜진 값만 적용). Microsoft PowerPoint 실측 대조: 공개 PPT 38개 1,537문단에서 크기 99.3%·굵게 99.0%·기울임 99.2%·밑줄·첨자 100%
  (상속 구현 전 크기 73.1%). 확장 서식 마스크는 실물에서 확인한 CF9 pp10ext·SI bidi 길이만 해석한다.

- **스타일 상속 · PPTX**: 슬라이드 → 같은 자리표시자의 레이아웃 → 마스터 → `p:txStyles` → `p:defaultTextStyle` 순서와 각 단계 `a:lstStyle` 의 수준별 값으로
  글자 크기·굵게·기울임·밑줄·위/아래첨자를 정한다. 규칙은 Microsoft PowerPoint 로 직접 측정해 정했다(글상자·일반 도형·날짜·바닥글에는 otherStyle 을 쓰지 않고,
  그림·표·차트 자리표시자는 본문 계열, 레이아웃·마스터 안내 문단의 서식은 상속하지 않는다). PowerPoint 실측 대조: 통제 덱 28/28, 공개 PPTX 30개 143문단에서
  크기 98.6%·굵게 100%·기울임 98.6%·밑줄 100%·첨자 100%. 표 셀·SmartArt·차트·노트 텍스트는 상속 대상에서 뺐고, 밑줄·첨자 상속은 공개 양성 표본이 적다.

- **스타일 상속 · HWP·HWPX (—)**: HWP/HWPX 스타일에는 DOCX `basedOn` 같은 부모 스타일 체인이 없다('다음 스타일' 은 부모가
  아니다). 문단은 확정된 모양 ID 를 직접 참조한다. 스타일 이름·개요 수준은 제목 감지에 반영한다.
- **제목 감지 · HWP·HWPX**: 개요 수준 1~3 만 제목으로 올린다(HWPX 와 같은 상한). 개요 4~6 은 본문으로 둔다(한글 문서는 깊은
  개요를 본문 열거에 자주 쓴다). 표 셀 안에서는 글꼴 크기만으로 제목을 만들지 않는다.

## 수식

- **PPTX**: `a14:m` 으로 감싼 OMML 을 DOCX 와 같은 변환기로 LaTeX 로 바꾼다. 실물은 1식, 구조별 변환은 단위 테스트로 검증했다.
- **DOC·PPT**: 내장 Equation 3.0(MathType MTEF v2/v3/v5) 개체를 LaTeX 로 바꾼다. 공개 실물 변환율 DOC 42/54, PPT 13/18.
  변환하지 못한 식(지원하지 않는 템플릿·행렬 등)은 미리보기 그림으로 남는다.
- **XLS**: 함수 이름·인자 수는 [MS-XLS] 함수 표(Ftab)에서 생성한다. 같은 문서의 XLSX 와 비교한 1,070 수식 중 1,059개(98.97%)가
  공백 정규화 후 일치한다. 메모리 토큰(PtgMemFunc·MemArea·MemErr, 공개 실물 426셀)과 BIFF5 셀 참조·공유식(447셀)은 독립 디코더와 셀 값 재계산으로
  검증했다. 데이터 표(PtgTbl·TABLE, [MS-XLS] 2.4.319 의 fRw·fTbl2 로 방향 결정, 공개 90/91셀 — 손상 레코드 1셀은 캐시)와 DDE 링크(SupBook·ExternName, 공개 1,399셀, 특수 문자 토픽·항목은 작은따옴표)를 수식으로 낸다. BIFF5의 내부 시트 3D 영역은 공개 정의 이름 1건에서 복원했다. 다른 BIFF5 3D 연결 형태·시트 범위·외부 통합문서와 배열은 실물 검증 전이며, 확인되지 않은 형태는 수식 표시를 생략하고 경고를 남긴다. OLE 링크 항목도 미지원이다. MemNoMem·ElfLel 은 합성 검증만 했다. 공개 FORMULA 95,932셀 중 95,922셀을 표시하며, 남은 10셀은 손상 TABLE 1셀, 미지원 Elf 1셀, 출력 격자 상한 8셀이다.
- **PDF (⬜)**: 태그 PDF 의 `Formula` 구조에 MathML·선언된 TeX 가 연결된 별행 수식만 `Equation` 으로 바꾼다(공개 8/8 의미 일치). 문장 속 수식·코드
  안 기호·대체 텍스트만 있는 수식은 글리프로 두고, 태그 없는 PDF 의 수식은 인식하지 않는다. 공개 양성 표본이 적어 ⬜ 로 둔다.

## 날짜·숫자 서식

- **XLS·XLSX**: 두 형식이 같은 서식기(`dochan/spreadsheet_format.py`)로 Excel 셀 서식(날짜·시각·경과 시간·백분율·통화·회계·조건 구역·색/지역 표기·분수·쉼표 배율)을
  표시 문자열로 바꾼다. XLS 는 FORMAT·XF·DATEMODE 와 BIFF5 바이트 서식 문자열을 읽어 같은 서식기에 넘긴다. Excel 이 저장한 표시값 대조: 공개 분수 표
  공백 정규화 후 3,540/3,540셀(고정 분모 2,124/2,124, 가변 분모 1,416/1,416), `TEXT()` 캐시 755/832행(과학 표기 248/248행, 분수 리터럴 190/190행, General·텍스트 구역 34행 추가 일치, 경계 사례 위주 표본이라 전체 비율은 실제보다 낮게 나오는 지표). General·서식 없는 숫자는 15자리 유효숫자로 표시한다. 표시 계약상 소수 자릿수 지수가 -10보다 크고 15보다 작으면 고정 표기, 그 밖에는 지수 표기를 쓴다. 이 대칭 경계 전체가 Excel 화면에서 실측된 것은 아니다. JSON·Markdown의 표시 문자열에는 원래 숫자의 16자리 이상 정밀도와 `1E+20` 같은 원문 표기가 남지 않는다. 문자열·논리값에는 텍스트 구역을 적용하되, 빈 네 번째 구역은 원문을 유지하고 양끝 `_x` 패딩은 생략한다. 연·월·일이 있는 날짜와 시각은 ISO·24시간으로
  정규화한다. 한 자리 숫자 토큰의 부분 날짜(`d`, `m/d`, `m"月"d"日"`, `d "days" h`, `d "days" h:mm`)는 월·일·시 토큰과 리터럴을 표시한다. 두 자리 토큰(`dd`·`mm/dd`)과 연 토큰이 있는 서식, 토큰 렌더러가 그리지 못하는 배치(`d "days" h:mm:ss.000` 등)는 이전처럼 ISO 로 낸다. 1900 날짜 체계의 일련번호 0·60은 일 토큰에서 0·29일로 표시한다. 기존 ISO였던 요일·월 이름 형식은 그대로 둔다. 색만 다른 음수 구역에는 `-` 를 붙인다(Markdown 에 색이 없으므로). 일반 숫자 표시에서는 `?` 자리 공백을 내지 않지만,
  과학 표기와, 색·통화·리터럴이 붙어 자리별로 그리는 분수 서식은 공개 Excel `TEXT()` 저장값과 같이 `?` 자리를 정렬 공백으로 낸다(기본 `# ?/?` 꼴은 생략). README 각주 6 에도 같은 예외를 적었다.
  공개 분수 표에 `[Red]` 접두 또는 빈 문자열 접미를 붙여 토큰 경로로 통과시킨 결과는 두 경우 모두 공백 포함 3,540/3,540셀 일치했다. 기본 `# ?/?`는 Markdown 표시에서 정렬 공백을 생략하지만, 토큰 경로는 공개 Excel 표시와 `TEXT()` 캐시의 정렬 공백을 보존한다. 이 두 출력 정책의 차이는 현재 계약이며, 한 가지로 통일하려면 기존 Markdown 표시와 캐시 정답 중 어느 쪽을 바꿀지 별도 결정이 필요하다.
  분수 서식은 정수부·분자·분모 자리와 그 사이 리터럴을 보존한다. 정수부의 쉼표는 천 단위 구분으로 처리한다(정수부에 소수점이 낀 `0.0 ?/?` 만 기존 표시). `_` 패딩 뒤 가분수는 공개 캐시에서 확인한 조합에만 적용하고, 근거가 없는 정수부 없는 가분수는 기존 대분수 표시를 유지한다. 분수 뒤 `%`는 배율을 적용하지 않은 기존 표시로 둔다. `#/#`·`##/##`의 Excel 표시값도 미검증이다. 자리표시 사이 리터럴은 필수 `0` 정수 자리 사이에서도 보존한다. 분수를 제외한 선택 `#`·`?` 자리와 리터럴 조합은 공개 실물 표본으로 확인되지 않았다.
  그 밖에 지원하지 않는 조합은 README 각주 6 에 적었다.

## 링크·주석·각주

- **하이퍼링크 · PDF (⬜)**: 링크 주석의 위치가 글자 위치와 확실히 맞을 때만 본문 글자에 링크를 건다(공개 비교 가능 링크 678개 중
  599개 연결, 연결한 것은 PDFium 글리프 기준과 599/599 일치). 주석 경계가 글리프 한쪽 끝을 가르면 글리프 중심으로 고르되, 바깥 이웃 글자가
  같은 단어로 이어지면(같은 조각 또는 TJ 분할로 맞닿은 조각, 토큰 안의 `.`·`,` 포함) 보류한다. 같은 URL 의 떨어진 주석은 각각 판정한다.
  연결하지 못한 79개(실제 글자가 그려진 것 40개)도 URL 은 페이지 끝 `<url>` 문단으로 남는다([검증 기록](benchmarks/2026-10-03-pdf-links-real-docs.md)).
- **내부 하이퍼링크 · PDF**: 문서 안 목적지를 확인할 수 있는 링크만 `#page-N` 으로 연결한다(47/47). 다른 PDF 를 가리키는 링크는 풀지 않는다.
- **주석/코멘트 · PDF**: 마크업 주석의 내용과 작성자를 DOCX 와 같은 코멘트 계약으로 낸다(공개 159/159). 하이라이트 등의 대상
  글자 위치가 확실히 맞으면 본문 런 끝에 `[comment N]` 참조를 두고, 아니면 페이지 끝 문단으로 남긴다.
- **각주/미주 · PDF (⬜)**: 각주는 하단 정의·위첨자·구분선이 모두 맞을 때만 복원한다(내부 실물 6/6, 음성 77문서 오탐 0). 위첨자 표지가 숫자와 괄호 두 조각으로
  그려져도 같은 기준선에 맞닿아 있으면 한 표지로 보고, 표지가 붙는 본문은 정의 글자보다 뚜렷이 큰 글자면 된다. 바로 위에 같은 폭의 가로선이 쌓인 표 하단선은
  구분선으로 보지 않는다. 공개 보도자료 HWPX 짝의 각주 8개(3문서) 중 3개를 복원했고 복원한 3개는 렌더와 모두 맞다. 표·그림 글자 때문에 쪽의 최빈 글자 크기가
  본문 크기와 다른 쪽(2문서 5개)은 정의·표지 크기 조건에 걸려 아직 놓친다([검증 기록](benchmarks/2026-10-04-pdf-split-footnote-markers.md)).
  미주는 장별로 번호가 다시 시작하는 구조(목차·장 제목·후속 구역)를 복원한다(공개 1문서 222/222). 공개 양성 표본이 하나뿐이고 내부 미주 양성은 아직 완전 복원하지 못해 ⬜ 로 둔다.
- **내부 하이퍼링크 · PPT**: jump·hyperlink 액션과 표시명만 있는 링크의 슬라이드 대상을 푼다(LibreOffice 실물 2개).

## Legacy Office 세부

- **이미지 참조 · DOC**: BStore(FBSE)·PICF 그림을 복원한다. BLIP 이 없는 빈 그림 정보는 이미지가 아니다. Word 6/95(비복합) 문서는 CHPX→PICF 의 직접 WMF 를 복원한다(공개 실물 1개 바이트 일치, 복합 저장·직접 DIB 는 미지원).
- **이미지 OCR · DOC·PPT·XLS**: OCR 은 Python 3.10 이상과 Tesseract 가 필요하다. 바이트가 같은 그림의 OCR 결과가 OOXML 판과
  같음(PPT 8/8, XLS 16/16)과 DOC 그림의 글자 대조로 검증했다. EMF·WMF 같은 벡터 그림은 OCR 결과가 비어 있다.
- **차트 · DOC (⬜)**: 내장 Excel·MS Graph 차트를 읽는 경로는 PPT 와 같지만, DOC 안에 차트가 든 공개 실물을 찾지 못했다.
- **차트 · HWPX**: XML 캐시 차트의 계열·범주·값을 표로 낸다(막대·꺾은선·원형·도넛·영역·방사형·분리 원형·주식형·표면형은 범주+값, 분산형·거품형은 X+Y).
  공개 차트 HWPX 41개의 차트 82개가 독립 XML 정답과 모두 같다(193계열, 값 1,718칸). 범주 없는 계열은 한컴오피스 화면처럼 같은 그림 영역의 범주를 빌리고,
  범주가 하나도 없으면 1부터 번호를 붙인다. 명시적 제목 34개를 3단계 제목으로 내고, 제목 글자가 없는 단일 계열 차트는 계열 이름을 제목으로 낸다.
  다중 계열 차트에 한컴이 보여 주는 "차트 제목" 은 UI 자리표시자라 내지 않는다. 거품 크기 열(`크기`)과 X 없는 분산형·거품형의 번호 채움은
  공개 표본이 없어 단위 테스트로만 검증했다. 문자열 X 값의 분산형·거품형 계열, 혼합 차트, 다단계 범주는 표를 내지 않는다. 머리글은 한국어
  (`범주`·`X`·`크기`)라 DOCX·PPTX·XLSX 의 긴 표(`Bubble size`)와 다르다([검증 기록](benchmarks/2026-10-03-hwpx-chart-types-real-docs.md)).
- **차트 · HWP**: GSO OLE 컨트롤의 DocInfo 저장소 ID로 `BinData/BINxxxx.OLE`을 찾고, 내장 `OOXMLChartContents`를 HWPX와 같은 파서로 읽는다. 공개 HWP 35문서의 OOXML 차트 38/38개에서 XML 원문의 계열별 범주·값 순서와 차트 종류가 일치했고, 명시적 제목 6/6개도 일치했다. `rhwp-` 접두 짝을 포함한 HWP/HWPX 28/28문서의 차트 표·캡션·제목과 앞뒤 문단 위치가 같다. `Excel.Chart.8`은 기존 내장 Excel 차트 파서로 표를 내며, 공개 5문서 8참조가 독립 BIFF 판독(`python -m scripts.verify_hwp_excel_charts`)의 시트 셀 값과 8/8 일치한다(분산형은 `Series | X | Y` 표를 점 단위로 대조). 차트 계열이 텍스트 열을 가리키면 Excel 차트 캐시는 0 이지만 dochan 은 시트의 문자열을 낸다. OOXML 차트는 계열별 `범주` 표, Excel 차트는 `Category`·`Series` 머리글 표로 형식이 다르다. 구형 한컴 `Contents` 차트는 CFB 루트 CLSID로 확인한 7문서 33참조이며, 한컴 공개 「한글 문서 파일 구조 - 차트」(개정 1.2) 명세가 있으나 아직 구현하지 않았다. 추가 실물 조사에서 `Contents` OLE 33개 모두 `OlePres000`이 없고 지정된 HWPX 짝에도 차트 XML이 없어, 독립 값 검증은 미완료다([조사 기록](benchmarks/2026-10-03-hwp-legacy-chart-real-docs.md)). 공개 차트 문서는 총 46개다. 자세한 집계와 한계는 `docs/benchmarks/2026-10-03-hwp-chart2-fix-real-docs.md`에 기록했다.
- **차트 숫자 표시 (공통)**: XLS의 General 차트 범주·값은 일반 셀과 같은 15자리 표시를 쓴다. 그 밖의 차트 값은 원시 숫자를 그대로 내고, 날짜·시각·경과 시간 서식만 표시 형태로 바꾼다(백분율·통화·자릿수 서식은 적용하지 않는다).
  축 눈금 서식은 데이터 값에 쓰지 않는다. 분산형은 X/Y 축을 구분하고, 막대·분산 혼합 차트는 범주와 숫자 X 를 다른 열로 낸다.
- **차트 · PPT·XLS**: 같은 통합문서를 가리키는 계열은 셀 값으로, 외부 통합문서 계열은 저장된 캐시로 낸다. MS Graph 의 비연속 선택은
  변환하지 않고 미리보기를 유지한다(34개 중 31개 변환, 변환한 것은 31/31 일치).
- **rich text 문자열 · XLS**: 공유 문자열(SST) 서식 런은 실물 731/731, 셀 단위 RSTRING 은 단위 테스트만.
- **읽기 순서 · DOC**: 문서의 논리 순서(CP 순서)를 따른다. 떠 있는 글상자·그림은 앵커 위치에 두고 화면 좌표로 다시 정렬하지 않는다.
- **컨트롤/스마트 태그 텍스트 · DOC**: 양식 필드(체크박스·드롭다운·입력란) 표시값과 스마트 태그 범위 텍스트(실물 184/184)를 보존한다.
- **구조 해석 실패 시**: DOC·PPT 는 구조를 해석할 수 없으면 경고를 남기고 기존 텍스트 경로로 돌아간다. 손상 PPT 는 해석된 구조에서
  빠진 텍스트를 구 경로로 보충한다.

## HWP·HWPX·DOCX 세부

- **변경 추적 · HWP·HWPX (⬜)**: `revision_mode`(preserve·final·original)로 삽입·삭제 텍스트를 투영한다. 개체·서식 변경 이력은
  재현하지 않는다. 한컴오피스 HWP(Mac)는 변경 추적을 만들 수는 없지만 `hh:trackChange` 의 `hide` 를 바꾼 통제 표본으로 최종본·원본·전체 보기를
  보여 주므로 정답 화면으로 쓸 수 있다(2026-10-03). 공개 `hwpxlib-ChangeTrack.hwpx` 와 `korea-mid-30-7_…(축산원).hwpx`(변경 문단 5개)는 세 모드가
  모두 한컴 화면과 같다. 그러나 공개 `admrul-관세조사-운영-훈령.hwpx` 의 문단 단위 삽입·삭제(146), 겹친 변경(127), 표 안 변경(26)은 아직
  투영하지 못해(경고·오류로 보고) ✅ 근거가 부족하다.
- **서식 · HWP·HWPX 취소선·밑줄**: 한컴오피스 화면처럼 3D 계열 취소선 모양과 HWP 밑줄 종류 2 는 서식으로 내지 않는다
  ([검증 기록](benchmarks/2026-10-03-hwp-strike-underline-hancom.md)).
- **컨트롤/스마트 태그 텍스트 · HWP·HWPX**: 단추 캡션, 선택 상자·라디오 상태(`[x]`/`[ ]`), 콤보 상자 표시 글, 입력 상자 글, 누름틀 본문을 낸다.
  한컴오피스 HWP(Mac) 화면을 정답으로 규칙을 정했다: 콤보 상자는 첫 목록 항목의 값을 보이고(선택값·표시 글 무관), 캡션의 `&&` 는 `&`, 단독 `&` 는 숨긴다.
  공개 `form-01`·`form-002` 화면과 통제 표본 7개가 일치하고, 양식 개체가 있는 HWP·HWPX 짝 3개(190개)의 출력이 같다. 빈 입력·콤보 상자의 컨트롤
  이름 자리표시자와 비밀번호 입력 내용은 내지 않는다([검증 기록](benchmarks/2026-10-03-hwp-controls-hancom.md)).
- **읽기 순서 · DOCX**: 글상자·떠 있는 도형·콘텐츠 컨트롤·그룹 도형이 든 공개 문서 466개 중 464개가 원문 순서와 완전 정렬로 일치했고,
  나머지 2개(Strict OOXML)도 직접 대조로 일치했다.
- **Strict OOXML**: ISO/IEC 29500 Strict 네임스페이스를 Transitional 과 같은 내부 표현으로 읽는다(DOCX·PPTX·XLSX).
