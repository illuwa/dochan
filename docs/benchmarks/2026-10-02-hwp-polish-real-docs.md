## 판정의 범위와 원인

누름틀 안내문은 필드 메타데이터이며 문서 본문이 아니다. 안내문과 같은 문자열이 실제 PARA_TEXT 또는 hp:t에 저장되어 있으면 그대로 보존한다. 따라서 단순히 안내문 문자열을 찾아 지우지 않는다. 재감수의 `field-01.hwp` 11회는 서로 다른 Direction 문자열의 합산 출현 횟수다. 원시 본문의 3회까지 지워 0으로 만들면 실제 내용 손실이 된다. 이 작업은 그중 합성 삽입 8개만 제거했다. 합성 삽입이 관찰되던 공개 3파일은 모두 HWPX 짝이 없어, 이 양성 사례의 동일 문서 짝 검증은 여전히 미검증이다.

기존 `test_clickhere_requires_clean_raw_empty_body`의 빈 본문·깨끗한 필드 기대값 `PROMPT` 하나를 빈 문자열로 바꾸고 테스트 이름도 수정했다. 기존 단언은 HWPX가 수행하지 않는 메타데이터 합성을 정답으로 고정하고 있었다. 새 `test_clickhere_only_emits_stored_body_in_both_formats`는 빈 본문, 일반 입력값, 안내문과 같은 실제 입력값을 양 형식으로 비교한다. 그 밖의 기존 단언은 변경하지 않았다.

직접 OUTLINE은 스타일 이름과 기본 문단 개요보다 먼저 적용한다. 유효한 직접 NONE은 스타일 paraPr의 개요 상속을 억제하지만, 기존 스타일 이름 판정과 글꼴 판정은 유지한다. 직접 개요가 지원 제목 범위 1~3 밖이면 스타일 개요로 되돌아가지 않고 기존 20/16/13pt 글꼴 판정을 쓴다. 새 임계값을 도입하지 않았다. HWPX 전체 1,699파일 중 원시 충돌은 3문서·57문단이며, 실제 제목 판정 경로를 거친 것은 22건이다. 57/57건의 실출력을 검증했다고 표현하지 않는다. 스캔 예외 31개는 BadZipFile 25개, KeyError 4개, XMLSyntaxError 1개, ValueError 1개다. 동일명 HWP 짝이 있는 HWPX 604개 중 읽힌 범위에서 직접 개요 4~6이면서 첫 텍스트 런이 13pt 이상인 양성 표본을 찾지 못했다. 깊은 개요의 글꼴 폴백은 단위 테스트만 통과했다.

변경 추적 스캔은 공개 HWP 5,363개의 FileHeader를 모두 확인했다. 변경 추적 비트가 있는 파일은 3개이며 모두 교차 검증에 포함했다. DocInfo 읽기 실패 29개와 보호·배포 문서 28개는 모두 변경 추적 비트가 꺼져 있다. 다만 읽지 못한 메타데이터에만 변경 정보가 있는지는 미검증이다. 읽힌 DocInfo에서 헤더 비트 없이 변경 정보만 있는 추가 파일은 없었다.

대형 문서의 BodyText는 212,001레코드, ViewText는 265,451레코드다. ViewText에는 PARA_LINE_SEG(tag 69)가 53,447개 더 있고, 컨트롤·범위 태그 등 3개가 더 있다. 같은 200,000레코드 상한이라도 ViewText에서 더 적은 본문을 읽게 되는 것이 원인이다. 전체 원시 레코드를 세어 얻은 최대값보다 하나 큰 265,452는 진단 프로브에서만 임시 적용했다. 운영 상한은 변경하지 않았다. 진단 비교의 공통 SHA-256은 `c4e152863b99535f995ba1353386a49b3d1f97b6d18ca84181d57859f53ba15a`이다.

교차 검증의 글자 수는 이미지 연결 전 SectionParser의 plain 출력이다. API의 이미지 연결 후 plain 출력은 대형 표본에서 386,962자이며, 비교용 BodyText 386,964자와 서로 다른 단계의 지표다. Markdown 출력량 513,422자도 별도 지표로 구분했다. 실제 final API는 기존처럼 저장된 BodyText를 재투영 없이 읽는다.

## 공유 파일과 안전 상한

공유 파일은 `dochan/reader.py`만 수정했다. OLE 컨테이너를 소유하는 진입점에서만 다른 스트림을 읽을 수 있으므로 preserve 폴백을 이곳에 추가했다. 대상은 변경 추적 비트가 켜진 비배포 문서의 ViewText이며, 같은 섹션 번호의 BodyText가 존재할 때만 폴백한다. original에는 적용하지 않는다. SectionParser는 폴백 가능한 경우 레코드 상한에서 모델 트리와 표 셀 예산을 소비하기 전에 전용 예외를 낸다. BodyText도 기존 바이트 예산·레코드 상한을 그대로 적용한다. BodyText가 없으면 기존 부분 ViewText와 ERR를 유지한다. BodyText까지 상한에 걸리면 ERR를 숨기지 않는다.

## 회귀 검증과 재실행

새 HWP 테스트는 수정 전 12실패·7통과였고, HWPX 우선순위 테스트는 수정 전 9실패·2통과였다. 수정 후 관련 HWP 테스트 56개와 HWPX 전체 테스트 510개가 통과했다. 최종 전체 테스트는 2,571개 통과, 24개 건너뜀, 14개 예상 실패였으며 새 실패는 없다.
