# XLS 반복 숫자 서식 캐시 — 2026-10-31

## 변경 범위

시작 커밋 `c1a6e0b` 대비, 미통합 커밋 `44d9764`의 XLS 숫자 표시 캐시만 재적용했다.
PDF 변경은 포함하지 않는다. 캐시는 기본 SpreadsheetNumberFormatter에만 적용하고
4,096개 상한을 유지한다. 키에 원시 수치 문자열, 서식, 날짜 체계, 경고 출처를 포함하고,
오류 수집기가 교체되면 비운다. 새 경고가 발생한 계산은 저장하지 않는다.
기존 셀·문자열·레코드 처리 상한과 런타임 의존성은 그대로다.

## 재현 방법

Python 3.9의 `python -m cProfile -o before.prof profile_xls.py`로 공개 XLS 경로를
정렬한 첫 100건을 Dochan으로 읽었다. 입력은 POI, LibreOffice, Tika의 공개 문서만 사용했다.
다른 프로젝트 구현 코드는 읽지 않았다.

독립 기준 소스는 시작 커밋의 `git archive`로 추출했다. 공통 규칙의
`git worktree add --detach`는 Git 메타데이터 쓰기 제한으로 실패하여 사용하지 못했다.

측정은 `scripts.probe_output_speed`의 EXTENSIONS만 `('xls', 'xlsx')`로 제한한
래퍼에서 `collect ROOTS --source SOURCE --workers 1 --output RESULT`를 실행한다.
`measure.py`, `run_measure.sh`, 원시 JSON과 프로파일은 비추적 `.codex-work/`에 보존한다.
전·후·후·전·전·후 순서로 각 3회 실행하며 파싱 시간 합계의 중앙값을 비교한다.
본문은 저장하지 않고 Markdown/JSON/일반 텍스트/오류 목록 SHA-256을 비교한다.
