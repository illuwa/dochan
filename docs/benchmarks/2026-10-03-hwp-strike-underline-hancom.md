# HWP·HWPX 취소선·밑줄 — 한컴오피스 화면 대조 (2026-10-03)

## 요약

공개 한글 문서 상당수가 화면에 없는 취소선·밑줄을 달고 Markdown 으로 나왔다. 원인은 두 가지다.

- **취소선 모양 3D 계열**: HWPX `hh:strikeout shape="3D"`(HWP 글자 모양 비트 26-29 의 값 15)를 취소선으로 읽었다. 한컴오피스는 3D 계열
  (`3D`·`3D_REVERS`·`THICK_3D`·`THICK_3D_REVERS`, HWP 13·14·15) 취소선을 그리지 않는다. 공개 HWPX 중 header.xml 을 읽을 수 있는 1,670개 중 572개 문서가 3D 를 쓴다.
  모든 글자 모양이 3D 인 문서는 기존 휴리스틱이 걸렀지만, 일부 글자 모양만 NONE 인 문서는 본문 전체가 취소선으로 나왔다.
- **HWP 밑줄 종류 2**: 글자 모양 비트 2-3 의 값 2 를 밑줄로 읽었다. 공개 HWP·HWPX 짝 511개에서 값 2 는 HWPX `type="NONE"`(3,483개)과,
  값 1 은 `BOTTOM`(437개)과 대응한다. 한컴 화면에도 밑줄이 없다. 이제 1(아래)·3(위)만 밑줄로 낸다.

Markdown `~~` 쌍 수에는 본문 글자 물결표도 섞인다(`hwp3-sample10` 하나가 양쪽에 각 89쌍). 표 셀은 서식을 꾸미지 않으므로 JSON run 기준이 더 정확하다:
HWP 취소선 run 130,475→133(문서 468→28), HWPX 77,755→192(문서 378→20)(Opus 감수 재측정).
남은 취소선은 실제 취소선이다. `admrul-관세조사-운영-훈령.hwpx` 의 SOLID 취소선 run 은 모두 변경 추적 삭제 구간(`hide="1"`)이라 한컴 최종 화면에는 글자 자체가 없고,
표 안 가격 취소처럼 변경 추적 없는 SOLID·`text-3.hwp` 의 CIRCLE·THICK_SLIM 등이 남는다. 본문 글자는 바뀌지 않고 강조 표기만 바뀐다.

후속(같은 날): 모든 글자 모양에 취소선이 걸리면 지우던 옛 휴리스틱(`_drop_blanket_strikeout`)을 없앴다. 모양 규칙 이후에는 한컴이 실제로 그리는
취소선만 지울 수 있었다. 또 본문이 `~~~`·```` ``` ```` 로 시작하는 줄은 Markdown 코드 펜스를 열지 않게 첫 글자를 이스케이프한다.

`Document.char_shapes` 의 HWP 항목은 원시 비트(`strikeout`·`underline_type`)를 그대로 두고, 화면 표시 여부는 `has_strikeout`·`has_underline` 으로 판단한다.
HWP 모양 13·14 를 THICK_3D·THICK_3D_REVERS 로 보는 대응은 선 종류 표 순서에 기대며 공개 HWP 에 13·14 는 없다.
