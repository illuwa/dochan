R2의 기존 진단은 header 서식, titleMark 경계, 끝 표지 3건, `paraend` 146건, 개체 26건, 문단 서식 참조 22건, 겹침 127건을 7개 항목으로 묶어 보고했다. 끝 표지 세 건은 같은 흐름에서 바로 앞에 닫힌 범위와 Id·TcId·paraend가 같고 사이 표시 슬롯이 0개인 인접 중복으로 확인되었다. 수정 후 세 모드 모두 서식 정보 경고 한 항목과 중복 끝 표지 정보 경고 한 항목이 남았다. `final`과 `original` CLI는 모두 종료 코드 0으로 출력했다. `preserve` 본문은 같지만 진단은 7항목에서 2항목으로 바뀌었다.

## 해석 근거와 한계

KS X 6101:2011 OWPML의 `hh:trackChange`, `hp:insertBegin`/`insertEnd`, `hp:deleteBegin`/`deleteEnd` 및 끝 표지의 `paraend` 요소·속성을 사용했다. 로컬에서 번호가 붙은 KS X 6101 표준 전문을 확보하지 못해 조항 번호와 문단 속성 승계 규칙을 공식 문구로 대조하지 못했다. 구현은 이 작업의 `paraend="1"` 요구와 공개 XML의 실제 배치를 근거로 문단 구분자를 범위에 포함한다. 합쳐진 문단에 앞 문단의 보이는 내용이 남으면 앞 문단의 속성을, 앞 문단 전체가 투영에서 없어지면 뒤 문단의 속성을 남기도록 선택했다. 이 선택은 합성 테스트로 고정했지만 한컴오피스 화면으로 검증하지 못했다.

R2에서 `paraend="1"` 끝 표지 146개는 모두 다음 형제 문단이 있는 문단 안에 있었다. 인접 중복이 아닌 짝 없는 끝 표지는 범위를 지어내지 않고 `ERR:`로 유지한다. 시작과 끝이 서로 다른 문단에 있는 범위도 지원 근거가 없어 `ERR:`로 보존한다. 겹친 범위는 종류별 제외 위치의 합집합으로 처리했고, 표와 그림은 하나의 개체 단위로 처리했다. 서식 참조는 텍스트를 바꾸지 않는 정보 진단으로 모으되, 앞뒤 문단 모양의 개요 수준이 다르면 부분 지원 오류를 남긴다. 서식 자체의 이전·이후 상태는 투영하지 않는다.

## HWP 바이너리 세 문서 조사

`dochan/hwp/revisions.py`는 ViewText의 문단 내부 WCHAR 위치 범위를 사용한다. HWPX의 `paraend` XML 속성과 같은 표지는 이 경로에 없다. 겹침은 여전히 부분 지원 진단이며, 이 작업에서 HWP 바이너리 코드는 고치지 않았다.
