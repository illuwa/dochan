# PDF Encoding CMap 2차 감수 실물 검증

## 판정 방법

ISO 32000-1:2008 9.7.6.2는 코드 공간의 각 바이트를 해당 위치의 하한·상한 바이트와 비교하도록 규정한다. 9.7.6.3은 무효 코드에서 첫 바이트도 맞지 않으면 최단 코드 공간의 길이만큼, 부분적으로 맞으면 가장 길게 일치하는 접두부의 코드 공간 길이만큼 소비하도록 규정한다. 접두부 길이가 같으면 더 짧은 코드 공간을 선택한다. 이 규칙을 GBK2K와 UTF-16 합성 PDF의 실패 테스트로 재현하고 수정했다.

실물 비교는 PDF별 Markdown의 SHA-256, 문자 수, 오류 수만 저장했다. 공개 pdf.js PDF는 부모 `4fd4fc5`와 수정본을 각각 983개 읽었다. 보도자료 PDF는 두 버전을 같은 시점에 병렬로 읽어 각각 396개 결과를 얻었다. 입력 해시의 전후 교집합 395개는 바이트가 같았고, 나머지 1개는 검증 중 코퍼스에서 제거됐다. 내부 PDF는 파일명을 기록하지 않고 80개를 두 버전으로 비교했다. 부모와 수정본의 모든 읽기에서 예외는 없었다.

GBK2K의 `82308130`이 CID 22690인 것과, 분리된 TJ 요소의 무효 UTF-16 서로게이트 뒤 `ABC`가 보존되는 것은 합성 단위·문서 테스트에서 확인했다. 이 두 입력의 독립 실물 표본은 확보하지 못했으므로 해당 사례의 실물 판정은 미검증이다. README의 PDF 텍스트 행은 이 작업 전부터 ✅였고, 이 감수에서 새 칸의 ✅를 제안하지 않는다.
