# XLS BIFF5 3D 수식과 잔여 누락 실물 검증

2026년 10월 3일 공개 XLS 721파일을 조사했다. 읽을 수 있는 667파일의 원시 FORMULA는 95,932셀이다. 기존 프로브는 BIFF5 BOUNDSHEET를 BIFF8 유니코드 레이아웃으로 읽어, 이미 수식이 표시되는 `biff5.xls`의 373셀과 `testEXCEL_5.xls`·`testEXCEL_95.xls`의 74셀을 누락으로 잘못 분류했다. 수정 전 집계의 95,933셀과 현재 95,932셀의 1셀 차이도 잘못 해석한 시트명으로 좌표가 충돌하던 결과다. 수식 뒤 주석을 누락으로 분류한 22셀까지 바로잡으면 실제 미표시 FORMULA는 10셀이다.

BIFF5의 토큰 클래스 비트가 피연산자 레이아웃을 바꾸지 않는 점과 BIFF8의 3D 출력 문법은 [MS-XLS]의 Ptg 계열을 참고했다. BIFF5의 14바이트 한정자와 EXTERNSHEET 레코드 형식은 위 공개 스트림 바이트에서만 확정했다. 한정자 앞 8바이트가 `ff ff`와 0 여섯 개이고 끝 4바이트가 0인 형태만 받아들인다. 다른 형태를 특정 시트로 추측하지 않는다. 이름과 참조 좌표를 시트 명단에 다시 대조하고, 잘린 토큰·없는 인덱스·무작위 손상 토큰 500개는 식을 생략하도록 검사했다. 사용한 구현 코드는 자체 작성했으며 POI·LibreOffice의 구현 파일은 읽지 않았다.

이 BIFF5 문서들에는 공개 코퍼스에서 확인되는 같은 이름의 BIFF8 또는 OOXML 짝이 없었다. 따라서 그 방식의 독립 문자열 대조는 수행하지 못했다.

전수 검증에서 기존 수식 문자열 해시 95,910개는 변경 0, 소실 0이었다. 이는 주석 인식 변경 이전에 추출한 해시로, 최초 프로브에서 복원됐다고 센 95,453개도 포함한다. 주석이 붙은 22개는 출력이 아닌 프로브의 분류만 바뀌었다. 숫자 표시 해시는 POI·LibreOffice 공개 XLS 720파일에서 맞춰진 705,683셀의 변경이 0이었다. 숫자 프로브는 전후 같은 39파일을 읽지 못했으므로 그 파일에 대해 숫자 셀 검증을 주장하지 않는다. Tika의 나머지 공개 XLS 1파일은 보호 문서이며 숫자 프로브에서 셀 0개를 반환했다. 수식 프로브는 공개 XLS 721파일에서 문서 리더 예외 0개, 미표시 FORMULA 10/95,932셀, 미표시 NAME 24/7,968개를 기록했다. NAME 수치에는 3D 이외의 손상·지원하지 않는 이름도 포함한다. 전체 출력 본문은 디스크에 저장하지 않았고 해시와 요약만 `.codex-work/`에 두었다.
