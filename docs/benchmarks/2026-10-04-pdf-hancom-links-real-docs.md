# 한컴 PDF 본문 링크의 배율·경계 수정과 실물 검증

2026년 10월 4일 기준 코드 `9298ad70`에서 수정 전 결과를 재현한 뒤, 합성 테스트를 먼저 실패시키고 배율 허용 오차와 구분자의 얕은 침범을 수정했다. 개발 보도자료 PDF 375개의 해석 가능한 링크 32개 중 글자 위에 놓인 6개는 수정 전 모두 보류됐고, 수정 후 5개가 본문에 연결된다. 나머지 1개는 배율 문제가 아니라 Type3 폰트의 메트릭 신뢰성 문제이므로 계속 보류한다. README는 수정하지 않았으며 하이퍼링크 · PDF 칸의 ⬜ 유지를 제안한다.

## 정답 프로브와 모집단

`scripts/probe_pdf_press_links.py`는 묶음 경로를 인자로 받아 PDF Link 주석마다 원시 Rect, PDFium 글리프의 잉크 상자 중앙점, native 진행 폭으로 다시 계산한 중앙점, 본문 연결 글자, 최종 출력의 링크 글자와 URL 보존, 같은 newsId HWPX의 같은 URL 링크 후보를 JSON으로 기록한다. 독립 중앙점 계산은 제품의 `_contains`, `_on_boundary` 또는 경계 허용 상수를 호출하지 않는다. native 중앙점은 제품과 폰트 해석을 공유하므로 완전히 독립된 정답은 아니며, PDFium과 HWPX 결과를 별도로 남긴다. Rect와 QuadPoints 유무를 함께 기록하므로 QuadPoints가 있는 주석은 Rect 기준 결과라는 점도 구별할 수 있다.

비교 정규화는 NFKC 변환 후 모든 Unicode 공백을 제거하고 문자열 양 끝의 `(`와 `)`만 제거하는 방식이다. 내부 괄호, 대괄호, 점, 슬래시 등 나머지 문자는 보존한다. URL은 정규화하지 않고 정확히 같은 대상만 비교한다. 같은 URL의 서로 다른 HWPX 링크는 문단별 후보로 남기며 합치지 않는다. HWPX가 없거나 같은 URL이 없거나 파서 경고가 있으면 일치로 세지 않고 미검증으로 남긴다.

## 규칙의 수치 근거와 보수성

배율의 `math.isclose` 상대 허용 오차는 `1e-6`에서 `1e-3`으로 바꿨다. 사전 제공된 개발 묶음 실측에서 그리기 1,177,374회 중 배율비 차이가 `1e-3` 이하인 비균등 사례는 448,535회이며, 그보다 크고 `5e-3` 이하인 사례는 8,753회, 더 큰 사례는 442회였다. 이번 작업에서 링크 두 문서의 원시 축으로 재확인한 배율비는 1.000550601이다. 보다 큰 비균등 배율까지 허용하려고 `5e-3`으로 넓히지는 않았다. 내적을 사용하는 기울임 판정과 기존 회전·반사 처리, 폰트 신뢰성 판정은 그대로다. `content.py`의 수정은 `_show`의 배율 판정과 설명 세 줄뿐이다.

진짜 세로 높이를 `H = fs × ys`, 배율비를 `r = xs / ys`라 하면 제품의 높이는 `fs × sqrt(xs × ys)`이고, 글자 중앙 y의 오차는 `Δ / H = |sqrt(r) − 1| / 2`이다. `math.isclose`의 최대 배율 기준을 반영해도 허용 구간에서 `Δ < 0.000251 × H`이다. 가로 진행 폭은 기존처럼 xs로 정확히 계산하므로 가로 중앙에는 이 근사 오차가 추가되지 않는다. 배율 차이가 있는 두 링크의 글리프 46개에서 최대 중앙 오차는 0.001931pt 미만이고, 각 글자 진행 폭 대비 최대 오차는 0.04727%이다. 최소 글자 폭은 3.769317pt였다. 이 오차는 글자 폭에 비해 무시할 수준이다.

경계 예외는 이미 단어 경계로 취급하는 여는·닫는 구분자에만 적용한다. 주석 밖 여는 구분자의 오른쪽 끝, 주석 밖 닫는 구분자의 왼쪽 끝, 주석 안 여는 구분자의 왼쪽 끝, 주석 안 닫는 구분자의 오른쪽 끝에서 침범 또는 절단이 진행 폭의 10% 이내이면 불확실로 세지 않는다. 끝점에서 중앙 쪽으로 전체 폭의 10%를 이동한 점이 중앙과 같은 쪽에 있는지 검사하므로 회전이나 사선 주석에서도 진행 방향의 깊이를 잰다. 문장부호 전체의 허용 오차를 키우지는 않았다.

개발 묶음의 주석 밖 `(` 침범은 0.16816~0.221pt, 해당 폭의 3.484~6.058%였다. pdf.js의 비교 가능 링크에서 괄호·대괄호 등의 경계 절단은 14개였고, 그 중 10개가 폭의 10% 이하였다. 이 10개의 범위는 0.007082~9.440035%이며, 나머지 `bug1997343.pdf`의 대괄호 네 개는 약 35.64~36.00%로 깊어서 계속 보류된다. 허용된 얕은 구분자가 있어도 다른 글자의 단어 절단이나 목적지 충돌이 있으면 해당 주석은 계속 보류한다. pdf.js에서는 새 연결이 위의 `issue17730.pdf` 한 개뿐이었다.

숫자·영문자, 점·슬래시·하이픈 등 단어를 잇는 문자는 원래 경계 판정을 유지한다. 합성 테스트는 5.5e-4 배율 차이, 0.02·0.3pt 앞 괄호 침범, 얕은 닫는 괄호 절단과 인용부호, 깊은 0.6pt 침범, 같은 크기의 문자·슬래시·하이픈 침범, 단어 중간 절단을 검사한다. 주석 참조는 `allow_clipped_edges=False`이므로 구분자 예외를 적용하지 않는다. 기존 테스트의 단언은 변경하지 않았다.

## 전체 출력 해시 비교

## 재현과 남은 검증

다음 명령은 네트워크 없이 읽기 전용 코퍼스로 실행할 수 있다. PDFium과 pdfminer는 기존 로컬 검증 도구이며 런타임 의존성을 추가하지 않았다.

python -m scripts.probe_pdf_link_boundaries corpus/pdfjs-src/test/pdfs --output pdfjs-table-links.json --baseline pdfjs-before-links.json --text-tables
