# PDF Form XObject 본문 글자 실물 검증 (2026-10-03)

이 작업은 ISO 32000-1 §8.10의 Form XObject 호출 순서, 행렬, 자원 상속과 Form의 독립 텍스트 상태를 적용했다. 기존 PDF `텍스트` 칸의 누락을 보완하며 README의 칸 표시는 변경하지 않았다. 공개 pdf.js 코퍼스 983개와 독립 PDFium의 `get_textpage().get_text_range()`를 사용했다. 직접 Form 안에 `BT`와 `Tj` 또는 `TJ`가 있는 39개 문서를 양성 집합으로 삼았고, 나머지 944개도 출력 해시를 비교했다.

공백 제거와 NFKC 정규화 후 2글자 조합의 빈도 다중집합으로 재현율과 정밀도를 계산했다. 조합은 `dochan` 평문 출력과 PDFium 평문 출력에서 만들었다. 신규 문자 정밀도는 변경 후 문자 빈도에서 변경 전 빈도를 뺀 뒤 PDFium 문자 빈도와 대조한 값이다. 이 지표는 좌표와 읽기 순서의 완전 일치를 증명하지 않는다. 각 문서의 전체 출력은 저장하지 않고 SHA-256, 문자 수, 오류 목록, 조합 빈도만 저장했다.

나머지 944개에서는 Markdown 해시 939개, JSON 해시 938개가 동일하다. 차이 6개를 확인했다. `inks.pdf`, `issue15629.pdf`는 중첩 Form 글자가 늘었고, `issue7454.pdf`는 `Tj`/`TJ` 이외의 텍스트 표시 연산을 쓰는 Form 글자가 늘었다. `bug1974436.pdf`, `issue14847.pdf`는 주석 경계 반올림 오차를 바로잡아 링크 표기가 바뀌었다. `bug1721218_reduced.pdf`는 Form 확장 예산 경고 한 줄만 JSON에 추가됐고 본문은 같다. 이 6개를 불명 원인 회귀로 처리하지 않았다.

내부 79쌍은 문서명을 기록하지 않고 문서별 수치를 비교했다. 79/79쌍의 지표가 변경 전과 같으며, 표 수 888개, 잘못된 머리말/꼬리말 0개, 평균 토큰 일치율 0.9754도 같다. 기본·`text_tables` 링크 프로브는 각각 공개 983개를 완료했고 예외·시간초과 0개다. 전체 테스트는 4,407개 통과, 29개 건너뜀, 14개 예상 실패이며 Ruff 검사도 통과했다.

안전 상한은 Form 중첩 16단계, 페이지별 디코드 Form 캐시 16 MiB, 확장 바이트 32 MiB, 확장 연산자 32,768개다. 자기·상호 참조, 1,000단계 체인, 10,000회 반복 호출, 0 행렬·거대 행렬, `/Resources` 누락을 합성 테스트로 확인했다. 디코드된 같은 Form은 페이지에서 재사용한다. Form의 벡터 선은 이번 텍스트 추출 경로에서 표 선으로 합치지 않는다. Form 내부 이미지 XObject와 주석 외관 스트림(`/AP`)은 이번 작업에 포함하지 않았다.
