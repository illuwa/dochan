## 3차 라운드: 캡션 속성, 표 안 각주, 본문 미주 참조

3차에서는 오케스트레이터 리뷰 A~E의 공개 원본 레코드와 HWPX 출력을 다시 대조했다. 칸별 표본, 기대, 실제, 판정은 [3차 실물 검증 기록](2026-10-04-hwp-parity-sweep-fix-real-docs.md)에 적었다. A의 캡션 방향은 `LIST_HEADER` 속성 전체를 방향 코드로 읽은 결함이었다. 하위 2비트로 읽자 공개 표본의 다섯 캡션이 모두 HWPX의 TOP과 일치했다. D의 표 셀 안 각주는 HWP 컨트롤 9개 중 하나가 모델에서 버려져 8개가 되었으므로 셀의 `Footnote`로 보존했다. E의 미주 참조는 HWP `PARA_TEXT`의 제어 코드 17을 본문 런 위치에 복원하고 정의와 번호를 연결했다. 각주 참조만 있는 빈 글자 문단도 보존한다.

B의 고정폭 빈칸은 해당 공개 짝의 HWP 제어 코드 31 열두 개와 HWPX XML의 문자 그대로인 `U+2007` 열두 개가 대응한다. 그러나 코드 31을 일괄 `U+2007`로 바꾼 실험은 이미 자산 경로 제외 일치하던 공개 208쌍을 불일치로 만들었다. 이 변경은 되돌렸고 표본의 차이는 남겼다. C의 제목 밑줄은 HWP 글자 모양 속성 `0x2`에 밑줄 비트가 없고 HWPX의 대응 제목에는 밑줄이 켜져 있어, 두 원본의 저장 서식 차이로 판단했다. HWP에 밑줄을 만들어 넣지 않았다.
