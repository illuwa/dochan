# HWP·HWPX 강조 제목 정밀도 검증

## 판정과 검증 범위

네모 표지의 약한 글꼴 강조 경로에서 진술 줄을 제외했다. 기준은 작업 시작 커밋 `a874d304b6f8509e250d253a8c5745e8b6823731`의 소스다. 1차 372문단과 2차 580문단을 현재 시작점으로 다시 읽었으며, 문단 경로와 라벨 접두어가 모두 일치했다. 라벨 952개 중 제목은 120개이고 건너뛴 행은 0개다. 기존 README의 HWP·HWPX 제목 감지 표시는 변경하지 않았다.

두 라벨 묶음은 이미 공개된 개발 자료다. 아래 수치는 독립 최종 평가 결과가 아니다. `corpus/press-pairs-holdout3`은 열거나 측정하지 않았다. 새 판독 라벨로 한 번 평가하는 일은 오케스트레이터에게 남긴다.

## 채택한 일반 규칙과 교차 확인

`□`와 `■`에서만 다음 조건 중 하나가 있으면 강조 폴백 승격을 하지 않는다. 태그 이름의 어휘는 검사하지 않는다.

1. 맨 앞 괄호 태그가 끝난 뒤 두 어절 이상의 내용이 이어진다.
2. 표지를 뺀 내용이 60자를 넘는다.
3. 내용에 `→`가 있다.
4. 공백 앞 어절이 `하여·하며·하고·하되`로 끝나 다음 구절을 잇는다.

태그만 있는 `□ (지정혜택)`은 이름으로 남긴다. `□ (기관) 본부` 같은 단일 명사 값은 텍스트만으로 절 이름과 확정 구별하지 못하므로 기존 동작을 유지한다. 이는 모든 태그+값을 제외하는 규칙보다 보수적인 선택이다. 기존 제목 테스트의 단언은 하나도 바꾸지 않았다. `□ 은행(첫 5영업일간 온라인 판매 비중 40%, 그 이후는 제한없음)`처럼 이름 뒤 괄호 설명이 오는 제목도 보존한다.

1차 검출 네모 이름은 최대 25자·8어절이고, 2차는 괄호 부연이 붙은 이름까지 최대 38자·9어절이었다. 기존 전체 후보 상한 120자를 절반으로 줄인 60자 후보 하나를 확인했으며, 가장 긴 이름 바로 위로 임계값을 미세 조정하거나 임계값 탐색을 하지 않았다. 1차의 이름을 유지하는 후보를 2차에서 확인하고, 2차 진술 형태에서 제안한 태그·연결 조건을 1차로 역확인했다. 양쪽 자료를 이미 분석한 뒤의 교차 개발 확인이므로 독립 평가라고 부르지 않는다.

개별 제거 수는 중복되어 합산할 수 없다. 1차는 시작점 FP가 0이라 정밀도를 더 높일 여지가 없었다. 두 묶음에서 TP 손실이 없지만 60자보다 긴 실제 네모 이름이나 화살표를 쓴 실제 이름이 새 문서에 없다는 뜻은 아니다. 이러한 재현율 위험은 새 최종 판독에서 확인해야 한다. 괄호 전체 제목과 문답은 긴 이름과 문장형 질문이 실제 제목이므로 이 조건을 적용하지 않는다. 명시된 개요·제목 스타일과 1.1배 이상 큰 글꼴의 기존 경로도 유지한다.

보도자료 91쌍의 공통 최상위 문단 1,962개는 제목 수준과 제목 여부가 전후 모두 1,962개 일치했다. 개발 묶음 1의 30쌍 787문단과 개발 묶음 2의 32쌍 500문단도 전후 모두 일치했다. 세 공개 묶음 합계는 153쌍 3,249문단이다. 내부 76쌍의 공통 9,856문단도 전후 모두 일치했다. 이는 같은 텍스트 문단의 다중집합 비교이며 모든 문단의 위치까지 같다는 주장은 아니다. 짝 수준 일치는 의미상 정답 검증을 대신하지 않는다.

## 테스트와 재현

새 합성 테스트 `tests/test_heading_precision.py`는 실제 HWP 레코드와 HWPX 패키지를 기존 테스트 조립기로 만든다. 네모 진술 12종을 같은 크기 굵기·조금 큰 보통 굵기·조금 큰 굵기의 세 경우로 읽었으며 수정 전 36개 실패, 수정 후 통과했다. 이름 보존·명확한 큰 글꼴 유지·단일 명사 모호점도 검증한다. 연속 공백이 길이 상한을 부풀리는 경우는 추가 실패 테스트를 확인하고 공백 정규화로 고쳤다. 새 테스트 49개를 포함해 제목 관련 테스트 166개와 전체 테스트 5,493개가 통과했다. 36개는 건너뛰고 14개는 기존 예상 실패였다. Ruff 전체 검사와 `git diff --check`도 통과했다.

기준 소스는 작업 시작점에서 `dochan/`만 추출한 사본 하나를 재사용한다. 다음 명령에서 소스와 코퍼스는 호출자가 지정한다.

```bash
/usr/bin/python3 -m scripts.probe_heading_precision corpus/press-pairs-holdout --labels docs/benchmarks/2026-10-04-heading-blind-labels.json --baseline <기준 소스>
/usr/bin/python3 -m scripts.probe_heading_precision corpus/press-pairs-holdout2 --labels docs/benchmarks/2026-10-04-heading-blind-labels-2.json --baseline <기준 소스>
/usr/bin/python3 -m scripts.probe_heading_relative compare corpus/hwp-public --baseline <기준 소스>
/usr/bin/python3 -m scripts.probe_heading_relative compare corpus/press-pairs --baseline <기준 소스> --pairs
/usr/bin/python3 -m scripts.probe_heading_relative compare <내부 짝 경로> --baseline <기준 소스> --pairs --private
/usr/bin/python3 -m pytest tests/ -q -p no:cacheprovider --basetemp=.codex-work/pytest-tmp
```

새 프로브는 형태 특징, 문단 SHA-256, 라벨 점수, 후보별 TP 손실·FP 제거를 JSON으로 출력한다. 조사·서술명사 단서는 이 프로브에만 있고 공통 제목 코드에는 없다. 공유 모델·출력·리더와 `dochan/hwp/section.py`는 변경하지 않았다. PUA 진술 3개, 큰 글꼴 `○` 진술 1개, 기존 FN 39개는 남는다. 새 최종 평가에서 손실을 확인하기 전에는 개발 수치만으로 제목 감지 전반이 완성됐다고 판단하지 않는다.
