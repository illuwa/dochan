# PDF 표 복원 3차: 불가능한 숫자 행 후보의 줄 조립 생략

**판정: 후보 철회.** 출력은 동일했으나 10% 감소 목표와 파일별 회귀 합류 조건을 충족하지 못했다. 런타임 소스는 기준으로 복원했고 이 문서는 실패 실험의 기록이다. 커밋하지 않았다.

## 후보 범위와 근거

기준 커밋은 `3df1bc9fbc98d4437ee08f1b16386f58b40ef922`다. 지정된 변경 전 체크아웃은 수정하지 않았다. PDF 가속 모듈 4개의 SHA-256이 기준과 일치한다.

숫자 행 보강은 두 줄 이상의 숫자 열이 최소 세 개이고 전체 열의 절반 이상이어야 한다. 조각 하나는 최대 한 줄에 속하므로 조각이 두 개 미만인 열은 이 조건을 만족하지 못한다. 또한 모든 조각이 같은 y 기준선에서 왼쪽에서 오른쪽으로 쓰이면 기존 줄 조립은 한 줄만 만든다. 이 두 필요조건으로 가능한 열 수가 부족한 밴드는 정렬과 줄 조립을 생략한다. 경계·허용 오차·예산·출력 규칙은 바꾸지 않았다.

`_fragment_index`는 이미 페이지당 한 번 만들어지고 있었다. 이전 작업의 캐시를 다시 추가하지 않았다. `content.py`, `_show_table.py`, `objects.py`, `structure.py`, C, AES, 공용 모델과 `heading_font`는 수정하지 않았다. 런타임·빌드 의존성도 추가하지 않았다.

## 이미지 의존성 조사

`PDFReader._page_images`는 `extract_image_bytes`가 비어 있지 않은 바이트를 반환해야 Image 요소를 만든다. 디코딩 경고는 문서 진단에 포함되며 PNG 생성 실패도 요소 존재를 바꾼다. 텍스트가 없는 페이지의 OCR 안내와 이미지 추출 불가 경고 역시 이 결과에 따라 달라진다. Markdown은 `image_data` 존재를 확인하고, `Image.has_data`와 OCR은 바이트를 직접 사용한다. 일반 파싱 시점에는 이후 어느 출력/OCR 경로가 사용될지 정해져 있지 않다. 따라서 현재 모델 계약을 유지하며 안전하게 지연할 경로를 확인하지 못했고 이미지 처리는 변경하지 않았다.

## 검증 방법

새 호출 수 회귀 테스트 두 개를 먼저 실행해 기존 코드에서 실패를 확인했다. 각각 조각 한 개 열과 같은 기준선의 다중 조각 열에 대해 기존 결과를 유지하면서 `_cell_lines` 호출이 없어야 함을 검증한다. 기존 숫자 행 실물 형태 테스트와 캐시 호출 수 테스트도 그대로 유지했다.

공개 PDF 목록 2,281개는 기존 검증과 같은 목록이다. 내부 문서는 사용하지 않는다. `scripts.benchmark_pdf_layout`의 `probe_output_speed.measure_file` 경로로 Markdown·JSON·텍스트·진단 SHA-256을 수집하고 `scripts.probe_output_speed compare`로 비교한다. 공용 모델과 제목 글꼴 로직은 변경하지 않아 기타 형식 6,109개 재검사 조건은 해당하지 않는다.

성능은 다른 자체 검증 작업이 종료된 뒤, 각 Python에서 전·후·후·전·전·후의 별도 프로세스로 300개 파싱 시간을 합산한다. 파일별 검사는 각 파일을 두 번 파싱한 최솟값으로 비교한다. 기준 10ms 미만인 1.2배 회귀 후보는 20회 최솟값으로 재검사한다. 프로파일은 일반 시간 측정과 구분한다.

## 해석과 최종 상태

`_cell_lines` 호출 수 감소만으로 이득을 판단할 수 없었다. 기존 숫자 행 검사의 조립 결과는 셀 배정에서 재사용된다. 후보가 검사를 건너뛰면 이 작업 일부가 셀 배정으로 옮겨가며, 새 필요조건 검사 비용도 생긴다. 숫자 행 조기 종료를 개선으로 채택하지 않았다.

최종 런타임 파일은 기준과 동일하게 복원했다. 신규 호출 수 테스트도 최종 구현에서 만족할 수 없는 최적화 요구이므로 `.codex-work/test_pdf_tables_cost.py`로 이동했다. 변경 전 실패 로그, 후보 patch와 전체 후보 소스, 양 모드 출력 해시, 교대/파일별 시간 및 프로파일은 `.codex-work/`에 남겼다. 기존 테스트 단언은 변경하지 않았다. 새 코드나 이미지 지연 최적화를 배포할 근거는 얻지 못했다.

호스트의 다른 프로세스 목록은 샌드박스에서 읽지 못했다. 자체 테스트/병렬 해시 수집과 성능 측정은 겹치지 않았으나 외부 부하가 완전히 없었다고 보장하지 않는다. 특히 파일별 두 번 최솟값은 작은 변동에 민감하다. 이 한계를 회귀를 무시하는 근거로 사용하지 않고 후보를 철회했다.

재현은 `.codex-work/validate.py`, `time_checks.py`, `restore_validate.py`와 원시 로그를 참조한다. 성능은 후보 상태에서 수집한 값이며, 복원된 최종 소스의 개선율로 주장하지 않는다.

## 해석과 최종 상태

`_cell_lines` 호출 수 감소만으로 이득을 판단할 수 없었다. 기존 숫자 행 검사의 조립 결과는 셀 배정에서 재사용된다. 후보가 검사를 건너뛰면 이 작업 일부가 셀 배정으로 옮겨가며, 새 필요조건 검사 비용도 생긴다. 숫자 행 조기 종료를 개선으로 채택하지 않았다.

최종 런타임 파일은 기준과 동일하게 복원했다. 신규 호출 수 테스트도 최종 구현에서 만족할 수 없는 최적화 요구이므로 `.codex-work/test_pdf_tables_cost.py`로 이동했다. 변경 전 실패 로그, 후보 patch와 전체 후보 소스, 양 모드 출력 해시, 교대/파일별 시간 및 프로파일은 `.codex-work/`에 남겼다. 기존 테스트 단언은 변경하지 않았다. 새 코드나 이미지 지연 최적화를 배포할 근거는 얻지 못했다.

호스트의 다른 프로세스 목록은 샌드박스에서 읽지 못했다. 자체 테스트/병렬 해시 수집과 성능 측정은 겹치지 않았으나 외부 부하가 완전히 없었다고 보장하지 않는다. 특히 파일별 두 번 최솟값은 작은 변동에 민감하다. 이 한계를 회귀를 무시하는 근거로 사용하지 않고 후보를 철회했다.

재현은 `.codex-work/validate.py`, `time_checks.py`, `restore_validate.py`와 원시 로그를 참조한다. 성능은 후보 상태에서 수집한 값이며, 복원된 최종 소스의 개선율로 주장하지 않는다.
