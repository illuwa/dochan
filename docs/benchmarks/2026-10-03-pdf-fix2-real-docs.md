# PDF 최종 감수 회귀 수정과 실물 검증

이번 작업은 이미지 해제 예산으로 인한 뒤쪽 본문 손실, Core 14 문자 인코딩 회귀,
CID 공백 폭 오판을 수정하고 주석 표지를 본문 위치에 연결했다. 비교 기준은 `3bcfc21`이며,
작업 시작 버전은 `1d4f0d1`이다. README와 CHANGELOG, 공통 모델·출력 계층 및 의존성은
변경하지 않았다. 외부 코퍼스 원본은 읽기 전용으로 사용했고 복사하지 않았다.

## 이미지 예산 분리

이미지 콜백은 `PDFFile.decode_image_bytes`를 사용한다. 본문 스트림의 200 MiB 누적 예산과
해제 캐시에 이미지를 넣지 않고, TIFF predictor의 문서 단위 연산 예산만 공유한다.
필터의 스트림별 50 MiB 해제 제한과 기존 이미지 픽셀·페이지별 개수 제한은 유지한다.
반복 이미지의 기존 동작을 보존하기 위해 별도 LRU 캐시를 두고 50 MiB·128항목으로 제한했다.
본문 예산이 소진돼도 이미지 콜백은 독립적으로 동작한다.

Pillow를 호출하지 않는 콜백 테스트에서 수정 전 60바이트 이미지가 본문 잔여 8바이트로 잘리고
본문 예산까지 차감되는 실패를 확인했다. 수정 후 이미지 전체가 해제되고 본문 8바이트도 남는다.
packed TIFF 작업 예산 공유, 캐시 용량·개수 제한, 스트림별 해제 제한도 검사했다.
기존 이미지 캐시 관련 테스트의 단언은 바꾸지 않았다.

## 인코딩과 공백의 원인

비기호 TrueType은 ISO 32000-1 §9.6.6.4에 따라 Windows 문자 코드를 사용하며,
Type1의 내장 StandardEncoding과 구분했다. 명시적으로 Symbolic 플래그가 있는 일반 글꼴
별칭에는 이 추론을 적용하지 않는다. `.notdef`와 표에서 찾지 못한 글리프 이름은 코드별 기존
바이트 디코더로 폴백한다. 이 폴백은 기하 연결의 신뢰성을 허가하지 않는다.
MacRomanEncoding에서 명세상 미정의인 코드에 대한 기존 U+FFFD 테스트 계약은 보존했다.
Adobe Glyph List 규칙은 이름 길이 127자와 Unicode scalar 범위를 제한해 직접 구현했다.

`issue6127.pdf`의 마지막 `T` 끝과 다음 `A` 시작의 간격은 2.193075pt다.
다음 CID 글꼴은 코드 32가 아닌 코드 3을 공백으로 매핑하고 명시 폭은 250이다.
코드 32의 폭 570을 쓰면 간격 임계값이 3.70386pt로 커져 공백이 사라졌다.
실제 공백의 폭을 쓰면 임계값은 1.6245pt가 된다. 기존 절반 폭 조건을 바꾸지 않았으며,
Identity-H에서 ToUnicode의 유일한 공백 코드와 명시 폭을 찾을 때만 적용한다.
글리프 advance와 주석/링크 좌표는 바꾸지 않는다.

공개 `Pages-tree-refs.pdf`의 실제 글꼴은 Type1 Courier이며 Encoding이 없다.
코드 39는 StandardEncoding의 `quoteright`이므로 `Testcase: ’Pages loop’`가 명세에 맞다.
ASCII apostrophe가 U+2019로 바뀌는 것은 의도한 변경이다. 오케스트레이터가 CHANGELOG에
기록할 대상이며 이번 작업에서는 CHANGELOG를 수정하지 않았다.

## 주석 앵커의 독립 검증

Highlight·Underline·StrikeOut·Squiggly는 QuadPoints를 사용하고 Text는 Rect를 사용한다.
주석의 넓은 외곽 Rect로 손상되거나 누락된 QuadPoints를 대체하지 않는다. 기존 링크의
명시 폭·해석된 폰트·경계 모호성·검사 횟수 상한을 재사용했다. 서로 다른 주석이 겹쳐
모호한 경우 연결을 보류한다. 마지막으로 선택한 런 끝에 기존 `[comment N]` 표지를 두고
`[^comment-N]` 정의를 보존한다. 표와 미주 변환에서도 참조 유형을 유지하며, 최종 출력에
표지가 남은 경우에만 페이지 끝 독립 문단을 제거한다. 페이지 본문 파싱 실패에도 정의와
독립 표지를 남긴다.

독립 프로브는 dochan의 적중 함수를 정답으로 사용하지 않는다. 원시 사각형을 별도로 읽고
PDFium의 글자 중심을 ray casting으로 판정한다. 공백·호환문자 정규화 후 비교하되 원문도
결과에 남긴다. `issue14046.pdf`의 히브리어는 PDFium의 논리 순서와 원시 그리기 순서가
반대이므로 양쪽 문자와 실제 좌표를 공통 물리 순서로 정렬해 검증했다. 해당 1건의 순서 차이는
기하 경계 오류와 구분했다. 독립 도구는 로컬 검증에서만 사용하며 제품 의존성이 아니다.

연결 정확도는 6/6건(100%)이지만 전체 연결률은 6/159건(3.77%)이고 대상 5종 대비는
6/53건(11.32%)이다. 보류 152건을 성공으로 세지 않았고, 독립 미검증 1건까지 합해
153건의 페이지 끝 표지를 보존했다. 이 수치를 일반 문서 전체의 정확도로 확대하지 않는다.

## 공개 코퍼스 전후 비교

Python 3.9의 별도 프로세스로 문서마다 180초 제한을 두고 측정했다. 기준 스냅샷의
983개 Markdown SHA-256은 기존 최종 감수의 같은 기준 산출물과 전부 일치했다.

| 지표 | 기준 `3bcfc21` | 수정 후 |
| --- | ---: | ---: |
| 완료 문서 | 983 | 983 |
| 프로세스 예외·시간초과 | 0 | 0 |
| Markdown 문자 수 | 2,185,238 | 2,190,148 |
| 평문 문자 수 | 2,092,330 | 2,096,986 |
| U+FFFD 수 | 348 | 348 |
| U+FFFD 포함 문서 | 17 | 17 |
| ERR 수와 포함 문서 | 1 | 13 |
| WARN 수 | 325 | 323 |
| WARN 포함 문서 | 258 | 257 |
| 빈 Markdown 문서 | 295 | 294 |
| 섹션 수 | 1,909 | 1,910 |
| 표 수 | 250 | 250 |

기준 대비 Markdown이 바뀐 문서는 61개다. 길이 증감은 정확도 점수가 아니며 인코딩·공백·
주석 표지 위치 및 기준 이후의 통합 변경을 함께 포함한다. ERR 증가 12개는 암호 누락·불일치·
미지원 암호화 경고의 분류이며, 수정 전 통합 버전의 최종 감수 결과도 같은 13개 오류였다.
문서별 오류와 메시지가 동일하므로 이번 작업에서 새로 발생한 ERR로 세지 않는다.

작업 시작 버전 `1d4f0d1`도 별도 스냅샷으로 983개 전부 다시 실행했다. 이 대조군과 비교하면
U+FFFD는 1,029개에서 348개로 줄었고, ERR 13개·WARN 323개는 그대로다. 이번 작업만으로
Markdown이 바뀐 문서는 33개다. U+FFFD가 줄어든 공개 파일은 `standard_fonts.pdf` 504개,
`poppler-90-0-fuzzed.pdf` 143개, `issue18059.pdf` 26개, `issue4304.pdf` 6개,
`issue11403_reduced.pdf` 2개이며 합계 681개다. 따라서 기준 이후 통합된 암호 오류 분류와
이번 인코딩 회귀 수정을 구분할 수 있다.

## 테스트와 재현

실패를 먼저 확인한 테스트로 이미지 콜백, TrueType 기본 인코딩, 글리프 폴백, CID 공백,
주석 본문 연결 및 주석의 미주 변환 보존을 구현했다. 기존 테스트 단언은 변경하지 않았다.
전체 결과는 **3,136 passed, 24 skipped, 14 xfailed**이며 ruff와 `git diff --check`도 통과했다.
건너뛴 테스트와 예상 실패를 통과 건수에 포함하지 않는다.

다음 명령의 `PDFJS_DIR`와 `PAIRS_DIR`에는 외부 읽기 전용 코퍼스 경로를 전달한다.
주석 프로브는 저장소 밖의 기존 PDFium 검증 환경에서 실행한다. 측정 JSON은 git 제외 경로인
`.codex-work/`에 저장한다.

```sh
/usr/bin/python3 -m pytest tests/ -q -p no:cacheprovider --basetemp=.codex-work/pytest-tmp
ruff check dochan scripts tests
/usr/bin/python3 scripts/compare_pdf_fix2.py .codex-work/baseline PDFJS_DIR .codex-work/pdfjs-baseline.json
```
