`TEXT()` 캐시는 `NumberFormatTests.xlsx`, `DateFormatTests.xlsx`, `ElapsedFormatTests.xlsx`, `FormatChoiceTests.xlsx`, `FormatConditionTests.xlsx`, `GeneralFormatTests.xlsx`, `TextFormatTests.xlsx`, `NumberFormatApproxTests.xlsx`, `DateFormatNumberTests.xlsx`의 832행을 모두 검사했다. 이 중 숫자 입력은 802행이고 비숫자 입력은 30행(불리언 20행·문자열 10행)이다. 비숫자 입력에는 숫자 서식기를 적용하지 않았다. 최종본의 566행은 Excel 캐시와 다르므로 정확 일치로 세지 않았다. 이 중 원시 값 폴백 111행도 정확 일치로 세지 않았다. 날짜·시각 서식으로 분류된 43행 중 27행은 Excel 캐시와 다르고, 이 가운데 19행은 ISO 표기로 정규화된 출력과 Excel 표시가 다른 사례다. 나머지 8행은 원시 값 폴백 등의 미지원 사례이므로 ISO 계약 차이로 세지 않았다.

분수 표의 총 3,540셀은 v1.12.0의 XLSX 서식기로 다시 측정하면 1,350셀, 수정본에서는 3,424셀이 공백 정규화 후 일치했다. v1.12.0 기준은 경로가 둘이다: XLS 셀에 실제로 배포되던 XLS 함수 경로는 30셀, XLSX 서식기 경로는 1,350셀이며 두 경로 모두 잃은 셀은 0이다(4차 감수 재현). 수정한 격리 로더의 실측 개선은 2,074셀이고 기존 일치의 회귀는 0셀이다. 6bbfffd와 430c0c2는 각각 3,424셀로 회귀가 없다. 공백까지 포함한 표시 문자열을 양끝만 자른 정확 일치는 2,112셀이다. 남은 116셀은 모두 가변 분모이다. 고정 분모에는 남은 불일치가 없다.

공개 XLS 720개와 XLSX 352개의 전체 Markdown SHA-256을 v1.12.0과 비교하면 XLS 552개 유지·168개 변경, XLSX 327개 유지·25개 변경이다. 6bbfffd와 비교하면 XLS 705개 유지·15개 변경, XLSX 348개 유지·4개 변경이다. 430c0c2와 비교하면 XLS 717개 유지·3개 변경, XLSX 351개 유지·1개 변경이며 양쪽 파싱 실패는 0건이다. 파일마다 Markdown 전문을 저장하지 않고 SHA-256과 길이·오류 요약만 저장했다.

2차 수정 당시 v1.12.0 대비 XLS 원시 셀 705,679개 중 174,746개 표시 해시가 바뀌었다. 서식별로 통화·회계 81,754, 일반 소수 83,634, 분수 3,512, 백분율 2,424, 시각 1,423, 날짜 1,387, 앞자리 채움 350, General 198, 경과 시각 50, 과학 표기 14셀이다. XLSX 원시 셀 887,477개 중 2,130개 표시 해시가 바뀌었다. 서식별로 일반 소수 1,791, 통화·회계 78, General 261셀이다. 이는 2차 당시의 역사적 집계이며 3차 최종본의 v1.12.0 대비 셀 집계로 사용하지 않는다. 원시 셀 추출기는 XLS 39개와 XLSX 18개의 손상 파일에서 셀 좌표를 얻지 못했으므로 이 파일들은 전체 Markdown 해시에 포함하되 셀 종류별 집계에서는 제외했다. 이 57개 파일의 전체 Markdown 해시는 모두 동일했다. 암호화된 `58616.xlsx`는 복호화한 패키지를 메모리에서만 읽어 셀 해시 분류에 포함했다.

이번 리뷰의 변경 파일에 한정해 원시 숫자 셀을 직전 서식기와 비교하면 XLS는 회계·통화 28,859셀, 일반 소수 1,578셀, General·리터럴 19셀, 날짜 12셀, 시각 12셀이 달라졌다. XLSX는 회계·통화 5셀, 일반 소수 15셀, General·리터럴 5셀이 달라졌다. 이 수치는 변경 파일의 원시 숫자 셀 분류이고 전체 Markdown 변경 셀 수는 아니다. 회계 영 구역은 서식에 따라 `-` 리터럴과 통화 기호·자리 맞춤 공백을 표시한다.

공백이 포함된 조건식, 정수 `0`, 앞자리 채움, 고정 분모, BIFF5 FORMAT, 빈 서식 구역, 회계 음수·영, 통화 기호 위치와 과학 표기 지수 폭은 합성 단위 테스트로 확인했다. 특히 접두사 뒤 앞자리 넘침, 중간 0이 있는 고정 분모, `# 0/8` 폴백은 공개 Excel 저장 표시값이 없어 규칙 추론으로만 확인했다. 남은 가변 분모 116셀과 `TEXT()` 캐시 미일치 566행은 지원 한계다. 가변 분모의 공개 Excel 정답 두 사례는 예상 실패 테스트로 남겼다. 이 한계를 명시하는 조건으로 XLS `날짜/숫자 서식` 칸에 ✅를 제안한다.

## 4차 감수 반영 (2026-10-03)

"색만 다른 음수 구역에만 `-` 를 붙인다" 결정을 휴리스틱 대신 정의대로 구현했다: 대괄호 토큰(색·조건·지역)을 지운 뒤 음수 구역의 리터럴이 모두
양수 구역에도 있고, 음수 구역에 색 표기(조건·지역·경과 시간이 아닌 대괄호, 지역화된 색 이름 포함)가 있을 때만 붙인다. 그래서 `#,##0;[Red]"▲"#,##0`
은 `▲1,235`, `#,##0.00 "USD";[Red]#,##0.00 "USD"` 는 `-1,234.50 USD`, `#,##0;[빨강]#,##0` 은 `-1,235` 다. 음수 구역에만 접미사가 있는 서식
(`#,##0;[Red]#,##0 "€"`)은 작성자의 표기로 보고 부호를 붙이지 않는다. 한 구역 서식의 음수는 리터럴 앞에 부호가 온다(`"Total "General` -5 →
`-Total 5`, NumberFormatTests A22 Excel 저장값 근거). Excel 정답 지표는 그대로다: TEXT() 266/832(잃은 행 0), 분수 3,424/3,540(잃은 셀 0).
