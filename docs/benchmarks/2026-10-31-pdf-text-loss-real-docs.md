기준 커밋 `c1a6e0b`와 이 워크트리 수정본을 비교했다. 커밋·푸시는 하지 않았다. 원본 저장소의 `.git` 쓰기가 제한되어 임시 공유 클론 안에서 동일 시작 커밋의 detached worktree를 생성했다. 코퍼스는 읽기 전용으로 사용했으며 문서를 저장소에 복사하지 않았다.

## 결론

큰 점수 차이의 주원인은 글리프 삭제가 아니라 **공백 누락과 가로 구분선 없는 숫자 표의 열 우선 읽기**였다. 단순 글자 수만으로 품질을 판단하지 않았다. 아래 단계별 글자 수 검사는 비공백 문자 다중집합 검사이며 순서·정확한 위치까지 증명하지는 않는다.

## 구현

- `content.py` / `_clines.c`: 공백 폭이 약 1em인 조각의 반각 공백 임계값에만 0.01em의 좌표 반올림 허용치를 적용한다. 개발 표본의 실제 간격 6.96pt가 기존 임계값 7.02pt보다 작아 단어가 붙던 경우를 복원한다. 좁은 공백 글꼴과 작은 자간은 그대로 유지한다. Python/C 계산 순서는 같다.
- `tables.py`: 위아래 가로선 및 내부 세로선이 있는 영역에서 최소 3개 숫자 열(전체 열의 절반 이상)이 같은 2개 이상 기준선을 공유할 때만 행을 복원한다. 모든 다른 텍스트도 그 기준선에 있어야 한다. 산문, 줄바꿈 라벨, 불일치 기준선, 조밀한 행은 분리하지 않는다. 행 500개, 검사량 및 기존 셀 예산으로 제한한다. 외곽 세로선 생략은 기존 표 복원 정책과 같이 허용한다.
- `reader.py`: Type1/TrueType/MMType1의 유일하고 폭이 명시된 ToUnicode 공백 코드를 사용한다. 누락·중복·잘못된 바이트 길이는 기존값을 유지한다. Type3까지 확장한 개발 파일럿은 평균을 악화시켜 제외했다.
- `probe_output_speed.py`: 동일한 일반 텍스트 생성 결과의 `text_length`를 함께 기록한다. 출력 해시의 계산 대상은 바뀌지 않는다.

## TASK-FIX: C/Python 반각 공백 임계값 동일성

오케스트레이터 재검증에서 가속 모듈이 반각 공백 보정을 반영하지 않아 156784181·156783774의 토큰 점수가 Python 경로보다 낮은 결함이 발견됐다. 이번 후속 작업 시작 시 C 소스에는 보정식이 이미 있었지만, 기존 바이너리에서 새 차등 테스트가 **10 failed, 5 passed**로 재현됐다. 소스만 확인하거나 두 모드 전체 테스트의 통과 건수만 비교하는 것으로 출력 동일성을 입증할 수 없었다. 앞선 단계별 추적 절의 동일성 주장을 정정했다.

`make_plain_line`은 `max(space, prev_space) * 0.5` 계산 직후 `0.45 * size <= threshold <= 0.55 * size`일 때 `0.01 * size`를 빼도록 정렬했다. Python과 곱셈·뺄셈 순서가 같으며 기존 `-ffp-contract=off`를 유지했다. `_Line.__init__`/`_hangul_tracking_gaps`와 C `make_plain_line`/`tracking`에 거울 구현임을 명시하고 동시 수정 및 차등 사례 추가 의무를 적었다.

새 테스트 15개는 float 크기 1.0·10.0·14.04의 전각 공백 폭, 0.49·0.495·0.5배 간격, 임계값 창의 정확한 0.45·0.55 경계와 `nextafter`로 만든 양옆 값을 포함한다. C가 `None`으로 위임하지 않았음을 먼저 확인하고 기존 bit/type-exact 서명 비교를 수행한다. 경계 밖은 공백을 추가하지 않는 기대값도 확인한다. Python 3.9 강제 재빌드 후 전체 차등 테스트 **103 passed**.
