# 들여쓰기 JSON C 가속 검증 (2026-11-02)

기준 v1.18.0 (`9a1b7f1`, base-round4) 대비 `_cjson` 원본 구현. 모델·리더는 수정하지 않았다. 셀·문단·런·출처의 dict를 만들지 않고 캐시된 이름의 `PyObject_GetAttr`로 읽는다. 런타임/빌드 의존성 추가 없음.

통합 재측정(한가한 장비 교대 3회 중앙값)에서도 JSON 단계가 전 그룹 −51~−59%(3.12)였고 독립 감수(최신 Opus)가 차단 결함 0건으로 합류 가능 판정을 했다([통합 재측정](2026-11-02-round4-integration.md)).

## 전수 출력 동일성과 JSON 시간

지정된 8개 공개 코퍼스 루트의 현재 일반 파일 **14,491건**을 기준과 비교했다. Python 3.9.6 가속 켬 최종 3회·끔 1회 모두 Markdown/JSON/텍스트/진단 해시 차이 0, 실패 변화 0, 전체 dict/stdlib 폴백 카운터 0이다. Asset 메타데이터 deepcopy 등 하위 트리 폴백은 이 카운터에 포함되지 않는다.

아래는 기준 수집과 부하가 줄어든 마지막 수집의 JSON 단계 합계다. 시간은 작업자 참고값이며 최종 합류 판정은 공통 규칙에 따라 오케스트레이터가 한가한 장비에서 다시 측정한다.

기준 2회 최솟값과 C 최종 3회 최솟값 비교에서 JSON 단계의 파일별 1.2배 초과는 **0건**이다. 전체 단계 합계는 453건이 의심되어 각각 전·후 20회 교대로 재검사했다. 451건 통과, 1ms 미만 2건은 각 200회 재검사하여 최종 초과 0건(전체 시간 비율 0.973 / 0.947, JSON 단계도 개선)을 확인했다. 같은 소스인 파서를 공유하고 출력기만 교체했으며 네 가지 해시를 매 회 비교했다. 초기 부하가 큰 수집의 JSON 의심 309건은 더 낮은 부하의 전수 재수집에서 모두 사라졌다.

## 동일 모델 교대 측정

각 형식의 고비용 공개 표본 3개씩 총 27개. XLS 표본에 `lo-src/sc/qa/unit/data/xls/opencl/financial/MDuration1.xls` 포함. 기준과 현재의 모델/리더 소스 바이트 동일성을 확인하고, 동일한 파싱 결과와 클래스 정체성을 공유하는 별도 이름 공간에 기준 출력기를 로드했다. 각 파일 전·후·후·전·전·후, 각 측 중앙값을 합산했다. 3.9 문자열 해시는 기준 전수 결과와도 같았다. 모든 런타임에서 표본 파일별 1.2배 초과 0건. 각 런타임의 전·후 해시는 모두 같았다. 3.12/3.13은 선택 의존성 Pillow가 없고 3.9에는 있어, PDF 2개의 파싱 모델 자산 수가 19→12 및 86→80으로 달랐다. 따라서 이 두 PDF의 런타임 간 해시 동일성은 주장하지 않는다. to_dict 단계부터의 차이를 별도 지문으로 확인했으며 출력기 차이가 아니다.

표의 절댓값은 런타임 간 속도 비교에 쓰지 않는다. 동시 작업 부하가 회차마다 달랐다. 파일 경로는 버리는 텍스트 sink로 디스크 I/O를 제외한 직렬화/쓰기 호출 비용을 잰다. 실제 파일은 별도로 켬·끔 UTF-8 surrogatepass 2,109,076바이트를 써서 표준 출력과 바이트 동일성을 확인했다.

## 안전성과 폴백

- 제한 API `0x03090000`, CPython 3.9 헤더 엄격 컴파일, `#` 길이 포맷 없음.
- UTF-8 surrogatepass 버퍼와 원본 이스케이프 루프. 제어 문자/따옴표/역슬래시/한글/비 BMP/단독 서로게이트, int/float/bool/None, tuple, dict 키 순서와 순환 검사를 보존한다.
- 출력 버퍼는 64KiB 단위로 합친다. 문자열 반환은 조각을 모아 한 번 합치고, 파일은 최종 문자열을 만들지 않는다. 최대 단일 문자열/키 크기만큼의 임시 버퍼는 필요할 수 있다.
- 정확한 내장/모델 클래스만 빠른 경로. 미지원 하위 트리는 출력 전에 Python으로 재계산한다. 모델 폴백은 Stream을 유지하는 트리를 C가 다시 순회하여 큰 표 전체의 문자열을 만들지 않는다. 소비한 Stream/이미 쓴 파일을 재실행하지 않는다.
- `JSON_BACKEND`, `DOCHAN_DISABLE_ACCEL=1`, ImportError 폴백. 다른 로더 예외·sink 예외는 전파한다.

## 최종 검증

- 전체 테스트: 가속 켬 **7,368 passed / 39 skipped / 14 xfailed**, 끔 **7,351 passed / 56 skipped / 14 xfailed**.
- 유효 무작위 구조 100,000건 + 오류 포함 무작위 구조 100,000건: 문자열/파일, 예외 종류·메시지 대조.
- 전 형식 실물 문단·런 변형 100,000건: `json.dumps(to_dict(...), ensure_ascii=False, indent=...)`와 문자열/파일 대조.
- 최종 C 소스 ASan/UBSan: 전 형식 실물 표본 + 대형 XLS, 100,000 중첩 구조, 2,000 모델 변형, 추가 실물 모델 변형 100,000건 통과. leak detection은 끈 실행이다. Xcode Python은 macOS sanitizer 로드 정책으로 실행할 수 없어 Homebrew 3.12에서 수행했다.
- 최종 소스를 3.13 헤더로 만든 abi3 모듈을 3.12에서 로드하여 전 형식 표본과 대형 XLS를 문자열/파일 변환, 기준 JSON 해시 일치.
- ruff, release 계약/로컬 경로 금지 검사, 실제 텍스트 파일 출력, 신규 파일을 포함한 공백 검사 통과.

## 재현 명령과 산출물

`PY39`, `PY312`, `PY313`, `PY39_INCLUDE`, `BASE_ROUND4`, `CORPUS_ROOT`는 선택된 로컬 실행 환경을 가리킨다. 코퍼스는 읽기 전용이다.

```bash
DOCHAN_BUILD_ACCEL=1 "$PY39" setup.py build_ext --inplace --force
"$PY39" -m pytest tests/ -q -p no:cacheprovider
DOCHAN_DISABLE_ACCEL=1 "$PY39" -m pytest tests/ -q -p no:cacheprovider
DOCHAN_JSON_FUZZ_CASES=100000 "$PY39" -m pytest tests/test_json_c.py -q -p no:cacheprovider
"$PY39" -m ruff check dochan scripts tests setup.py
clang -std=c99 -Wall -Wextra -Wpedantic -Werror -fsyntax-only -I"$PY39_INCLUDE" dochan/output/_cjson.c
"$PY39" -m scripts.probe_output_speed collect \
  "$CORPUS_ROOT/hwp-public" "$CORPUS_ROOT/poi-src" "$CORPUS_ROOT/lo-src" \
  "$CORPUS_ROOT/press-pairs" "$CORPUS_ROOT/press-pairs-holdout" \
  "$CORPUS_ROOT/press-pairs-holdout2" "$CORPUS_ROOT/press-pairs-holdout3" \
  "$CORPUS_ROOT/pdfjs-src" --workers 6 --output .codex-work/after.json
"$PY39" -m scripts.probe_output_speed compare "$BASE_HASHES" .codex-work/after.json
```

기준 수집은 동일 collect에 `--source "$BASE_ROUND4"`, 비가속 수집은 `DOCHAN_DISABLE_ACCEL=1`을 사용했다. 교대 실행기는 `.codex-work/bench-alternate.py`, sanitizer 실행기는 `check-extension.py`/`sanitize-fuzz.py`/`model-fuzz.py`, 재검사 실행기는 `recheck-total.py`/`recheck-two.py`에 보존했다. 결과 요약은 `validation-summary.json`, 비교 표는 `compare-*-final*.txt` 및 `compare-on-recheck.txt`, 프로파일은 `profile-*-tottime.txt`와 `profile-{39,312,313}-*.txt`다. 큰 전수 원시 JSON은 집계와 SHA-256을 보존한 뒤 삭제한다. build 디렉터리도 정리한다.
