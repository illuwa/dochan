# A01 HWPX 코퍼스 인벤토리

측정일: 2026-09-19. 대상: `corpus/hwp-public/hwpx` 전체, 출처 인덱스:
`corpus/hwp-public/SOURCES.json`. Python 3.9.6, pytest 8.4.2에서 검증했다.
문서 본문 파싱·변환 결과가 아니라 파일 식별 및 컨테이너 메타데이터 조사다.

## 구현 및 실행

구현과 검증 파일은 다음과 같다.

- `scripts/hwpx_inventory.py`: 인벤토리 API와 CLI.
- `tests/test_hwpx_inventory.py`: 합성 입력으로 검증하는 회귀 테스트.
- `docs/benchmarks/hwpx/inventory.md`: 실행 방법, 집계, 한계 및 공개 정책.

저장소 루트에서 실행한다.

```bash
python -m pytest tests/test_hwpx_inventory.py

python scripts/hwpx_inventory.py \
  corpus/hwp-public/hwpx \
  --source-index corpus/hwp-public/SOURCES.json \
  --output hwpx-inventory.local.json
```

`python -m scripts.hwpx_inventory`도 같은 CLI다. `python`은 프로젝트 의존성이
설치된 환경의 인터프리터를 뜻한다. `hwpx-inventory.local.json`은 공개하지 않는
로컬 조사 결과이며 검토 후 삭제한다. `--output` 생략 시 전체 JSON을
stdout으로 출력한다. 지정하면 파일에 전체 JSON, stdout에 집계를 쓴다.
출력 경로는 입력 디렉터리 밖이어야 하며 출처 인덱스를 덮어쓸 수 없다.
종료 코드는 0=파일별 오류 없음, 1=파일별 오류를 JSON에 기록하고 조사 완료,
2=잘못된 입력 디렉터리·출처 인덱스·CLI 옵션 또는 출력 실패다.
확장자 불일치만으로 종료 코드 1을 반환하지는 않는다.

### JSON 계약

- `schema_version: 1`, `files`, `duplicate_groups`, `summary`를 제공한다.
- 재귀적으로 모든 파일을 조사한다. 확장자 필터로 파일을 누락하지 않는다.
  `extension`은 소문자 확장자, `container`는 시작 magic에 따른 `zip`/`ole`/`unknown`이다.
  ZIP 로컬 헤더, 빈 ZIP, 빈 ZIP64, 분할 ZIP 시작 signature를 분류한다.
  분할 볼륨의 재조립은 하지 않으며 자기 압축 해제 실행파일 등 앞에 다른 데이터가
  붙은 파일은 ZIP으로 추정하지 않는다.
- 파일별 상대 경로, 실제 읽은 바이트 수, SHA-256, 확장자 불일치, 출처 라벨,
  오류 코드 및 ZIP 메타데이터를 기록한다. 해시는 1MiB 청크로 계산한다.
  읽을 수 있는 손상 파일도 해시 및 중복 그룹에 포함한다.
- `duplicate_groups`는 같은 SHA-256을 가진 2개 이상 파일의 상대 경로 목록이다.
  `duplicate_files`는 각 그룹에서 대표 1개를 제외한 사본 수다.
- ZIP은 파트명, 중앙 디렉터리 등장 인덱스, 선언된 압축/비압축 크기, 압축 방식,
  압축률, CRC32, 암호화/디렉터리 여부를 기록한다. 동일한 파트명을 삭제하지 않는다.
  중복 파트명과 경로 탈출·절대 경로 형태의 파트명도 별도로 집계한다.
  압축 크기가 0이면 압축률은 `null`이며 Infinity/NaN을 출력하지 않는다.
- 생성기는 정확히 하나 있는 `version.xml`의 `application`, `appVersion` 속성만
  기록한다. 해당 파트/속성이 없으면 `generator: null`이다.
- 선택적 출처 인덱스는 JSON 배열 또는 `fixtures` 배열을 받는다. `path`는 인덱스
  파일의 부모 기준이며 전체 경로로 연결한다. 같은 basename만으로 연결하지 않는다.
  `source`, `license`만 복사하며 URL, 비고, 문서 제목 등 다른 필드는 복사하지 않는다.
  `license`는 수집 인덱스의 분류를 옮긴 값으로, 라이선스 원문 직접 확인이나
  개별 파일의 저작권·재배포 권리 검증을 수행했다는 뜻이 아니다.
- 파일은 상대 POSIX 경로, 중복 그룹은 해시, 그룹 내 경로는 문자열,
  ZIP 파트는 `(name, index)`, 출처 라벨은 정규 JSON 기준으로 정렬한다.
  객체 키도 정렬하고 UTF-8 JSON/들여쓰기 2칸/마지막 개행을 사용한다.
  실행 시각·절대 입력 경로·mtime을 넣지 않아 동일 입력에서 바이트 단위로 재현된다.

### 자원 상한 및 오류 범위

- ZIP 중앙 디렉터리를 할당하기 전에 EOCD/ZIP64 선언을 검사한다.
  중앙 디렉터리 상한은 16MiB, 엔트리 상한은 10,000개다. 실제 읽은 엔트리 수도
  확인한다. 표준 라이브러리의 비공개 `zipfile._EndRecData`를 사용하는 지점은
  이 사전 검사 한 곳이며, Python 변경 시 ZIP/ZIP64 상한 회귀 테스트가 필요하다.
- 문서 본문·이미지·첨부 파일을 압축 해제하거나 추출하지 않는다.
  `version.xml`만 압축 크기와 선언된 비압축 크기 각각 64KiB 이내에서 허용하고,
  실제 읽기도 최대 64KiB+1로 제한한다. 암호화/중복된 생성기 파트는 읽지 않는다.
  XML은 외부 네트워크·DTD 로딩·엔티티 해석을 비활성화하고 DOCTYPE을 거부한다.
- 출처 인덱스 읽기는 16MiB로 제한한다. 심볼릭 링크·FIFO 등 일반 파일이 아닌
  항목은 열지 않고 오류로 기록한다. 디렉터리 열거 실패는 빈 코퍼스로 위장하지 않는다.
- 손상 ZIP/OLE, 빈 파일, 알 수 없는 magic, 파일 읽기 실패, 메타데이터 상한 초과,
  생성기 XML/CRC 오류 등을 고정 오류 코드로 기록한다. 원래 예외 문자열은 넣지 않는다.
- OLE은 FAT/디렉터리 수준의 구조를 확인하며 문서 스트림을 열지 않는다.
  ZIP/OLE signature는 HWPX/HWP 형식 확정이 아니다. ZIP의 다른 파트 CRC,
  로컬 헤더와 중앙 디렉터리의 완전한 일치, 본문 XML, HWPX 규격 적합성,
  의미 구조나 파서 품질은 이 도구의 검증 범위 밖이다.
  `errors: []`는 이 인벤토리 단계에서 오류가 발견되지 않았다는 뜻이다.

## 경로 및 개인정보 공개 정책

전체 JSON은 로컬 조사 자료다. 상대 파일명·ZIP 파트명·출처/생성기 메타데이터에도
개인정보가 포함될 수 있으므로 공개 전 별도 검토가 필요하다. 이 보고서에는
개별 파일명·개별 파일 해시·URL·문서 본문·XML·이미지·예외 원문을 싣지 않는다.
집계 및 전체 결과 재현 확인용 해시만 기록한다. 검증에 사용한 임시 JSON 두 개는
확인 후 삭제했으며 저장소에 원문이나 전체 인벤토리 JSON을 추가하지 않았다.
