# XLS 외부 참조·NameX·사용자 정의 함수·배열 상수 검증

2026년 10월 2일 `illuwa/w-xls-formula` 워크트리에서 검증했다. 리뷰 재검증 후 XLS 수식 칸은 **⬜ 유지**를 제안한다. 최종 근거와 전후 생략률은 [리뷰 수정 검증](2026-10-02-xls-formula-fix-real-docs.md)에 있다. 이번에 배정된 미지원 경로를 구현했고, 합성 테스트와 공개 Office 실물에서 출력 계약을 검증했다. 다만 1,070개 수식의 문자열 일치율은 100%가 아니며, 남은 11개 차이는 아래처럼 구분한다. 오케스트레이터가 증거를 검토할 수 있도록 README는 변경하지 않았다.

## 구현과 출력 계약

SUPBOOK을 내부 여부만 가진 값에서 내부 통합문서·추가 기능·외부 통합문서의 링크 정보로 바꿨다. EXTERNSHEET의 XTI가 지정하는 SUPBOOK과 시트 번호를 사용하고, 외부 문서는 내부·추가 기능·현재 시트·미사용 SUPBOOK을 제외한 외부 링크 등장 순서로 `[1]`, `[2]`를 부여한다. 파일 경로나 네트워크를 열지 않는다. 공백과 작은따옴표가 있는 시트 및 시트 범위는 전체 한정자를 한 번 따옴표로 감싼다.

EXTERNNAME은 바로 앞 SUPBOOK에 소속시키며 NAME의 시트 범위를 보존한다. PtgNameX의 이름 번호는 1부터 시작하고, 내부 링크는 NAME, 외부 및 추가 기능 링크는 해당 EXTERNNAME 목록에서 찾는다. 내부 통합문서 범위 이름은 `[0]!이름`, 내부 시트 범위 이름은 `시트!이름`, 외부 이름은 `[n]!이름` 또는 `[n]시트!이름`으로 낸다. 손상된 NAME도 인덱스 자리는 남겨 뒤의 정상 이름이 당겨지지 않게 한다.

PtgFuncVar의 iftab 255는 첫 번째 인자가 실제로 해석된 Name 또는 NameX일 때만 그 이름으로 호출한다. 첫 인자를 함수명으로 소비하되 나머지 인자와 바깥 피연산자는 보존한다. 숫자·문자열·미해결 이름을 함수명이라고 추정하지 않으며 기존 F255와 WARN 호환 경로를 유지한다. 함수 호출 위치의 `_xlfn.`은 제거하고, 추가 기능을 식별하는 `_xll.`은 보존한다. 일반 이름과 문자열 안의 접두사는 바꾸지 않는다.

PtgArray의 7바이트 예약 영역 뒤에서 RPN을 계속 읽고, 값은 rgce 뒤 RgbExtra의 PtgExtraArray에서 순서대로 읽는다. 열 수와 행 수에는 저장된 값에 각각 1을 더한다. SerNum·SerStr·SerBool·SerErr·SerNil과 여러 배열, 문자열의 유니코드·큰따옴표 이스케이프를 처리한다. FORMULA, ARRAY, SHRFMLA, NAME 경로에서 후속 데이터를 전달한다. ARRAY와 공유 수식의 후속 셀에도 식을 적용한다. 출력은 기존 XLSX와 같은 `캐시 (=식)` 또는 `=식`이며 모델이나 출력 경로는 새로 만들지 않았다.

구현은 [MS-XLS]의 SupBook, ExternName, XTI, Lbl, PtgNameX, PtgFuncVar, PtgArray, PtgExtraArray, SerAr 필드 구조와 공개 표본의 바이트 관찰을 근거로 직접 작성했다. 네트워크는 사용하지 않았고 POI 구현 코드를 읽거나 옮기지 않았다. POI 테스트 소스는 기대값과 표본 설명만 확인했다. 로컬에 전체 명세 원문이 없으므로 이번 검증에서 직접 대조한 원본은 OOXML과 BIFF 바이트이며, 명세 전체를 새로 검수했다고 주장하지 않는다.

## 단위 테스트, 상한과 남은 검증 범위

`tests/test_xls_formula_extended.py`의 최초 28개 중 구현 전에 24개 실패와 4개 기존 통과를 확인했다. 이후 공유 수식 후속 데이터·프로브·상한 회귀를 더했다. 기존 테스트의 단언은 하나도 바꾸지 않았다. 기존 손상 배열 경고의 `token 0x20` 표기도 유지했다.

추가 테스트는 외부 링크 번호에서 내부·추가 기능 제외, 토큰 클래스 세 종류, 외부 시트 범위 따옴표, 내부·외부 이름 범위, UDF 첫 인자와 바깥 피연산자, 접두사, 여러 배열, 유니코드·따옴표·오류·불리언, ARRAY/SHRFMLA 후속 셀, NAME 배열, 손상·잘린 입력과 캐시 보존을 검증한다. 링크 상한에 도달한 후 EXTERNNAME이 이전 SUPBOOK에 붙지 않는 실패 테스트도 먼저 확인하고 수정했다.

새 경로는 추가 데이터 1MiB, 배열 값 65,536개, 렌더링 수식 65,535자, SUPBOOK과 각 EXTERNNAME 목록 65,535개, 경고 목록 1,000개의 상한을 둔다. 이 수치는 의미를 추정하는 조건이 아니라 자원 제한이다. 잘린 자료·잘못된 인덱스·지원하지 않는 DDE/OLE 이름·비정상 배열 값은 WARN으로 낮추고 캐시와 다른 셀을 보존한다. 재귀나 외부 파일 접근은 없다.

`_xll.` 접두사와 혼합 자료형 배열, 다중 외부 통합문서 번호, SHRFMLA/NAME의 배열 후속 데이터는 합성 테스트를 통과했으나 해당 세부 변형의 실물 표본 대조는 미검증이다. CONTINUE에 걸쳐 나뉜 긴 수식/배열/링크 문자열, DDE/OLE 호출, 이번 범위 밖의 전체 Ptg 종류를 모두 지원한다고 주장하지 않는다. 기존 `RepeatingRowsCols.xls`의 이름 수식 PtgMemFunc(0x29)는 남는다. 삭제 참조(0x3C 등)는 후속 리뷰 수정에서 복원했으며 별도 실물 근거는 리뷰 수정 검증 문서에 있다.

공유 모델·출력·라우팅 파일, README·CHANGELOG·AGENTS·패키지 메타데이터는 변경하지 않았다. `xls.py` 변경은 수식 메타데이터 수집과 수식 해석·전달 경로이며 FILEPASS 및 복호화 진입점은 건드리지 않았다. 새 런타임 의존성은 없다.

리뷰 전 전체 테스트는 **2,574 passed, 24 skipped, 14 xfailed**였으며 신규 합성 테스트 33개가 포함된다. 건너뜀과 예상 실패는 통과로 세지 않았다. `git diff --check`도 통과했다.

## 재현과 산출물

저장소 루트에서 다음 명령을 실행한다. 코퍼스는 읽기 전용이며 원본 문서를 저장소에 복사하지 않는다.

```bash
/usr/bin/python3 -m scripts.probe_xls_formula_pairs corpus/poi-src/test-data/spreadsheet --oracle-python corpus/.venv-oracle/bin/python --output .codex-work/formula-final.json
/usr/bin/python3 -m pytest tests/ -q -p no:cacheprovider --basetemp=.codex-work/pytest-tmp
git diff --check
```

`.codex-work/formula-baseline.json`과 `.codex-work/formula-final.json`은 전후 셀별 기대·실제·분류 및 캐시 결과다. 프로브는 미일치 셀의 원시 토큰·배열 후속 데이터·외부 SUPBOOK 바이트도 보존한다. `.codex-work/formula-red.log`, `.codex-work/formula-red2.log`, `.codex-work/formula-full-tests.log`에 실패 확인과 전체 검증 로그가 있다. 이 파일들은 커밋 대상이 아니다.
