# HWP·HWPX 같은 크기 강조 절 제목 재현율 진단

## 판정

본문과 크기가 같거나 1.1배에 못 미치는 절 제목을 승격하는 공통 규칙을 합성 HWP 레코드와 HWPX XML로 먼저 구현하고 검증했다. 보류한 대리 평가 표본에서 기존 오검출 1건이 5건으로 늘어 처음에는 채택하지 않았다. 대리 라벨은 규칙과 같은 단서(굵기·크기·표지)로 만든 것이라, 규칙을 그대로 복원해 규칙을 모르는 판독자가 새 보류 보도자료의 PDF 렌더로 매긴 라벨로 다시 평가했고(아래 "독립 판독 라벨 평가"), 그 결과로 **채택했다**. 평가 라벨을 본 뒤 규칙의 조건·상수는 바꾸지 않았다(이후 코드 감수로 고친 구현 오류 5건은 같은 라벨 점수를 바꾸지 않았다). README의 `제목 감지` 행은 이미 ✅이며 이 작업에서 변경하지 않았다.

이 문서의 “시험 규칙”은 독립 라벨 평가 뒤 채택한 규칙이다. 시험 규칙은 최상위의 120자 이하 한 줄에서 `□`·`■`, 번호, 로마 숫자, 괄호로 감싼 줄, 한컴 PUA 표지를 찾고, 실제 내용 글자가 본문보다 크거나 일부 표지에서 내용 전체가 굵을 때 H3으로 올렸다. `○`·`※`·`*`, 문장형 종결, 콜론이 있는 값 목록, `□ 표 1.` 형식의 표 캡션은 제외했다. 전체 코퍼스 첫 비교에서 번호형 승격이 8,246개로 많아, 평가 라벨을 열기 전에 번호형은 내용 글자가 본문보다 커야 한다고 좁혔다. 아래 모든 시험 규칙 수치는 이 축소본 기준이다. 평가 라벨을 본 뒤에는 상수나 조건을 더 고르지 않았다.

## 보류 평가: 34문서 780문단

평가용 `.codex-work/eval/labels-auto.json`과 교정 파일 `review-overrides-round2.json`은 개발 표본과 규칙을 고정한 뒤 읽었다. 기준 `main`은 `git archive main`으로 만든 한 사본, 작업 시작점은 `git archive HEAD`로 만든 한 사본에서 실행했다. 이 브랜치의 시작 커밋은 현재 `main`보다 616개 파일의 변경을 포함해 앞서 있다. 따라서 `main`과 시험 규칙 사이의 차이를 이번 규칙만의 효과로 해석할 수 없다. 직접적인 효과는 시작점과 비교했다.

| 판정 | 표본 수 | 제목 라벨 | TP | FP | FN | 정밀도 | 재현율 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 라벨 파일에 저장된 `main` 판정 | 780 | 82 | 82 | 524 | 0 | 13.5% | 100.0% |
| 라벨 파일에 저장된 작업 시작점 판정 | 780 | 82 | 21 | 12 | 61 | 63.6% | 25.6% |
| 시험 규칙 | 780 | 82 | 46 | 5 | 36 | 90.2% | 56.1% |

시험 규칙을 나누면 HWPX 589문단에서 TP 39·FP 5·FN 31, HWP 191문단에서 TP 7·FP 0·FN 5다. 저장된 시작점 판정은 HWPX에서 TP 21·FP 12·FN 49, HWP에서 TP 0·FP 0·FN 12다. PDF 크기가 인접 본문보다 1.1배 이상인 제목 15개 중 검출은 저장된 시작점 14개, 현행 시험 규칙 10개다. 나머지 67개에서는 7개에서 36개로 늘었다. 평가 라벨은 PDF 글꼴 크기·굵기·표지와 HWP 굵기를 단서로 생성한 **대리 라벨**이므로, 같은 단서를 쓰는 시험 규칙의 재현율은 낙관적일 수 있다. 별도의 PDF 렌더 독립 감수 전에는 의미상 제목의 진실값으로 단정하지 않는다.

시험 규칙의 오검출 5개는 공개 `156783710.hwpx`의 날짜형 줄 1개, `156783908.hwpx`의 `【…】` 해수욕장 소표제 3개, `156784219.hwpx`의 `<…>` 상황 설명 1개다. 이들은 대리 라벨에서 본문이며, 기존 오검출 1개보다 4개 늘었다. 라벨을 보고 이 5개에 맞춘 예외를 추가하지 않았다.

## 초기 진단에서 누락된 65문단의 원인

앞선 대리 라벨 버전에서 작업 시작점이 누락한 65개 전부에 대해 문단 경로, 첫 런 크기, 문서 본문 추정 크기, 전체 비공백 글자의 굵기 비율, 표지 유형, 스타일 이름, 개요 속성, PDF 글꼴을 `.codex-work/eval-head-diagnosis.json`에 기록했다. 이 진단은 위의 재채점된 780문단 표와 다른 시점의 라벨을 사용했다. 당시 65개 모두 최상위 문단이고 개요 속성은 0이었다. 표지는 번호 24개, 괄호 20개, `□`·`■` 12개, PUA 7개, 그 밖 2개다. 스타일은 `바탕글` 49개가 가장 많았고, 표 셀·머리말·각주·캡션에 들어간 문단은 없었다.

기존 크기 폴백에서 놓친 직접 원인은 첫 크기가 본문 추정 크기 이하인 54개와, 1.071배로서 기존 1.1배 문턱 미만인 11개다. 크기 이하 54개 중 35개는 비공백 글자 전체가 굵고, 5개는 일부가 굵고, 14개는 굵기 비트가 없다. PDF 글꼴은 `H2hdrM` 31개, `Batang` 15개, `HCRBatang-Bold` 7개, `MalgunGothicBold` 4개 등이다. 이는 HWP/HWPX 파서가 굵기를 전혀 못 읽는다는 뜻이 아니다. 글꼴 크기만 사용하는 제목 폴백이 이 정보를 판정하지 않았다는 뜻이다.

HWP 전용 문서의 누락 12개는 괄호형 7개, PUA 3개, 네모 표지 2개다. 이 가운데 7개는 전체 굵기 비트가 기록됐고, PUA 3개는 글머리 런만 보통 굵기여서 전체 비공백 글자 기준 굵기 비율이 약 0.97이었다. 공개 `156783954.hwp`의 `[ 추진 배경]` 문단은 HWP DocInfo 글자 모양 ID 66을 쓴다. 해당 레코드의 오프셋 42 기준 크기는 1400(14pt), 오프셋 46 속성은 `0x2`(진하게 비트 1)다. 공개 `156783859.hwp`의 `【 ➊ 현장대기 프로젝트 신속 가동 】`은 ID 55, 기준 크기 1400, 속성 `0x0`이며 글꼴 ID 5의 이름은 `한컴 윤고딕 230`이다. 한컴 공개 HWP 5 파일 형식의 글자 모양 표 33·35와 이 원시 바이트를 대조했다. 전자는 굵기 정보를 읽고도 제목 판정에 쓰지 않는 경우이고, 후자는 PDF에 시각 강조가 있지만 HWP의 굵기 비트가 없는 경우다. 이름의 `230`을 굵기 등급으로 해석하는 근거는 확보하지 못했다.

PUA 첫 런이 항상 제목보다 작다는 가설은 이 평가 표본에서 확인되지 않았다. 공개 `156784097.hwpx`의 PUA 네 문단은 글머리와 뒤 내용이 모두 15pt이고, 문서 전체 본문 추정치도 15pt였다. 같은 PDF 주변 본문의 대리 라벨 크기는 13pt다. 공개 `156783599.hwp`의 PUA 세 문단도 글머리와 뒤 내용이 15pt이고 문서 본문 추정치가 15pt다. 첫 런을 건너뛰는 것만으로 이 일곱 문단을 복구하지 못한다. 본문 크기를 문서 전체에서 하나로 추정하는 현재 방식과 문서의 지역적 서식 차이가 남는다.

## 전체 공개 문서와 짝 비교

`scripts/probe_heading_relative.py`는 기준 소스를 파이프로 읽으며 문서별 Markdown 전체를 저장하지 않고 SHA-256·문자 수·오류·문단 경로와 제목 수준만 비교했다. 제목 수준을 잠시 0으로 만든 Markdown의 해시로 제목 외 출력 변화를 검사했다. 새 제목 무작위 60개의 공개 파일명과 텍스트 앞 40자는 `.codex-work/promoted-sample.json`에 있다. 첫 시험안은 번호형 8,246개를 승격하여 축소했고, 아래는 축소 후 한 번 더 측정한 값이다.

| 시작점·공개 보도자료 | HWP 111 | 90 | 0 | 0 | 모두 0 |
| 시작점·공개 보도자료 | HWPX 346 | 353 | 0 | 0 | 모두 0 |
| 시작점·내부 짝 | HWP·HWPX 합계 157 | 37 | 0 | 0 | 모두 0 |

공개 전체 7,076개 중 HWPX 28개는 시작점과 현행 규칙 모두 같은 예외로 읽지 못했다. 새 예외는 0개다. 승격 유형은 번호 5,068개, 네모 표지 3,217개, 괄호 970개, PUA 495개다. HWP 제목→본문 2건은 리뷰에서 찾은 판정 오류를 고친 결과이며 제목 외 Markdown 해시·문단 경로·오류 목록은 변하지 않았다. 기존 무작위 60개에는 절 제목으로 읽히는 줄이 많지만 `1) 인건비`, `□ 광주`, `[별지 제4호]`처럼 목록과 제목의 경계가 확정되지 않은 줄도 있다. 목록과 제목의 경계는 아래 독립 판독 라벨에서 확인했다(값 목록 키 3개·꺾쇠 캡션 1개가 오검출).

공개 보도자료 HWP↔HWPX 91쌍의 공통 최상위 문단 1,962개는 시작점과 시험 규칙의 제목 수준·상태가 모두 1,962개 일치했다. 내부 76쌍의 공통 9,856문단도 양쪽 모두 9,856개 일치했다. 내부 문서의 파일명·본문·개별 차이는 기록하지 않았다.

요청된 `main` HEAD 전체 비교도 별도 수행했다. 다만 브랜치 시작점까지 616개 파일의 독립 변경이 있으므로 HWP에서 제목→본문 196,498개, HWPX에서 113,678개, 제목 외 Markdown 변경 문서 각각 1,426개·983개, 새 예외 HWPX 28개 같은 차이는 이번 시험 규칙의 회귀 수치가 아니다. 이번 규칙의 고립된 변화는 위 시작점 비교로 판단했다.

## 독립 판독 라벨 평가 (보류 보도자료 26문서 372문단)

규칙 조정에 한 번도 쓰지 않은 `corpus/press-pairs-holdout`(같은 수집기의 31~45쪽, `press-pairs` 와 newsId 겹침 0)에서 시드 고정 무작위로 HWPX 22문서·HWP 전용 4문서를 골랐다.
표 밖 최상위 문단 중 120자 이하 372개를 텍스트만(제목 수준 없이) 목록으로 만들어, 규칙과 dochan 출력을 보지 않은 판독자(Opus)가 PDF 를 `pdftoppm -r 70` 으로 렌더한 109쪽을 보고
"절·소절의 이름을 붙이고 뒤 내용을 이끄는 줄이면 H, 내용 문장·값 목록·캡션·연락처·주석·붙임 목록 등은 B" 로 매겼다. 위치를 못 찾은 문단은 0개다. 라벨은
`docs/benchmarks/2026-10-04-heading-blind-labels.json`(공공누리 1유형 공개 자료, newsId 와 텍스트 앞 40자)에 있고, 다음 명령으로 다시 잴 수 있다.

    python -m scripts.score_heading_labels corpus/press-pairs-holdout --labels docs/benchmarks/2026-10-04-heading-blind-labels.json --baseline <기준 dochan 소스>

| 기준 | 형식 | 제목 라벨 | 이전(크기 기준만) TP·FP | 채택 규칙 TP·FP·FN | 정밀도 | 재현율 |
|---|---|---:|---:|---:|---:|---:|
| 판독 그대로 | HWPX 310문단 | 43 | 0·0 | 19·4·24 | 82.6% | 44.2% |
| 판독 그대로 | HWP 62문단 | 7 | 0·0 | 2·0·5 | 100% | 28.6% |
| 판독 그대로 | 합계 372문단 | 50 | 0·0 | 21·4·29 | 84.0% | 42.0% |
| 엄격(애매 16개를 B 로) | 합계 372문단 | 34 | 0·0 | 20·5·14 | 80.0% | 58.8% |

이전 리더는 이 문서들의 제목 50개를 하나도 찾지 못했다(같은 크기이거나 1.1배 미만).
오검출 4개는 `<용도별 공시지가 공시>`(표·예시 상자 바로 위 캡션), 한 문서의 `□ (장소) …`·`□ (기관별 서명자)`·`□ (진행 순서)`(일시·장소와 같은 형식의 값 목록 키)다.
놓친 제목은 `▶ 중앙행정기관` 같은 `▶`·`◆`·`>>` 소제목, `Q.1 …` 문답 질문, 굵은 `ㅇ` 항목 이름, `첫째, …한다.` 문장형 머리, `[ … ]` 괄호 소제목 일부, HWP 자동 번호 절 이름이다.
엄격 기준에서 오검출이 하나 늘어난 것은 `□ 지역성장엔진산업 훈련비 우대`(하위 내용 없는 형제 항목)를 본문으로 본 결과다.

## 남은 일

실제 한컴 글꼴 ID와 PDF 글꼴이 같은 줄을 가리키는지 확인하고, 문서 전체와 지역 본문 크기가 다른 표본을 분리해 독립 PDF 감수 표본을 늘려야 한다. 번호·괄호·PUA 줄은 절 제목과 목록·캡션을 구별할 구조 근거가 필요하다. 오검출 두 유형(괄호 키 값 목록, 표 위 꺾쇠 캡션)과 놓친 유형은 다음 새 보류 묶음에서 평가할 후속 과제다.
