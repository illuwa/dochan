# PDF Phase 5 — 남은 과제 해결 방안 (2026-09-07)

1.4.0 이 남긴 PDF 한계 다섯 가지의 해결 방안이다. 각 항목은 실문서 79쌍(동일 문서
HWPX 정답지)에서 먼저 실태를 재고, 그 수치에 맞춰 알고리즘·검증·우선순위를 정했다.
측정은 스크래치 프로브로 했고, 채택 시 `scripts/compare_pdf_pairs.py` 에 지표로 편입한다.

## 실태 측정 요약

| 과제 | 79쌍 실측 | 시사점 |
| --- | --- | --- |
| 한글 줄바꿈 결합 공백 | CJK 결합 7,653건 중 39.3% 는 원문에 공백이 있음. 현재 규칙(항상 무공백) 정확도 0.607 | 가장 많이 발생하고 가장 크게 개선 가능 |
| 중첩 표 | HWPX 중첩 표 66개(13개 문서). PDF 에서 채택된 표 안에 별도 괘선 성분 289개 | 중첩은 실재하며, 안쪽 성분은 필터링이 필요 |
| 페이지 걸침 표 | 본문 하단까지 닿은 표 → 다음 페이지 상단 같은 열 구조: 2쌍(1개 문서). 열 구조가 다른 유사 사례 12건 | 이 코퍼스에선 드물다. 엄격한 조건으로 기본 적용 가능 |
| 세로쓰기 | 회전 텍스트 조각 0개 | 실물 표본이 없다. 스펙 기반 합성 픽스처로 구현·검증 |
| 괘선 없는 표 | 측정 불가(정답지의 '선 없음' 속성을 PDF 에서 식별 못 함) | 텍스트 정렬 기반, 마지막 순위 |

## A. 한글 줄바꿈 결합 공백 — 문자 통계 모델

**문제.** 한글은 글자 단위로 줄이 바뀌므로 줄 끝이 어절 경계인지 어절 안인지 PDF 만으로
알 수 없다. 현재는 CJK 끼리 항상 무공백으로 잇는데, 정답의 39% 는 공백이 있어
`이사회의운영에`, `사항에대하여는` 같은 오류가 남는다.

**근거.** 결합 지점 7,653건에 HWPX 정답을 붙여 규칙 후보를 비교했다(문자 통계는
해당 문서를 뺀 나머지 78개 문서로 학습, leave-one-out).

| 규칙 | 정확도 |
| --- | ---: |
| 현재: 항상 무공백 | 0.607 |
| 앞 글자가 조사(은/는/이/가/을/를/의/에/서/로/와/과/도/만/께)면 공백 | 0.743 |
| 앞 글자 통계 P(공백 \| 앞 글자) 만 사용 | 0.804 |
| 앞·뒤 글자 주변 확률의 나이브 결합 | 0.878 |
| **문자쌍 P(공백 \| 앞 글자, 뒤 글자) + 주변 확률 폴백** | **0.929** |

**방안.**
1. 모델: `(앞 글자, 뒤 글자) → P(공백)` 표와 `앞 글자 → P`, `뒤 글자 → P` 주변 표.
   쌍 표는 관측 5회 이상 항목만 두고, 없으면 주변 확률의 나이브 결합, 그것도 없으면
   사전확률(0.29)을 쓴다. 판정은 `P > 0.5`.
2. 학습 데이터: 저장소 밖 공개 HWP/HWPX 코퍼스 7,188개(`scripts/download_public_hwp_corpus.py`)를
   HWPX/HWP 파서로 읽은 플레인 텍스트. 79쌍만으로도 쌍 항목 9,173개(0.929)이므로
   전체 코퍼스면 표가 수십만 항목으로 커지고 정확도는 더 오른다.
3. 포장: 학습 스크립트 `scripts/build_korean_spacing_model.py` 가 `dochan/pdf/spacing_model.json`
   (또는 확률을 8비트로 양자화한 압축 바이너리, 수백 KB 목표)을 만든다. 패키지 데이터로 포함
   (pyproject `package-data`, `test_release_contracts` 갱신). 런타임 의존성 없음.
4. 적용 지점: `dochan/pdf/layout.py::_joins_without_space` 를 `P(공백)` 판정으로 교체.
   숫자 이어짐(`202`/`3.12.19.`)과 영문은 지금 규칙을 유지한다. 표 셀 안의 결합에도 동일 적용.
5. 검증: `compare_pdf_pairs.py` 에 `join_accuracy` 지표 추가(정답 라벨링 로직은 프로브와
   동일하게 HWPX 텍스트에서 3글자 문맥으로 찾는다). 목표 ≥ 0.93, 토큰 유사도 0.938 → 0.96 대 기대.
   회귀 테스트: 대표 어절 경계 10건 + 어절 내부 10건 픽스처.

**위험.** 모델이 규정·지침 문체에 치우칠 수 있으므로 공개 코퍼스(법령·보도자료·서식)로
학습해 문체 편향을 줄인다. 확률이 0.4~0.6 사이인 애매 구간은 현재 규칙(무공백)을 유지하는
보수 옵션을 둔다.

## B. 중첩 표의 독립 트리 복원

**문제.** 셀 안에 그린 표는 지금 바깥 표의 평면 격자에 흡수되거나(괘선이 닿는 경우)
바깥 셀의 평문으로 남는다(닿지 않는 경우). HWPX 정답에는 중첩 표 66개가 있다.

**방안.** `build_tables` 를 두 단계로 나눈다.
1. 후보 생성: 괘선 연결 성분마다 격자·bbox 만 만들고 텍스트는 아직 배정하지 않는다.
2. 포함 트리: 후보를 면적 내림차순으로 정렬해, 각 후보의 부모 = "그 후보를 완전히 담는
   가장 작은 후보 중, 후보 bbox 가 부모의 **단일 셀** 안에 들어가는 것". 셀 경계를 걸치면
   중첩 표가 아니라 바깥 표의 내부 괘선이므로 지금처럼 평탄화한다.
3. 텍스트 배정은 **안쪽부터**(트리의 잎 → 뿌리). 안쪽 표가 소비한 조각은 부모 배정에서 제외.
4. 부모 셀의 `paragraphs` 에 안쪽 `Table` 을 블록으로 삽입한다. 위치는 셀 안 줄들과 y 로 정렬.
   모델·렌더러는 이미 중첩 블록을 지원한다(`flatten_block_texts`, Markdown 의 중첩 구분자,
   JSON 트리).
5. 안쪽 성분 289개 중 실제 중첩 표는 66개 안팎이다. 나머지는 페이지별로 쪼개진 중첩 표,
   셀 안 괘선(밑줄·구분선)이 우연히 2×2 를 이룬 경우로 보이므로, 안쪽 후보는 "셀 3개 이상"
   또는 "텍스트가 배정된 셀 2개 이상"일 때만 표로 채택한다.

**검증.** HWPX 트리와 PDF 트리의 (깊이, 행, 열) 서명 일치율을 `compare_pdf_pairs.py` 에
추가(`nested_match`). 목표: 중첩 표 66개 중 ≥ 70% 서명 일치. 예산: 중첩 깊이 ≤ 32
(`MAX_FLATTEN_DEPTH` 와 동일), 후보 수 상한은 기존 선 수·셀 수 한도로 충분하다.

## C. 페이지에 걸친 표 병합

**문제.** 한 표가 페이지를 넘기면 PDF 는 페이지마다 닫힌 표를 그린다. 이 코퍼스에서는
2건뿐이지만(신청서·목록형 문서에서는 흔하다), 병합하지 않으면 행 수와 셀 수가 어긋난다.

**방안.** 리더가 페이지 요소를 만든 뒤 후처리로 인접 페이지의 표를 잇는다. 조건을 모두
만족할 때만 병합한다.
1. 앞 페이지의 **마지막 요소**가 표이고, 그 아래에 본문 조각이 없다(꼬리말 영역 60pt 제외).
2. 뒤 페이지의 **첫 요소**가 표이고, 그 위에 본문 조각이 없다(머리말 영역 제외).
3. 열 경계가 같다: 열 수가 같고 각 x 경계의 차이가 허용오차(1.5pt) 이내.
4. 뒤 표의 첫 행 텍스트가 앞 표의 첫 행과 같으면 반복 제목 행으로 보고 버린다
   (한글의 '제목 줄 자동 반복').
5. 병합 결과: 앞 표에 뒤 표의 행을 이어 붙이고, `Table`/`Cell` provenance 에 페이지 범위를
   남긴다(`Provenance.page` 는 시작 페이지, 새 필드 `page_end`).
6. 셀 하나가 페이지 경계에서 잘린 경우(앞 표 마지막 행과 뒤 표 첫 행이 같은 셀의 앞·뒤)는
   PDF 만으로 구분할 수 없다. 앞 행 셀 텍스트가 문장 부호 없이 끝나고 뒤 행 같은 열이
   소문자/조사로 시작하면 이어 붙이는 휴리스틱을 **옵션**으로 두되 기본은 두 행 유지.

**검증.** 79쌍에서 2건 모두 병합돼 HWPX 행 수와 일치해야 하고, 열 구조가 다른 12건은
병합되지 않아야 한다. `compare_pdf_pairs.py` 의 `signature_match` 가 지표다. 페이지에
걸친 표가 많은 문서(서식·명부)를 확보하면 별도 픽스처로 추가한다.

## D. 세로쓰기 읽기 순서

**문제.** 세로쓰기와 회전된 표 머리글은 텍스트 x축이 장치 y축으로 간다. 지금은
`dir_x≈0` 이면 그리기 순서를 유지할 뿐, 줄 조립이 y 기준이라 글자마다 줄이 갈린다.
실물 표본이 코퍼스에 없어(회전 조각 0개) 스펙(PDF 32000 §9.4.4 텍스트 행렬)으로 설계한다.

**방안.**
1. `Fragment` 에 `dir_y` 를 추가해 진행 방향 벡터 `(dir_x, dir_y)` 를 완성한다
   (`_show` 의 `start_tm` 첫 행). 방향은 네 가지로 분류: 가로(→), 가로 반전(←),
   세로 하향(↓, `dir_y<0`), 세로 상향(↑).
2. 줄 조립을 방향별로 한다. 세로 조각은 **x 로 묶고**(같은 열) y 내림차순으로 잇는다.
   조각 간격→공백 판정은 진행축 좌표로 계산한다(현재 `_Line` 의 `x/width` 를 `pos/advance` 로 일반화).
3. 세로 열의 순서: 전통 세로쓰기는 오른쪽 열이 먼저다. 열 순서 = x 내림차순. 단, 표 셀 안의
   회전 머리글(한 열짜리)은 순서 문제가 없다.
4. 본문 흐름에 섞이는 위치는 그리기 순서(`order`)를 그대로 쓴다. 표 셀 배정은 조각의
   기준점(현재 `x + width/2, y + 0.35·size`)을 방향에 맞게 회전한 점으로 계산한다.
5. 픽스처: `q 0 1 -1 0 300 100 cm BT … ET Q` 로 세로 하향 텍스트 두 열, 표 셀 안 90° 회전
   머리글 한 개를 합성해 회귀 테스트로 둔다. README 체크(⬜→✅)는 실물 세로쓰기 문서
   (한글 `쪽 설정 → 세로쓰기` 로 저장한 PDF)를 `test_pairs/` 에 추가해 검증한 뒤에만 올린다.

## E. 괘선 없는 표 (선 없음 표)

괘선이 전혀 없으면 격자 근거가 없으므로 텍스트 정렬로만 추정해야 한다. 같은 y 밴드에서
2개 이상의 줄이 같은 x 시작 위치 집합(허용오차 2pt)을 3행 이상 반복하면 열로 본다.
오탐 비용이 커서(본문 목록이 표로 둔갑) 기본은 꺼 두고 `Dochan(..., pdf_text_tables=True)`
옵션으로 제공하며, 정답지에 '선 없음' 표가 확인된 문서가 모이기 전에는 README 체크를
올리지 않는다. 우선순위는 마지막이다.

## 우선순위와 일정

| 순위 | 과제 | 기대 효과 | 규모 |
| --- | --- | --- | --- |
| 1 | A. 줄바꿈 공백 통계 모델 | 결합 정확도 0.61 → 0.93, 전 문서 본문 품질 | 학습 스크립트 + 모델 파일 + layout 교체, 1~2일 |

| 4 | D. 세로쓰기 | 회전 머리글·세로쓰기 문서 | content/layout 일반화 + 픽스처, 1일 + 실물 확보 |

목록에서 해당 항목을 지우는 것은 실물 검증 뒤에만 한다.
