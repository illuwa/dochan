# PDF 남은 기능 실물 검증 (2026-10-02)

## 검증 원칙과 실행 환경

Python 3.9의 네이티브 PDF 리더로 공개 pdf.js PDF 983개를 조사했다. 원격 `.link` 표본은 포함하지
않았다. 내부 HWPX/PDF 문서는 저장소에 복사하지 않으며 파일명과 내용을 기록하지 않는다. README는
수정하지 않고, 단위 테스트와 실물 정답 비교가 모두 있는 범위에 대해서만 체크를 제안한다.

## 1. LZWDecode와 TIFF Predictor 2

ISO 32000-1의 7.4.4와 7.4.4.4에 따라 LZW의 9~12비트 코드, Clear, EOD, EarlyChange 0/1과
TIFF의 같은 색 이전 픽셀에 대한 샘플 단위 덧셈을 구현했다. 1/2/4비트는 바이트 패딩을 샘플로
취급하지 않으며, 16비트는 big-endian 샘플로 처리한다. 필터 배열의 DecodeParms는 같은 인덱스의
필터에 적용한다. DecodeParms가 배열이 아닌 사전이면 첫 필터에만 적용한다. 해제 크기 50 MiB, 사전 4,096항목, predictor 행 크기 한도를 적용한다.

리뷰 후 잘못된 LZW 코드도 유효한 Clear 이후의 정상 접두 출력은 보존한다. 시작 Clear가 없는
임의 바이트는 거부하므로 기존 HEAD의 손상 입력 단언도 유지한다. packed TIFF에는 별도
1,048,576 샘플 연산 예산을 적용하며 초과 시 완성한 행까지만 반환하고 경고한다.

새 합성 테스트는 구현 전에 9개가 실패했고 구현 후 기존 필터 테스트를 포함해 22개가 통과했다.
EarlyChange 0/1의 모든 비트 폭 전이와 사전 초기화, KwKwK, 필터 체인, TIFF 1/2/4/8/16비트,
다중 색과 다중 행, 손상 입력과 크기 한도를 검사했다. 실물에서 EarlyChange 0과 TIFF 1/2/4/16비트
표본은 발견하지 못했으므로 해당 조합의 실물 검증은 미검증이다.

공개 983개 중 LZW를 쓰는 파일은 3개이고 해당 스트림은 5개다. Predictor 2는 1개 파일의 1개
이미지 스트림에서 발견했다. 검증 스크립트는 `scripts/probe_pdf_features.py`이며 코퍼스 경로를
인자로 받는다. 이미지 검증은 압축 원시 바이트를 TIFF 컨테이너로 감싸 기존 Pillow의 libtiff
해제 결과와 비교했다. libtiff는 검증에만 사용하며 PDF 런타임 경로에 추가하지 않았다.

## 2. 주석과 코멘트

기존 DOCX의 `Comment(Footnote)`와 작성자 필드, 문단과 `TextRun`의 의미 필드를 재사용한다.
Markdown도 기존 출력 경로의 `[comment N]` 본문 표지와 `[^comment-N]: ...` 정의를 사용한다.
공유 Markdown 렌더러는 현재 DOCX의 코멘트 표지를 자동으로 Markdown 참조로 바꾸지 않으므로,
PDF에서만 별도 표기를 만들지 않았다. 팝업은 부모의 표시창으로 보고 별도 댓글을 만들지 않는다.
Contents를 우선하고 없으면 RC XML의 텍스트를 추출한다. UTF-16BE와 UTF-8 BOM 및 PDFDocEncoding을
지원하며, RC의 DTD·외부 엔티티는 XML 인코딩과 관계없이 차단한다.

리뷰 후 최종 구조 조사는 983개 중 954개를 완료했고, 해석 불가 19개와 문서당 5초 시간초과
10개를 별도로 제외했다. 59문서의 코멘트 158건은 FileAttachment를 포함하며, 독립 문자열
디코더와 DOM의 내용·작성자가 158/158건 일치했다. Popup 127개를 별도 코멘트로 만들지 않았다.
RC 70개 중 fallback 18건이 일치했다. RC 스트림 지원은 합성 검증을 통과했으나 해당 실물은
0개다. Sound 내용과 Redact도 실물 미검증이다. xref 스트림 캐시의 객체 ID 재사용 오류를
고친 뒤 같은 프로브를 두 번 실행하여 JSON 전체의 동일성을 확인했다. 이전 126건 집계는
이 최종 수치로 대체하며, 추가 FileAttachment를 중복 가산하지 않는다.

페이지 주석 256개, 개별 텍스트 64 KiB, RC 노드 4,096개·깊이 32, 문서 코멘트 4,096개와
내용·작성자 합계 8 MiB 상한을 적용한다. 사전 공유 참조로 발생하는 출력 증폭도 누적 예산으로
막는다. 상세 프로브는 `scripts/probe_pdf_annotations.py`다.

## 3. 내부 하이퍼링크

Link의 Dest와 GoTo를 실제 페이지로 풀고 기존 내부 링크 계약인 `TextRun.link='#...'`를 사용한다.
대상 페이지에는 DOCX/HWPX와 같은 `[bookmark: NAME]` 마커를 넣으며 이름은 `page-N`이다.
카탈로그 Dests 사전과 Names/Dests 트리의 자식 노드, D 배열 래퍼를 처리한다. 별칭 순환, 트리 깊이
32와 이름·노드 4,096개 한도를 둔다. GoToR 같은 외부 파일 목적지는 로컬 페이지로 추측하지 않는다.

원시 내부 링크 144개 중 실제 페이지 참조를 확인할 수 있는 47개가 독립 목적지 해석과 모두
일치했다. 나머지 97개는 이름이나 페이지 참조를 확인하지 못했으므로 성공 분모에서 제외했다.
페이지 끝 Page N 링크는 최종 최상위 문단의 일반 링크 런이 세 출력에 남는 경우에만 생략한다.
표·각주·반복 머리글에만 붙은 링크는 fallback을 유지한다. 페이지 첫 요소가 문단이면
북마크 마커도 그 문단의 첫 런에 넣으며, 문단이 없는 페이지에만 독립 문단을 만든다. 합성 테스트는 자식 이름 트리와 순환·원격 목적지도 검사했다.

## 4. 본문 하이퍼링크

리뷰에서 재현한 글자 경계 오류와 URL 소실 때문에 초기의 양성 3/3 및 ✅ 제안을 철회한다.
링크가 없는 문서의 오연결 0건은 본문 연결의 정밀도 근거가 아니다. 최종 검증은
`scripts/probe_pdf_link_boundaries.py`로 수행하며 자세한 문서별 집계는
`2026-10-02-pdf-fix-real-docs.md`에 있다.

코드별 폭이 문서에 명시되어 있고 폰트 인코딩과 좌표를 해석한 조각만 연결한다. 기본 폭,
미해석 폰트, 비균등 변환, 겹치는 서로 다른 목적지, 글리프 전진 영역을 가르는 경계는 보류한다.
확신할 수 없는 조각이 있는 줄의 같은 링크도 부분 연결하지 않는다. 기하 검사 200만회 한도는
불확실성 검사와 양 끝점 검사까지 포함하며, 초과하면 부분 연결을 남기지 않는다.

공개 983개를 다시 조사했다. 대상이 해석된 링크 문서 49개, Link가 없는 898개, 목적지만
미해결인 9개, 해석 불가 26개와 15초 시간초과 1개를 구분했다. 수정 전 본문 연결 양성으로
관찰한 41문서(외부 목적지 양성 32문서)를 모두 재검사했다. 이는 감수자의 31문서보다 넓은
모집단이다. 현재 본문 연결은 18문서의 주석 87건에서 독립 정답과 87/87건 일치했고 경계 오류는
0건이었다. 총 678개 주석 중 591건은 연결하지 않았다. 그중 552건에는 독립 기준의 글자가 있고
39건에는 없었다. 보류를 성공이나 재현율에 포함하지 않는다.

독립 정답은 PDFium이 추출한 실제 글리프 상자의 중심이 Rect 또는 QuadPoints 안에 있는 글자다.
PDFium이 비유니코드 표지를 내는 2건은 독립 pdfminer 글리프로 교차 검사했다. 공백과 NFKC
정규화(예: 합자)를 적용하되 문자 순서와 내용은 비교한다. 제품의 advance 중앙 판정은 정답에
재사용하지 않는다. 런이 최종 모델에 남는지도 따로 확인한다. PDFium과 pdfminer는 이미 설치된
검증 도구로만 사용하며 런타임 의존성을 추가하지 않았다.

49개 문서를 기본 모드와 text_tables 모드에서 모두 검사했다. Markdown·plain text·JSON의 URL
소실과 최종 연결 런 불일치는 두 모드 모두 0건이다. 표·각주·반복 머리글에만 있는 링크의
fallback은 유지한다. 본문 연결은 보수적인 부분 지원으로 보고하고 ⬜ 유지를 제안한다.

## 5. 사용자 암호

PDF 쪽 API는 `PDFReader(text_tables=False, password="")`이며 `read(path)`로 문서를 읽는다.
문자열 또는 이미 인코딩한 바이트를 받을 수 있다. 공용 Dochan API와 CLI에는 암호 인자를
연결하지 않았다. R2~R4는 PDFDocEncoding을 사용하고 R5는 UTF-8, R6는 표준 라이브러리의
Unicode 3.2 SASLprep 후 UTF-8을 사용한다. RC4, AES-128과 AES-256 및 문자열 Identity 필터를
구분한다. EncryptMetadata false인 Metadata 스트림도 암호화하지 않은 바이트를 보존한다.

매니페스트가 암호를 지정한 7개는 모두 인증과 페이지 개방에 성공했고, 틀린 암호 7개는 경고와
빈 결과로 중단했다. 매니페스트 MD5도 모두 일치했다. 사용자 인증과 소유자 복원 인증은 최대
각 1회이며 잘못된 암호의 무한 재귀를 제거했다. R2의 비어 있지 않은 암호와 확장 PDFDocEncoding
암호는 실물 미검증이다. 암호화하지 않은 Metadata의 별도 실물 바이트 검증도 남아 있다.
프로브는 `scripts/probe_pdf_passwords.py`다.

## 6. 각주와 미주

숫자-닫는괄호 하단 정의, 같은 번호의 유일한 본문 위첨자와 독립된 구분선이 함께 있는 경우만
기존 Footnote와 TextRun.note_ref로 변환한다. 페이지별 인쇄 번호와 별개로 문서 전역 번호를
부여하며 정의 조각만 본문에서 소비한다. 구분선이 표의 세로 테두리에 닿으면 거부한다.
본문 대비 표지 크기 0.75, 상승 0.207~0.217 및 정의 위 15pt 구분선이라는 실제 관찰에서
크기·거리 조건을 정했다. 하단 25%, 표지 크기 80% 이하, 상승 15~30%, 기존 괘선 허용 오차
1.5pt를 사용한다. 조각 5만개, 표지 1천개, 각주 100개와 기하 검사 20만회 상한을 적용하고
초과하면 본문을 유지한다. 구분선·참조·소비 조각 검사 모두 같은 예산으로 계산한다.

이전 각주 음성 78개에는 미주 1개가 포함돼 있었다. 원시 HWPX의 footNote/endNote와 모델을
함께 확인한 올바른 양성은 2문서 7건, 음성은 77문서다. 실제 PDFReader에서도 각주 6건의 정의가
모두 일치했다. 정의 비교는 NFC 정규화 후 공백을 제거한 글자열 기준이며 각주 총 261/261자다.
리뷰 후 혼합 크기 정의는 원래 조각 ID로 소비하고, 연속 줄은 하단 60pt를 피하며 관측한
여백·내어쓰기와 줄 간격을 확인한다. 미주 1건은 425자 중 하단 첫 15자만 복원했고 나머지를 연결하지 못했다.
기하만으로 각주와 미주를 구별할 수 없어 검출 결과는 footnote로 정규화한다. 따라서 합친
README 각주/미주 칸은 ⬜ 유지가 맞다. 양성 추가 표본도 필요하다.

| 칸 | 표본 파일 | 정답 근거 | 기대 | 실제 | 판정 |
|---|---|---|---|---|---|
| 각주 | 내부 실물 1문서 6건 | 같은 문서 HWPX Footnote와 원시 footNote 태그 | 정의 본문 6건과 본문 표지를 복원한다. | 실제 리더 정의 6/6건 일치, 전역 참조 번호를 출력한다. | 확인한 범위는 통과다. |

## 7. 표 개선 전제조건과 중첩 텍스트 계약

새 표 휴리스틱은 추가하지 않았다. 같은 행의 HWPX와 DOCX는 부모 셀 안의 Table 모델과 중첩
행·열 텍스트를 JSON과 Markdown에서 보존한다. 기존 PDF의 분리형은 이 계약의 일부만 만족한다.
내부 79쌍의 중첩 정답은 66개이고 현재 PDF 출력은 25개이며 정답 서명 일치는 24개다.
중첩 음성 66문서에는 기존 오탐 1개가 있다. 예전 연결형 추정은 +2개 정답에 211개 오탐을
만들었으므로 재도입하지 않았다. 현재 분리형 전제조건의 회수 상한은 24/66이다.

경계 후보 14건에서 열 일치와 기존 연속 표는 모두 3건이었다. 앞뒤 셀 텍스트를 합쳤을 때
HWPX 단일 셀과 같은 양성은 0건이므로 잘린 셀 결합을 구현·검증했다고 할 수 없다. 초기 기록의
15개 후보는 12% 시작 위치 조건을 적용하기 전의 수치이며 현재 14개와 분모가 다르다.

## 8. WMode 1 세로 폰트

Identity-V와 등록된 세로 CMap 이름, 스트림의 WMode/usecmap을 판별한다. ISO 32000-1의
9.7.4.3·9.7.5·9.4.4에 따라 DW2/W2, 글리프 원점과 y축 전진, Tc/TJ 및 CTM을 구현했다.
세로 전진에는 Tz를 곱하지 않고 원점 x에만 적용한다. W2는 CID 0~65535와 누적 65,536항목
확장 상한을 두며 손상 메트릭을 경고와 기본값으로 처리한다. 계산 결과가 비유한 좌표인 조각도
경고와 함께 건너뛰므로 다른 본문은 남는다.

전체 리소스 조사 983개에서 세로 표본 4개, 비세로 950개, 해석 불가 19개와 시간초과 10개를
구분했다. 시간초과는 제품 내부의 Exception 처리에 흡수되지 않게 별도로 기록한다.
최종 프로브의 두 번 실행 결과는 JSON 전체가 같았다. 이 조사는 별도 프로브의 분모이며 주석 조사와 섞지 않는다. ToUnicode가 있는 2개는
첫 런 문자열·좌표 2/2와 세로 열 문자열 10/10이 일치했다. 다른 2개는 ToUnicode가 없어 기존
Unicode 추정 금지 계약을 유지했다. 실물 W2 배열·범위와 비 Identity CMap의 코드→CID 변환은
미검증이다. `scripts/probe_pdf_vertical.py`로 재현한다.
