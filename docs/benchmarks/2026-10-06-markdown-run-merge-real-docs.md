# Markdown — 서식이 같은 인접 런을 한 번만 감싸기 (전 형식)

2026-10-06. Markdown 출력 계층의 변경이다. 리더와 모델은 건드리지 않았고 JSON·일반 텍스트 출력은 그대로다.
요소 지원을 더한 작업이 아니므로 README `Supported Elements` 표는 바꾸지 않는다.

## 무엇이 문제였나

문서 형식들은 글자 크기나 글꼴만 달라도 런을 가른다. 런마다 강조 마커를 치면 굵은 런 둘이 이어진 곳이
`**제1조(목적)****이 규칙은**` 이 된다. 가운데 `****` 는 앞이 구두점이고 뒤가 글자라서 CommonMark 의 닫는 구분자가
되지 못하고, 별표가 글자로 남는다. 강조가 풀리는 경우에도 LLM 입력에는 뜻 없는 마커가 끼어든다.
PPT 와 PDF 는 2026-10-02 부터 서식이 같은 인접 런을 합쳐 렌더했지만 나머지 형식에는 적용하지 않았다.
공개 표본 200개씩을 세어 보니 `****` 가 든 문서는 HWPX 70개, HWP 39개, DOCX 5개, PPTX 3개였다.

## 바꾼 것

`dochan/output/markdown.py` 의 런 병합(`_markdown_runs`)을 모든 형식에 적용한다. Markdown 에 드러나는 속성
(굵게·기울임·밑줄·취소선·위아래 첨자·링크)이 같고 출처(`provenance`)가 같은 인접 런만 합친다. 각주 참조와 수식 런은
경계다. 합치는 것은 렌더할 때의 사본이고 모델의 런은 그대로다(JSON 의 런 목록·글자 크기 불변).

## 전수 대조

`python -m scripts.probe_markdown_run_merge` 로 같은 모델을 이전 규칙과 현재 규칙으로 두 번 렌더해 비교했다.
CommonMark 해석에는 설치돼 있던 markdown-it-py 3.0.0 을 검증 도구로만 썼다. 대상은 15,216건(공개 14,959 + 내부 257)이다.

| 형식 | 파일 | Markdown 이 바뀐 문서 | `****` 전 → 후 | 글자로 남는 별표 전 → 후 | 별표가 준 문서 | 별표가 는 문서 |
|---|---:|---:|---:|---:|---:|---:|
| HWP | 5,761 | 1,312 | 5,992 → 106 | 35,496 → 20,112 | 913 | 3 |
| HWPX | 2,973 | 1,303 | 6,104 → 197 | 39,495 → 23,239 | 961 | 3 |
| DOCX | 1,785 | 130 | 319 → 0 | 1,014 → 110 | 66 | 0 |
| PPTX | 545 | 21 | 26 → 2 | 117 → 31 | 11 | 0 |
| DOC·PPT·XLS·XLSX·PDF | 4,152 | 0 | — | — | — | — |
| 합계 | 15,216 | 2,766 | 12,441 → 305 | 76,122 → 43,492 | 1,951 | 6 |

- 바뀐 2,766건 모두에서 강조·밑줄·취소선·첨자 마커와 이스케이프 역슬래시를 뺀 글자가 변경 전과 같다(낱말 단위 비교).
- JSON·일반 텍스트·오류 목록의 해시는 15,216건 모두 그대로다. Markdown 해시가 바뀐 문서 수는 위 표와 같다(2,766).
- "글자로 남는 별표"는 40만 자 이하인 2,759건을 CommonMark 로 해석해 인라인 글자 토큰에 남은 `*` 를 센 것이다.
- 병합 뒤에도 남는 `****` 305개는 서식이 서로 다른 런이 맞닿은 곳(굵은 기울임 뒤 기울임 등)과 본문이 별표인 곳이다.

### 별표가 는 6건

공개 HWP 3건·HWPX 3건(같은 문서의 두 형식 2쌍 포함)이고 모두 같은 꼴이다. `**기능****(3개)**과` 가 `**기능(3개)**과` 로
바뀐 곳이다. 닫는 `**` 의 앞이 닫는 괄호·따옴표이고 뒤에 조사가 붙으면 CommonMark 는 그 구분자를 닫는 것으로 보지 않는다.
변경 전에는 뒤쪽 `**(3개)**과` 만 깨지고 앞쪽 `**기능**` 은 굵게 나왔는데, 합친 뒤에는 구간 전체가 굵게 나오지 않는다.
원인은 병합이 아니라 한글에서 흔한 "구두점으로 끝나는 강조 뒤에 붙는 글자" 문제이고, 남은 43,492개에도 이 유형이 보인다
(`**‘지역 통계’**는` 등 — 비율은 세지 않았다). 이 문제는 이번에 고치지 않았다. 고치는 방법(구두점을 강조 밖으로 빼기, `<strong>` 쓰기)은
어느 쪽도 LLM 입력으로서의 깔끔함을 해칠 수 있어 따로 정해야 한다.
