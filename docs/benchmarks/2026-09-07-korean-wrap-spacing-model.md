# 2026-09-07 — 한글 줄바꿈 결합 공백 통계 모델 검증

## 목적

PDF 에서 줄바꿈으로 갈라진 한글 두 글자를 이을 때 공백을 넣을지 판정하는
문자 통계 모델(`dochan/pdf/spacing.py`, `dochan/pdf/korean_spacing.json`)의 효과를
실문서로 검증한다. 한글은 글자 단위로 줄이 바뀌므로 줄 끝이 어절 경계인지 PDF 만으로는
알 수 없고, 1.4.0 까지는 항상 무공백으로 이어 `이사회의운영에` 같은 오류가 남았다.

## 정답 라벨

동일 문서 HWPX↔PDF 79쌍에서 PDF 줄 병합이 일어난 한글-한글 경계마다 직전 줄 끝 3글자와
다음 줄 첫 3글자를 HWPX 플레인 텍스트(NFC, 공백 정리)에서 찾는다. `tail+head` 만 있으면
무공백, `tail+' '+head` 만 있으면 공백, 둘 다이거나 둘 다 없으면 채점하지 않는다.
결과 7,654건이 라벨링됐고 그중 39.3% 가 공백이었다.
(`scripts/compare_pdf_pairs.py` 의 `join_accuracy`; 직전 줄 '원문'을 문맥으로 쓰므로 앞선
예측 구분자가 라벨에 섞이지 않는다.)

## 규칙 후보 비교 (설계 단계 측정, 통계는 해당 문서를 뺀 78개 문서로 학습)

| 규칙 | 정확도 |
| --- | ---: |
| 1.4.0: 항상 무공백 | 0.607 |
| 앞 글자가 조사(은/는/이/가/을/를/의/에/서/로/와/과/도/만/께)면 공백 | 0.743 |
| 앞 글자 통계만 | 0.804 |
| 앞·뒤 글자 주변 확률의 나이브 결합 | 0.878 |
| 문자쌍 P(공백 \| 앞, 뒤) + 주변 확률 폴백 | 0.929 |

## 최종 모델 (표본 외)

학습 데이터는 저장소 밖 공개 HWP/HWPX 코퍼스(`scripts/download_public_hwp_corpus.py`,
법제처·국세청·정책브리핑·법원 등)이며, 평가용 79쌍(무역안보관리원 규정)은 학습에 쓰지 않았다.

```bash
python -m scripts.build_korean_spacing_model corpus/hwp-public --output dochan/pdf/korean_spacing.json --workers 6
python -m scripts.compare_pdf_pairs test_pairs/
```

| 학습 문서 | 음절쌍 | 모델 크기 | 결합 정확도 | 토큰 유사도 평균/최저 | 셀 일치율 |
| --- | ---: | ---: | ---: | ---: | ---: |
| (1.4.0, 모델 없음) | — | — | 0.607 | 0.938 / 0.805 | 0.894 |
| 80 HWPX (test_pairs, 인샘플 참고용) | 396K | 52 KB | 0.944 | 0.962 / 0.820 | 0.902 |
| 공개 코퍼스 465 | 2.29M | 192 KB | 0.929 | 0.961 / 0.822 | 0.902 |
| 공개 코퍼스 1,211 | 2.74M | 209 KB | 0.930 | 0.961 / 0.822 | 0.902 |

465 → 1,211 문서로 늘려도 정확도가 0.93 근처에서 수렴한다. 남은 7% 는 한 글자 문맥으로는
결정할 수 없는 경계(같은 글자쌍이 어절 안팎에 모두 흔한 경우)로, 더 긴 문맥(앞 2글자)이나
어절 사전이 있어야 줄일 수 있다.

## 모델 형식

- `prior`: 인접 한글 음절 사이 공백 확률(사전확률). `last[a]`/`first[b]`: 관측 20회 이상 글자의
  주변 확률. `pairs[a+b]`: 관측 5회 이상 쌍 중 주변 확률의 나이브 결합과 판정이 다르거나
  0.2 이상 차이 나는 쌍만 저장(예외 목록). 모두 소수 둘째 자리.
- 런타임은 쌍 → 주변 결합 → 사전확률 순으로 조회하고, 정확히 0.5 인 동률은 무공백으로 둔다.
- 리소스가 없거나 손상되면 빈 모델(사전확률만)로 동작하며 예외를 내지 않는다.
