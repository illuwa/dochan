# HWP·HWPX 대형 문서 레코드·셀 상한 검증

2026-10-03, 작업 `hwp-large`와 리뷰 반영 `hwp-large-fix`. 기준선은 `332d6d653a396a6ed024139d404809daa75b995e`이다. 원본은 읽기만 했으며 공개 파일명과 집계 수치만 기록했다. README, CHANGELOG, 공용 모델 및 출력 코드는 변경하지 않았다. 리뷰 반영의 전체 근거는 [후속 검증 문서](2026-10-02-hwp-large-fix-real-docs.md)에 기록했다. reader의 배포용 호출 연결과 공용 해제 유틸리티는 수정했다.

## 결과와 측정 범위

기존 200,000레코드 제한에 걸린 공개 HWP 5개가 완독되었고 해당 ERR가 모두 사라졌다. 기본 공개 HWP 5,363개와 HWPX 1,675개, 두 폴더에 혼재한 대소문자·다른 확장자 표본 38개를 포함해 총 7,076파일을 변환했다. 변경된 5개를 제외한 7,071개는 JSON·Markdown·일반 텍스트·오류 목록이 기준선 332d6d6과 정확히 같다. 추가 38개도 모두 같다. 파일 수는 폴더/확장자 기준이며 실제 파서는 파일 서명으로 형식을 판별한다.

구조 분포는 모델을 만들지 않고 레코드 헤더와 XML을 읽어 측정했다. 기본 HWP 32개, HWPX 2개, 추가 표본 1개에는 손상·압축 거부 등으로 일부 또는 전체 구조를 측정하지 못한 경우가 있다. 분포는 성공적으로 읽힌 스트림 기준이며 이들을 완독 표본으로 세지 않았다. 기본 HWP에는 배포용 27문서, 변경 추적 비트가 있는 3문서가 있었다. HWPX의 물리 XML 계수는 선택되지 않는 switch 분기도 포함하므로 출력 객체 수와 같다고 단정하지 않는다.

내부 실물은 157파일(HWP 77개, HWPX 80개)의 구조를 익명 집계했다. 비교 가능한 76쌍은 기존 `scripts.compare_hwp_pairs`의 `compare_pair`와 `summarize`로 전후 비교했다. 내부 파일명·내용은 저장하거나 인용하지 않았다.

레코드 헤더는 최소 4바이트이므로 바이트만 200MiB로 제한하면 빈 레코드 52,428,800개까지 허용한다. 이 때문에 바이트와 객체 개수 제한을 함께 둔다. 100만/130만은 실측 최대를 수용하는 명시적 자원 정책이며 특정 파일명이나 내용에 따른 예외가 없다. 기존 구조 깊이 64, 표 깊이 32, OLE 스트림/문서 바이트 제한도 유지한다.

상한 초과 시 기존 계약대로 이미 읽은 레코드의 본문을 보존하고 `doc.errors`에 ERR를 남긴다. `reject_record_limit=True`인 변경 추적 ViewText는 기존처럼 BodyText 폴백 전에 예외로 거부한다. 해당 시도의 레코드·바이트도 누적 예산에서 지출한다. 상한 뒤 레코드는 객체화하지 않는다. 크기 거부는 빈 섹션/DocInfo와 ERR로 강등된다. 잘린 deflate, CRC 오류, 잘못된 deflate는 예외에 기록한 해제량만 차감한다. 남은 예산 전부를 차감하던 결함은 정정했다. 문서 예산 진단은 종류별 1회만 남기고 배포용 검증과 본문 해제를 통합했다.

`_fix_empty_list_headers`의 반복 `pop`이 형제 배열을 반복 이동하는 O(n²) 경로도 제거했다. 한 번 읽고 한 번 압축하는 리스트 재구성으로 바꾸되 노드 순서와 재귀 방문 순서를 유지했다. 트리 보정은 최대 5회 선형 패스와 깊이 제한이 있는 순회로 제한된다. 기존 구현과 합성 랜덤 트리 2,000개의 노드/순서/오류를 비교해 동일함도 확인했다.

아래 자동 집계 표에 변경된 5파일과 기대/실제를 전부 열거한다. HWP 셀의 물리 헤더는 표 컨트롤 내부 TABLE 이후 LIST_HEADER이며 선언 격자는 TABLE의 행×열이다. XML/차트는 실제 요소와 배치 참조를 계수했다.

| --- | --- | --- | --- | --- | --- |

변경 추적 3문서는 운영 상수 그대로 재검증했으며 진단용 monkeypatch를 쓰지 않았다. API와 독립 BodyText 비교에 같은 BinData 연결을 적용했다. 대형 문서는 이미지 연결 전 plain 402,644자, 연결 후 402,642자이며 두 경로가 같은 조건에서 정확히 일치한다. BodyText 212,001레코드와 ViewText 265,451레코드의 끝까지 원시 계수를 완료했다.

대형 문서의 독립 ViewText final과 BodyText에는 저장 서식 차이가 남는다. Markdown 첫 차이는 0 기반 문자 위치 6,134에서 표 제목 앞 `# ` 유무이다. JSON 첫 차이는 `sections[0].elements[6].style_id`로 ViewText 19, BodyText 2이다. 전체 JSON 차이는 style_id 52,477개와 heading_level 255개뿐이며 텍스트·요소 종류·개수·표 구조·런 서식은 같다. 원시 PARA_HEADER 53,448개 중 스타일 바이트(offset 10)는 53,179개가 다르다. 첫 차이는 원시 문단 ordinal 22, ViewText offset 2,752(ID 19), BodyText offset 1,872(ID 2)이다. 이를 원본 저장 스타일 차이로 분류하고 임의 치환하지 않았다. API final은 저장 BodyText를 선택하므로 세 출력이 정확히 일치한다. 시장구조 문서는 배포용 암호화 문서가 아니라 변경 추적 문서이며 별도의 공개 배포용 문서들은 전체 비교에서 출력 변화가 없었다.

## 기준선 332d6d6 대비 출력과 내부 쌍 비교

`to_dict()`를 키 정렬 JSON으로 직렬화한 SHA-256, Markdown/plain의 SHA-256과 문자 수, 오류 목록, 예외를 파일마다 비교했다. 처리 시간과 RSS는 비교 판정에서 제외했다. 변환 예외는 전후 0개였다. 기준선은 332d6d6 소스를 임시 경로에 추출하고 별도 프로세스에서 import했다.

| 기본 HWP | 5,363 | 5,358 | 5 | 기존 레코드 상한으로 잘리던 본문만 복구되었다. |

재측정 기준선 99.422초, 리뷰 수정 후 118.731초가 걸렸다. 이는 병렬 3작업자로 수행한 코퍼스 비교 소요시간이며 성능 개선/저하의 통제 실험으로 해석하지 않는다. 내부 76쌍의 비교 지표 전체를 익명 직렬화한 SHA-256도 `e499b657caf5d937af020976b60ea295a06fba5d53c41f29fa2d939f5c7d37e8`로 같았다. 평균 토큰 비율 0.9997, 최소 0.9927, 평균 셀 일치율 0.9991, 평균 서식 일치율 1.0, 오류 있는 쌍 0개이다. HWPX 표 796개/HWP 표 795개라는 기존 차이도 그대로이며 이를 완전 동일 판정으로 바꾸지 않았다.

## 테스트·자원 측정과 재현

초기 대형 문서 작업과 리뷰 반영에서 실패 테스트를 먼저 확인했다. 리뷰 수정 후 전체 실행은 공개 실물 옵션을 켠 상태에서 **3,324 passed, 24 skipped, 14 xfailed**이며 Ruff와 diff 공백 검사도 통과했다. 손상 섹션 뒤 본문을 지우는 동작을 기대하던 HEAD 테스트 단언은 결함 근거와 함께 정정했다. DocInfo 경계 픽스처도 최종 20만 정책으로 바꿨다. 자세한 변경 근거는 후속 검증 문서에 적었다.

자원 측정은 파서 단독에서 공개 API(Dochan→to_markdown→to_json)로 교체했다. 모델과 두 출력 문자열을 보관하고 사례마다 새 프로세스로 최대 RSS를 측정했다. DocInfo 20만과 본문 3×100만 시도에서 65만 문단을 보존하고 나머지 레코드는 문서 130만 상한으로 거부했다. 시간은 다른 검증과 병행한 관측값이며 OS 강제 상한은 아니다.

다음 명령은 저장소 루트에서 실행한다. 코퍼스는 읽기 전용 인자로 전달하고 원본을 복사하지 않는다.

## 남은 제한과 판정

`pubinst-kostat_2022년_사회조사_결과_보도자료.hwpx`는 41,681,210바이트 section XML로 기존 32MiB 제한에 걸린다. `2026년 2분기 가축동향조사 결과 보도자료(최종).hwpx`는 168,436,854바이트 BMP가 기존 이미지 제한에 걸린다. 전자는 본문 완독 미지원, 후자는 이미지 제한 경고이며 셀·차트 점 상한과 원인이 다르다. 이 작업에서 XML/이미지 제한은 확대하지 않았으며 HWPX 전체 완독을 달성했다고 주장하지 않는다.

HWP 대형 본문 레코드 절단 해결은 단위 테스트와 공개 실물 5/5 검증을 충족했다. 독립 ViewText의 저장 서식 차이가 해결되지 않았으므로 변경 추적 칸은 ⬜로 유지한다. DocInfo 20만 초과 지원은 철회했으며 합성 경계 거부만 검증했다. 별도 실물 ✅ 근거로 쓰지 않는다. HWPX 셀·차트는 회귀 없음만 확인했으며 새 Supported Elements 기능을 구현한 것으로 올리지 않는다. README 표의 변경은 오케스트레이터에게 맡긴다.
