# HWP·HWPX 남은 기능의 실물 검증

2026년 10월 2일 `illuwa/w-hwp`에서 검증했다. 리뷰 반영 최종 결과와 제한 사항은 `2026-10-02-hwp-fix-real-docs.md`에 기록했다. README는 수정하지 않았다. 이 문서의 ✅는 아래에서 명시한 텍스트 추출 범위에 대한 제안이며, 미확정 기능은 해당 칸을 ⬜로 유지하도록 제안한다. 코퍼스는 외부 경로에서 읽기만 했고 저장소에 복사하지 않았다.

## 명세와 출력 계약

DOCX의 컨트롤·스마트 태그 테스트는 표시 텍스트를 기존 TextRun으로 순서대로 내는 계약이다. HWP/HWPX도 같은 모델과 출력 경로를 쓴다. 명령·내부 개체 이름·비선택 후보 목록은 표시값으로 추정하지 않는다.

공개 HWP 5 명세의 PARA_RANGE_TAG는 시작·끝 DWORD와 상위 8비트 종류·하위 24비트 값으로 구성된 12바이트 레코드이다. 삽입 0x10·삭제 0x11 및 DocInfo의 1 기반 참조는 위 공개 HWPX 정답쌍의 바이트와 XML을 비교해서 확인했다. DocInfo 변경 정보의 로컬 날짜 성분에는 시간대가 없어 UTC나 초를 만들어 넣지 않는다. 다른 종류·길이·손상 범위는 원문을 보존하고 부분지원 진단을 낸다. 비기본 모드의 미확정 투영은 HWPX처럼 ERR로 보고한다.

배포용 ViewText와 변경 추적 ViewText는 서로 다르다. AES 복호화는 배포용 bit 2가 있을 때만 적용하며, 변경 추적 bit 14만 있는 ViewText는 일반 압축 본문으로 읽는다. 압축 EOF 뒤 trailer는 임의 삭제하지 않고 CRC32·원문 길이와 영 패딩을 검증한다. 16바이트 슬롯 형식과 packed 형식은 둘 다 공개 실물에서 관찰했다.

HWP 스타일 표의 다음 스타일 ID와 HWPX nextStyleIDRef는 부모 스타일 참조가 아니다. 스타일의 문단·글자모양은 직접 ID로 해석하며 DOCX basedOn 체인을 가상으로 만들지 않는다. HWPX의 기존 깊은 개요 수준 제한은 바꾸지 않았다. 공개 스타일 검증은 수준 1–3만 확인했다.

## 내부 실물 회귀 검증

내부 실물은 파일명과 내용을 기록하지 않았다. 기준 HEAD의 소스만 임시 디렉터리에 풀어 동일한 76쌍을 다시 읽었으며, 저장한 비교 행에는 표본 이름이 없다. 각 행을 작업 결과와 비교했을 때 바뀐 행은 0개이고 tok_ratio·cell_hit·signature_exact·nested_exact·format_match 하락 쌍도 각각 0개였다. 임시 소스 디렉터리는 제거했다.

## 재현과 표본 한계

다음 명령은 코퍼스 경로를 인자로 받고 표본을 복사하지 않는다.

```bash
/usr/bin/python3 -m scripts.probe_hwp_features corpus/hwp-public
/usr/bin/python3 -m scripts.probe_hwp_distribution corpus/hwp-public/hwp
/usr/bin/python3 -m scripts.probe_hwp_styles corpus/hwp-public
/usr/bin/python3 -m scripts.probe_hwpx_features corpus/hwp-public/hwpx
/usr/bin/python3 -m scripts.compare_hwp_pairs test_pairs/
/usr/bin/python3 -m pytest tests/ -q -p no:cacheprovider --basetemp=.codex-work/pytest-tmp
```

공개 HWP 5,363파일의 기능 프로브는 양식 11문서·235개와 변경 추적 3문서를 찾았다. 일반 기능 프로브에서 29파일은 압축 trailer 검증 등의 이유로 읽기를 완료하지 못했고 5개 스트림은 레코드 진단이 있어, 코퍼스 전체를 완전 검증했다고 주장하지 않는다. 누름틀은 읽힌 범위에서 최소 228문서·4,387개가 있었으며 구식 세미콜론 명령 641개는 typed Direction 파서의 범위 밖이다. 입력된 본문 텍스트는 그 명령을 해석하지 않아도 보존한다.

생성 표본 경로를 시작 후와 마지막에 확인했으나 `corpus/generated/hwp/`는 없었다. 콤보의 현재 선택값·빈 selectedValue 매핑, 빈 표시 본문을 가진 구식 누름틀 안내문과 HWPX 안내문, 미압축 배포용 문서, 정답쌍이 없는 변경 추적 문서는 추가 실물 검증이 필요하다.

리뷰 전 전체 단위 테스트는 1,881 passed, 24 skipped, 14 xfailed였다. 리뷰 후 최종 수치는 후속 검증 문서에 기록했다. skip과 xfail은 실물 검증 통과로 세지 않았다. 신규 합성 테스트는 CI에서 외부 코퍼스 없이 실행할 수 있다.
