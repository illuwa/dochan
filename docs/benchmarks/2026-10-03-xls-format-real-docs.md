# XLS 시트 숫자 서식 실물 검증 (2026-10-03)

이 문서는 첫 구현 직후의 XLS/XLSX 짝 비교를 기록한 이력 자료다. 짝의 두 형식이 같은 서식기를 쓰므로 아래 일치율은 Excel 표시 정확도를 입증하지 않는다. 리뷰 반영 후의 Excel 저장 정답과 최종 판정은 `2026-10-02-xls-format-fix-real-docs.md`에 기록했다. 이 작업의 대상은 README `Supported Elements`의 XLS `날짜/숫자 서식` 한 칸이며, 문서 전체 출력은 저장하지 않고 SHA-256과 문자 수 및 오류 요약만 기록했다.

`scripts.compare_office_pairs`로 같은 이름의 XLS/XLSX 36쌍을 읽었고 파싱 실패는 0건이었다. 더 정확한 숫자 비교를 위해 두 파일에서 같은 시트·좌표의 원시 숫자가 허용 오차 안에서 일치하는 2,142셀을 따로 골랐다. XLSX 출력과의 일치는 변경 전 **1,451/2,142(67.74%)**, 변경 후 **2,130/2,142(99.44%)**였다. 679셀이 일치로 바뀌었고, 일치에서 불일치로 바뀐 셀은 **0개**였다. 남은 12셀은 `FormatKM.xls` 9개와 `tile-range-test.xls` 3개로, 양쪽 파일에 저장된 원시 부동소수 값의 표현 정밀도 차이 때문에 변경 전에도 불일치했다. 일부 조건부 서식은 XLSX 서식기 자체가 배율 쉼표를 미지원하여 원시 값을 보존한다. 이를 Excel 표시 정확 일치로 간주하지 않았다.

변경 전 불일치의 상위 원인은 다음과 같다. 전체 원인은 11종이므로 20개 한도 안에서 모두 기록했다. `General` 6건은 XLS/XLSX 원시 숫자의 정밀도 차이이며, 서식기의 오류로 세지 않았다.

공개 XLS 720개 전체의 Markdown 해시를 변경 전후 비교했다. 567개는 같고 153개가 달랐으며 양쪽 모두 문서 파싱 실패는 0개였다. 변경된 파일에서 원시 숫자·서식으로 추적한 표시 변경은 108,756셀로, 소수·회계 99,752, 분수 3,524, 백분율 2,424, 시각 1,423, 날짜 1,190, General 198, 앞자리 채움 175, 경과 시각 56, 과학 표기 14셀이다. 이 수치는 전체 출력 변경 지점의 원인 분류이며, 짝이 없는 셀까지 Excel 정답과 일치한다고 주장하는 수치는 아니다. 짝에서 직접 검증된 변경은 개선 679셀, 악화 0셀이다.

공용화한 XLSX 서식기의 출력 보존을 확인하려고 공개 XLSX 352개의 변경 전·후 Markdown SHA-256을 비교했다. **352/352개가 바이트 단위로 같았고 실패는 0건**이었다. `FormatChoiceTests.xlsx`의 `TEXT()` 수식 캐시 15개 중 13개가 공용 서식 결과와 같았으며, 불일치 2개는 `[< 10]`과 `[<      10]`처럼 조건 연산자와 숫자 사이에 공백이 있는 기존 미지원 문법이었다. 이는 이번 XLS 연결로 생긴 회귀가 아니며 별도 개선 범위다.

단위 테스트는 FORMAT·XF의 백분율, 통화 지역 코드, 날짜+시각, 경과 시각, 내장 서식 10 및 DATEMODE 1904와 수식 숫자 캐시를 합성 BIFF 바이트로 확인했다. 기존 테스트의 `0%`→`12.5%`·`21.7%` 단언과 날짜+시각→원시 `0.5` 단언은 과거 버그를 고정하고 있었다. XLSX의 기존 `0%` 테스트는 `0.125`→`13%`를 단언하고, 실제 공용 서식기는 `0.217`→`22%`와 1904 날짜+시각 `0.5`→`1904-01-01 12:00`을 낸다. 이 네 단언만 현재 출력 계약에 맞게 고쳤다.

위 짝 비교만으로는 XLS `날짜/숫자 서식` 칸의 ✅를 판정할 수 없다. 리뷰 후 Excel 저장 정답 기반 검증과 남은 한계는 `2026-10-02-xls-format-fix-real-docs.md`를 따른다.
