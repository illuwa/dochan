# PDF 본문 링크 재현율과 미주 실물 검증

2026년 10월 2일 `illuwa/w-pdf-links`에서 측정했다. README의 체크는 변경하지 않았다.
본문 링크는 재현율을 개선했지만 보류가 남아 있으며, 미주는 제한된 합성 경로만 통과했다.
두 칸 모두 현재는 ⬜를 유지하도록 제안한다. 연결한 범위의 정확도와 전체 재현율을 구분한다.

## 구현과 데이터 출처

Adobe Core 14 AFM 14개에서 글리프 폭 4,172개와 내장 인코딩 코드를 추출했다.
생성기는 `scripts/generate_pdf_core14.py`이며 생성물은 `dochan/pdf/core14_metrics.py`다.
원본 AFM의 SHA-256을 생성물에 기록했고, 다시 생성한 모듈의 바이트가 동일함을 확인했다.
모든 Adobe 저작권·상표 고지, MustRead.html의 허가 문단 전문과 수정본 표시를 생성물 머리와
NOTICE에 보존했다. 유니코드 대응에 쓴 Adobe Glyph List의 BSD 고지와 FontTools의
ZapfDingbats 대응표 MIT 고지도 함께 보존했다. FontTools는 로컬 데이터 생성에만 사용하며
라이브러리 런타임 의존성을 추가하지 않았다. 원본 AFM과 실물 문서를 저장소로 복사하지 않았다.

Standard, WinAnsi, MacRoman, Symbol, ZapfDingbats 인코딩과 Differences를 코드 → 글리프 이름 →
폭으로 연결한다. PDF MacRoman의 219번은 현대 Python 코덱의 Euro가 아닌 currency이며,
합성 PDF의 독립 PDFium 추출에서도 ¤를 확인했다. PDF에서 미정의인 Macintosh 수학 기호는
확정 폭으로 처리하지 않는다. 명시적 Widths는 AFM보다 우선한다. Arial·TimesNewRoman·CourierNew의
명시적인 별칭만 지원하고, 임의 부분 문자열·서브셋 접두사·내장 폰트에 AFM 폭을 강제하지 않는다.
폭 단위는 ISO 32000-1 §9.6.2.2와 Annex D의 텍스트 공간 1/1000 em이다.
Type0의 Identity-H CID는 W 배열의 두 형식과 내부 간접 참조를 읽으며, DW 또는 표준 기본 폭
1000을 근거 있는 폭으로 취급한다. CID 코드와 누적 확장량은 65,536으로 제한한다.
Differences는 4,096개로 제한하고 초과·비유한 기본 폭은 경고와 링크 보류로 처리한다.

링크 검사는 동일 목적지와 동일 사각형의 중복 계산을 합치고, 진행선과 교차하지 않는 영역을
먼저 제외한다. 원래 주석과 측정 분모는 보존하며, 글리프 경계 판정과 2,000,000회 검사 상한은
유지한다. 애매한 글리프 경계를 허용하도록 문턱을 완화하지 않았다.

## 본문 링크 전체 측정

기존 `scripts/probe_pdf_link_boundaries.py`로 공개 pdf.js 983개 전체를 변경 전후 측정했다.
PDFium 글리프 좌표를 독립 기준으로 사용하고, PDFium의 비유니코드 글리프는 기존 프로브처럼
pdfminer로 대조했다. 비교는 기존 NFKC·공백·soft hyphen 정규화를 그대로 사용했다.
Markdown, 일반 텍스트와 JSON의 최종 런 및 목적지 보존도 함께 검사했다.

| 지표 | 변경 전 | 변경 후 | text_tables 옵션 |
| --- | ---: | ---: | ---: |
| 조사한 공개 PDF | 983 | 983 | 983 |
| 목적지를 해석한 링크 문서 | 49 | 49 | 49 |
| 본문 연결 양성 문서 | 18 | 35 | 35 |
| 비교 가능한 Link 주석 | 678 | 678 | 678 |
| 연결·독립 기준 일치 | 87 | 372 | 372 |
| 경계 오류 | 0 | 0 | 0 |
| 보류 | 591 | 306 | 306 |
| 그중 실제 글자가 있는 보류 | 552 | 267 | 267 |
| 최종 출력 목적지 유실 문서 | 0 | 0 | 0 |
| 최종 런 불일치 | 0 | 0 | 0 |
| 프로브 오류 | 0 | 0 | 0 |

연결된 주석은 372/372개 일치했다. 비교 가능한 주석 전체 대비 연결률은 12.83%에서
54.87%로 올랐고 보류는 285개 감소했다. AFM·인코딩·CID 폭 변경 단계에서는 116개가 일치했고,
영역 검사 개선으로 256개가 추가되었다. 추가 256개는 `bug1978317.pdf` 한 파일의 주석이며,
동일 사각형·목적지를 합치면 128개다. 중복 주석이 포함된 연결률을 문서 일반화 성능으로 해석하지 않는다.

기존 본문 양성 18문서를 모두 다시 검증했다. 링크 없는 900문서, 목적지만 미해석인 9문서,
페이지·암호 등의 사유로 제외한 25문서는 기존 분류와 같다. 따라서 678을 원시 Link 객체 전체
수나 983개 전체의 모든 링크라고 주장하지 않는다. 글자가 있는 267개 보류가 남아 있으므로
본문 연결 칸은 ⬜ 유지로 제안한다. 특히 `freeculture.pdf` 171개와 `pdfjs_wikipedia.pdf` 51개가
남아 있으며, 모든 보류를 기본 폭이나 미해석 폰트 문제라고 설명하지 않는다.

## 미주와 각주 회귀

문서 끝의 명시적인 `미주`, `Endnotes`, `Notes` 제목과 앞선 본문의 고유한 위첨자 참조가

표나 새 본문, 번호 재시작으로 범위가 모호하면 본문에서 제거하지 않는다.

내부 미주 양성의 나머지 내용은 다음 페이지의 일반 본문과 표로 출력되어 있다.
PDF에 명시적 미주 제목이나 독립적인 연결 증거가 없어 마지막 페이지 전체를 미주로 옮기지 않았다.
`freeculture.pdf`에는 장별 소제목과 번호 재시작이 있고, 이후 감사문과 색인이 이어진다.
Link 주석 172개는 모두 URI이며 GoTo는 0개여서 목적지로 본문 참조를 직접 대응시키지 못했다.

공개 미주 검색은 `probe_pdf_notes.py --public`으로 983개를 독립 조사했고, 제목 양성 1개를
확인했다. Poppler 변환 비정상 종료·시간 초과 21개가 있어 나머지 전체를 음성이라고 단정하지 않는다.
프로브는 각주와 미주를 같은 후보 풀에서 비교하던 방식 대신 유형과 내용이 모두 맞아야 성공으로 센다.
실물에서 미주 복원 성공은 없으며 신규 미주 경로는 합성 테스트만 통과했다.

## 테스트와 재현

신규 Core 14와 링크·CID 테스트는 실패를 확인한 뒤 구현했다. 명시적인 미주 구역·여러 페이지 정의,
중복 참조와 출력 계약은 `tests/test_pdf_endnotes.py`의 합성 테스트로 검사했다.
기존 합성 각주 PDF 네 곳은 Helvetica의 폭을 500으로 가정한 배치였으므로 Widths를 명시했다.
기존 단언과 위첨자 검출 조건은 바꾸지 않았다. 원래 가정대로라면 Body 끝이 x=64였지만,
정확한 Helvetica AFM 폭에서는 x=67.348이 되어 기존 위첨자가 겹쳤던 것이 원인이다.

```bash
/usr/bin/python3 -m scripts.generate_pdf_core14 AFM_DIR --output dochan/pdf/core14_metrics.py --notice NOTICE
/usr/bin/python3 -m scripts.probe_pdf_link_boundaries PDFJS_DIR --output .codex-work/links-final.json --baseline .codex-work/links-before.json
/usr/bin/python3 -m scripts.probe_pdf_link_boundaries PDFJS_DIR --text-tables --output .codex-work/links-final-text-tables.json
/usr/bin/python3 -m scripts.compare_pdf_pairs PAIRS_DIR
/usr/bin/python3 -m scripts.probe_pdf_notes PAIRS_DIR
/usr/bin/python3 -m scripts.probe_pdf_notes PDFJS_DIR --public
/usr/bin/python3 -m pytest tests/ -q -p no:cacheprovider --basetemp=.codex-work/pytest-tmp
```

이 명령의 디렉터리는 읽기 전용 외부 코퍼스 경로를 인자로 전달한다. 독립 PDFium·pdfminer·Poppler는
검증 도구이며 제품의 외부 변환 엔진이나 런타임 의존성으로 추가하지 않았다.

최종 전체 테스트는 2,765 passed, 24 skipped, 14 xfailed였고 `git diff --check`도 통과했다.
