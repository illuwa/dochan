# 글 속 수식의 문단 보존: 공개 실물 검증

2026년 10월 4일 기준 워크트리 구현과 변경 전 `HEAD` 소스 스냅숏을 같은 공개 파일에 적용했다. `scripts/probe_inline_equation.py`는 파일마다 Markdown의 SHA-256과 길이, 수식 LaTeX 다중집합의 SHA-256, 수식 외 글자의 다중집합 SHA-256, 문단·수식·오류 개수만 기록한다. 문서별 전체 출력은 저장하지 않았다. 실행 중 실제 HWP 바이트가 `.hwpx` 확장자로 저장된 파일은 자동 형식 판별로 다시 읽었으며, 최종 집계의 파싱 실패는 0건이다.

DOCX 1,783개의 문단은 합계 36,745개에서 36,729개로 16개 줄었다. HWPX는 15,489개 줄었다. HWP는 기존에도 수식을 문단 뒤 블록으로 냈기 때문에 문단 개수는 변하지 않았다. 수식 런이 있는 파일 수는 HWP 58개, HWPX 28개, DOCX 8개다. HWP의 나머지 Markdown 변경 8개는 표 셀의 별행 수식을 복구한 결과다.

수식 외 글자의 공백까지 포함한 다중집합은 HWP 5,389/5,389, HWPX 1,662/1,687, DOCX 1,780/1,783개가 같았다. 차이가 난 HWPX 25개와 DOCX 3개는 이전 문단 분할 때 버려졌던 공백·탭·줄바꿈만 되살아났다. 이 28개에서도 비공백 글자 다중집합은 모두 같다. 새 구분 공백을 임의로 넣지 않았다.

HWP 수식 다중집합은 엄격한 전후 동일 기준을 **통과하지 못했다**. 46개 공개 파일에서 1,361식이 늘었고 수식이 줄어든 파일은 없다. 원인은 종전 HWP 표 셀 파서가 `Equation` 블록을 버리던 동작이다. 글 속 수식 런으로 옮겨지며 300식이 보이게 되었고, 셀의 별행 `Equation`을 보존하는 수정으로 1,061식이 더 복구되었다. 이 수정은 같은 문서 HWPX와 수식 총량이 같은 수학 양성 짝을 6/24에서 22/24로 늘렸다. 전후 동일성 실패를 숨기지 않고, 누락 복구로 판정한다.

공개 HWPX XML의 수식 24,648개 중 `<hp:pos>`의 `treatAsChar="1"`은 24,645개, `"0"`은 3개였다. 실제로 다른 비공백 글자와 함께 있는 20,849개만 런으로 옮겼다. 작업 배경의 7,803개는 현재 공개 코퍼스 구성에서 재현되지 않으므로 이번 실측값으로 대체한다.

## 같은 문서 짝

`corpus/hwp-public/SOURCES.json`의 동일 이름 HWP/HWPX 공개 짝은 610쌍이며 수식이 있는 짝은 24쌍이다. 이 24쌍의 글 속 수식 개수는 모두 같고, 양쪽에서 각각 19,491식이었다. 글 속 LaTeX 다중집합은 바이트 그대로 23/24쌍, 줄바꿈 `CRLF`와 `LF`만 통일하면 24/24쌍이 같았다. 전체 수식 LaTeX 다중집합은 18/24쌍이 같아, 기존 별행 수식 차이는 남아 있다. `corpus/press-pairs/`의 동일 이름 91쌍에는 수식이 없어 글 속 수식의 양성 검증에는 쓰지 않았다.

내부 문서의 동일 이름 HWP/HWPX 76쌍은 파일명과 내용을 기록하지 않고 집계만 남긴다. 그중 수식이 있는 1쌍은 별행 수식만 있으며 LaTeX 다중집합이 일치한다. 글 속 수식이 있는 내부 짝은 0쌍이므로 내부 짝으로는 이 기능의 양성을 검증하지 못했다. 기존 `scripts.compare_hwp_pairs`의 구조 비교도 76쌍, 표 서명 일치율 0.9987, 셀 평균 일치율 0.9999, 오류 쌍 0으로 끝났다.

## 리뷰 반영 후 재검증

수정 후 공개 HWP 5,389개, HWPX 1,687개, DOCX 1,783개를 다시 읽었다. 파싱 실패는 모두 0건이다. HWP의 수식 수와 수식 외 비공백 글자 다중집합은 직전 구현 대비 각각 5,389/5,389개가 같고, Markdown 해시는 35개에서 달라졌다. DOCX는 1,783/1,783개에서 수식 수와 Markdown 해시가 모두 같다. HWPX의 글 속 수식은 20,849식·6,703문단, 전체 수식은 24,648식으로 유지된다. 내부 표본의 문맥 문자열은 프로브 결과에 저장하지 않는다.
