# 2026-09-07 — PDF CTM 레이아웃 엔진·괘선 표 복원 실문서 검증

## 목적

1.4.0 의 PDF 레이아웃 엔진(CTM 그래픽 상태 반영)과 벡터 괘선 기반 표 복원이
실제 한글 'PDF로 저장' 문서에서 어느 수준으로 동작하는지, 같은 문서의 HWPX 파싱
결과를 정답지로 삼아 측정한다. README 비교표의 PDF 열 `표 (단순)`·`표 (셀 병합)`·
`읽기 순서` ✅ 는 이 측정을 근거로 한다.

## 코퍼스

- 동일 문서 HWP/HWPX/PDF 쌍 **79개** (`test_pairs/`, 저장소 밖 — 무역안보관리원 규정·지침
  242개 파일 중 `.hwpx` 와 `.pdf` 가 모두 있는 것). 모두 한글(Hancom) 'PDF로 저장' 출력이며,
  텍스트 런을 `q 0.12 0 0 -0.12 tx ty cm BT … ET Q` 로 감싸고 표 괘선을 `m/l/re + S`
  경로로 그린다.
- HWPX 파서 결과가 정답지다(AGENTS.md 검증 정책).

## 방법

```bash
python -m scripts.compare_pdf_pairs test_pairs/ --output /tmp/pdf-pairs.json
```

| 지표 | 정의 |
| --- | --- |
| tok_ratio | HWPX↔PDF 플레인 텍스트를 공백 토큰 시퀀스로 본 difflib 유사도 (문단·읽기 순서·공백 복원) |
| cell_hit | HWPX 표 셀 텍스트(정규화) 중 PDF 표 셀에 그대로 존재하는 비율 |
| signature_match | (행 수, 열 수, 병합 span 다중집합)이 완전히 같은 HWPX 표 비율 |
| merge_match | 행·열 수가 같은 PDF 표가 있는 병합 셀 표 중 span 구성까지 같은 비율 |

이전(1.3.0)에는 CTM 을 무시해 모든 조각이 Tm 원점(0,0)에 놓였고, 그 결과 페이지 전체가
공백 없는 한 문단으로 나왔다. 1.3.0 에서 보고한 문자 단위 유사도 0.868 은 이 결함을
가렸으므로(글자 순서는 맞았다), 이번에는 공백 토큰 기준으로 다시 잰다.

## 결과

| 지표 | 1.3.0 (기준선) | 1.4.0 |
| --- | ---: | ---: |
| 평균 tok_ratio | 0.032 | **0.936** |
| 최저 tok_ratio | 0.004 | 0.802 |
| PDF 표 수 (HWPX 845) | 0 | **868** |
| 평균 cell_hit | 0 | **0.894** |
| signature_match | 0 | 0.619 (523/845) |
| merge_match | — | **0.913** (210/230) |
| 표 검출 문서 | 0/79 | 79/79 |
| 크래시·ERR | 0 | 0 |

- 표 구조 완전 일치가 62% 에 그치는 주된 이유는 페이지에 걸친 표가 페이지별로 나뉘고
  (PDF 표 868 > HWPX 845), 중첩 표가 바깥 격자로 평탄화되기 때문이다. 행·열 수가 맞는
  병합 표에서는 91% 가 병합 구성까지 일치하므로 병합 셀 복원 자체는 신뢰할 수 있다.
- 최저 문서(`이해충돌방지제도 운영규정`, 0.80)는 중첩 표와 서식 표가 많은 문서다.
- 첫 페이지 개정 이력 표처럼 좌우 테두리를 생략한 표는 괘선이 뻗은 범위까지 열을 확장해
  복원한다(초기 구현 cell_hit 0.634 → 0.894 의 차이가 이 처리다).

## 남은 한계

- 괘선이 전혀 없는 표(선 없음 표)는 복원하지 않는다.
- 중첩 표는 독립 트리로 복원하지 않고 바깥 표의 격자에 포함된다.
- 페이지에 걸친 표는 병합하지 않는다.
- 한글 줄바꿈은 글자 단위라 어절 경계에서 끊긴 줄을 이을 때 공백이 사라질 수 있다
  (숫자·한글은 무공백 결합, 그 외는 공백 결합). 세로쓰기 읽기 순서는 그리기 순서를 유지한다.
