# 공개 보도자료 PDF 표와 줄 결합 검증

## 범위와 판정 방법

2026년 10월 4일에 공개 보도자료 HWPX/PDF 346쌍을 읽기 전용으로 비교했다. 기준 코드는
`177bfa0`이다. `scripts.compare_pdf_fix2`의 표 서명은 행 수, 열 수, 병합 span의
다중집합이다. `scripts.probe_pdf_press_tables`는 같은 쌍에서 텍스트가 겹치는 표의
대응 후보와 줄 경계의 공백 판정을 기록한다. 후보의 분류는 인과관계나 실제 표의
일대일 대응을 확정하는 판정이 아니다. 특히 1×3 HWPX 머리말 표와 1×1 PDF 제목
상자는 같은 글자를 담아도 서로 같은 격자라고 간주하지 않았다.

346쌍 중 `156783589.hwpx`와 `156784075.hwpx`는 배포용 암호화 때문에 정답
본문이 비었다. `156783622.pdf`는 렌더상 1쪽 요약본이고 HWPX는 전문이다.
전자는 정답 없는 2쌍으로, 후자는 내용이 다른 1쌍으로 별도 표시했다. 내용 차이
경고는 토큰 일치가 0.5 미만이면서 PDF 글자 수가 HWPX의 절반 미만일 때만 낸
보수적인 후보이므로 다른 배포 차이의 부재를 증명하지 않는다. 나머지 343쌍의
표 서명 정답은 3,094개이며 기준 일치는 586개다. 공식 전체 지표의 분모 3,102개와
구별해 해석한다.

## 줄 결합 공백 오류

휴리스틱 판정(앞뒤 3글자 문맥이 HWPX 에 공백 있게/없게 나타나는지)이 가능한 한글 줄 경계 9,283개 중 7,652개가 맞았다(0.8243).
공백 누락이 1,451개, 불필요한 공백이 180개다. 별도의 593개는 짧은 양쪽
문맥이 HWPX에 공백 유무 양쪽으로 나타나거나 모두 없어 채점하지 않았다.
`156783737.pdf` 3쪽의 일정표에서는 `기술개발`/`분과`와
`산·학·연`/`지원` 경계의 공백이 빠진다. `156784118.pdf` 1쪽에는
`가공`/`라인` 사이에 공백을 넣은 반대 사례가 있다. 렌더의 글자 위치만으로
복합어의 원래 띄어쓰기를 항상 알 수 없어서 통계 모델의 임계값을 임의로
바꾸지 않았다. 두 사례의 페이지 PNG를 독립 PDFium 렌더로 확인했다.

## 시도했지만 채택하지 않은 규칙 — 여러 열 그룹 아래 반복 소제목 머리행 제거

`156784165.pdf` 26–31쪽의 네 표는 다섯 순위 그룹(1위~5위) 아래 `연도/값` 두 줄 머리행이 쪽마다 반복되어 데이터 행으로 남는다(렌더 확인, 연한 파란 배경).
"첫 행에 서로 다른 그룹 제목이 3개 이상이고 그 아래 같은 문자 소제목 배열이 3그룹 이상 반복되면 반복 머리행으로 지운다"는 규칙을 시험했다.
보도자료 표 서명은 587 → 591/3,102 로 늘었지만(이 한 문서의 네 표), 채택하지 않았다.

- 실물 근거가 한 문서 한 양식의 양성 4개뿐이다. 새 분기의 전제조건(두 쪽의 둘째 행이 같음)이 평가된 횟수는 보도자료 4회(모두 이 문서), pdf.js 0회, 내부 0회라,
  "pdf.js 983개·내부 79쌍 출력 불변"은 이 규칙의 오탐을 시험한 음성 대조가 아니다.
- Opus 감수가 합성 PDF 로 데이터 행 삭제를 재현했다: 그룹 제목이 1위/2위/3위이고 다음 쪽 첫 데이터 행이 앞 쪽 첫 데이터 행과 같은 글자 배열이면(같은 상품·등급, 미리 인쇄된 `년 월 일`/`(인)` 양식, 모두 `적합`인 점검표, `O`/`X` 체크 행) 그 행이 사라진다.
  `row_span` 과 반복 행 조건을 더하면 일부는 막히지만 같은 행이 쪽마다 한 번만 나오는 경우는 글자·격자만으로 반복 소제목과 구별되지 않는다(머리행 배경색이 판별 근거가 될 수 있으나 표 후보에 색 정보가 없다).

## 재현과 한계

PDFium 렌더는 `.codex-work/renders/`에 선택한 쪽만 PNG로 보관했다. 표본명 뒤의
`-pN.png`는 PDF의 1부터 시작하는 N쪽이다. 원본 PDF·HWPX나 문서별 전체
Markdown 출력은 저장하지 않았다. 진단 JSON도 표 크기·쪽·텍스트 포괄률과
짧은 줄 경계 표본만 담는다. 코퍼스 경로는 실행 인자로 받는다.

```bash
/usr/bin/python3 -m scripts.probe_pdf_press_tables corpus/press-pairs .codex-work/press-diagnostic.json
/usr/bin/python3 -m scripts.compare_pdf_fix2 . corpus/press-pairs .codex-work/press-final.json --mode pairs --jobs 4
/usr/bin/python3 -m scripts.compare_pdf_fix2 . corpus/pdfjs-src/test/pdfs .codex-work/pdfjs-final.json --jobs 4
/usr/bin/python3 -m scripts.block_lxml pytest tests/ -q -p no:cacheprovider --basetemp=.codex-work/pytest-tmp
ruff check dochan scripts tests
```

`corpus/press-pairs`와 `corpus/pdfjs-src`는 읽기 전용 공개 자료를 가리키는 실행
인자 예시다. PDF 글자·괘선만으로 알 수 없는 배치용 표 경계와 숨은 병합은
추정해 구현하지 않았다. 후보 분류의 숫자는 실제 오류 유형의 확정 유병률이 아니다.
