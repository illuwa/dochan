# HWPX 파싱 반복 순회 제거

2026-11-02, 기준 v1.18.0 (`9a1b7f1`). HWPX 전수 파싱 합계가 18.42% 감소했고
두 모드 전 형식 출력 해시 차이는 0이었다. 작업자 검증을 통과했고, 유휴 장비 교대 재측정에서도 HWPX 파싱 −17.3%(3.12)·−18.3%(3.9)로
확인해 합류했다([통합 재측정](2026-11-02-round4-integration.md)). 공개 코퍼스는 읽기 전용으로 사용했다.
README 지원 표와 CHANGELOG는 변경하지 않았다.

## 범위와 측정 방법

- 전 형식 대상: `hwp-public`, `poi-src`, `lo-src`, `press-pairs`,
  `press-pairs-holdout`, `press-pairs-holdout2`, `press-pairs-holdout3`, `pdfjs-src`.
- 현재 기준 수집은 14,491개, 그중 HWPX는 2,683개다. 작업 배정의 과거 수치와 구별한다.
  형식별 집계는 확장자 기준이며 기존 문서 진단도 별도 해시로 대조한다.
- HWPX를 `(파일 크기, 경로)` 순으로 정렬하고 양 끝을 포함해 등간격으로 300개 선정했다.
  압축 파일 크기는 851~43,049,693바이트다. 전체 파일 목록과 원시 측정은 `.codex-work/`에만 둔다.
- import와 작은 문서 한 개의 준비 파싱은 프로파일·시간 측정에서 제외했다.
  파싱은 `Dochan(path)`만 측정하며 출력 직렬화 시간을 섞지 않았다.
- Python 3.9와 3.12에서 같은 표본을 전·후·후·전·전·후 순으로 실행한다.
  각 소스의 세 합계 중앙값을 비교한다. 동시 작업자가 있으므로 시간은 참고치다.
- 전 형식은 `python -m scripts.probe_output_speed collect … --workers 6` 및 `compare`를
  사용한다. Markdown·JSON·텍스트·진단의 SHA-256과 실패 상태를 대조한다.

300개에 포함된 공개 표본 예시다. 정답 근거는 동일 파일에 대한 기준 소스의 네 출력 해시이며,

## 구현 후보

`dochan/hwpx/parser.py`에서 선택된 XML 분기를 순회하는 반복자의 중첩을 줄였다.
본문 예산 검사는 같은 태그의 비용을 최대 1,024종까지만 저장하고, 차트 존재 여부도 함께
수집한다. 차트가 없는 섹션의 추가 전수 순회를 생략한다. 노드 제거는 모든 형제 순회 후
실행하여 예산 초과 시 다음 형제를 건너뛰지 않는다.

태그 이름 분리는 최대 1,024개, 이름 길이 256자 이하의 캐시를 사용한다.
`dochan/hwpx/revisions.py`에서는 무관한 태그에 대한 `rsplit` 대신 접미사를 비교한다.
수정 이력 속성은 `Element.get`으로 읽어 속성 없는 노드의 빈 딕셔너리 생성을 피한다.
기존 경량 호환 트리의 속성 매핑 조회도 유지한다.
공용 XML, 모델, 출력 계층과 C 소스는 변경하지 않았다. 새 의존성도 없다.

## 실제 파싱 시간

각 배열은 해당 소스의 실행 순서이며 실행은 전·후·후·전·전·후로 교대했다.

| Python | 전 3회 합계(초) | 후 3회 합계(초) | 중앙값 전 → 후(초) | 감소 |
|---|---|---|---|---:|
| 3.9.6 | 6.300196, 6.181772, 5.295016 | 5.149093, 5.094568, 4.364737 | 6.181772 → 5.094568 | 17.59% |
| 3.12.12 | 3.967622, 3.967245, 3.901219 | 3.321410, 3.309826, 3.299214 | 3.967245 → 3.309826 | 16.57% |

전체 HWPX 2,683개에서 파일별 두 번의 파싱 시간 중 작은 값을 합산하면
74.052138 → 60.414399초로 **18.42% 감소**했다. 단일 실행의 가장 빠른 전후 합계는
74.401604 → 60.692432초였다. 300개 합계만으로 전체 개선을 판정하지 않았다.

병행 부하의 영향은 크다. 동일 기준 소스의 전 형식 수집 wall이 72.5초와 274.1초였고,
최종 후보의 두 실행도 207.9초와 64.5초였다. 변경하지 않은 형식의 시간도 움직였다.
따라서 모든 시간은 작업자 참고치이며 통합 판정은 유휴 장비에서 재측정해야 한다.

## 출력 및 회귀 검증

- 가속 켬·끔 각각 14,491개 문서의 Markdown·JSON·텍스트·진단 해시 차이 0.
  누락, 실패 변화, 표준 JSON 폴백도 0이다. 각 수집의 예외·시간 초과 failure는 0개다.
- 현재 공개 `press-pairs`에서 스크립트가 식별한 HWP/HWPX 91쌍의 상세 비교 결과 차이 0.
  표 구조·셀·서식 일치율의 기존 1.0을 유지했다. 기존 토큰 평균 0.9883 등 차이도 유지했다.
- 선택 분기 순서와 예산 초과 시 가지치기를 기준 구현과 무작위 10,000개 트리에서 대조했다.
  남은 XML, 예산, 보존 텍스트, 진단이 모두 같았다.
- 신규 회귀 테스트는 반복 태그 분리·무관한 수정 이력 태그 분리·빈 속성 매핑 실체화에서
  먼저 실패를 확인했다. 선택 분기, 주석, 각주 예산, 차트 진단도 함께 검증한다.
- 전체 테스트: 가속 켬 7,297 passed / 39 skipped / 14 xfailed,
  끔 7,287 passed / 49 skipped / 14 xfailed. `ruff check dochan scripts tests setup.py` 통과.
- C 소스 변경과 새 모듈이 없어 C 차등 퍼징·ASan/UBSan·교차 헤더 빌드 대상은 없다.

파일별 2회 최솟값에서 파싱 또는 전체 변환 합계가 1.2배 초과인 1,619개를
전후 각각 20회 재검사했다. 이 단계에서 HWPX 회귀는 0개였으나, 변경하지 않은 형식의
15개 파일에서 파싱 14건·총합 13건의 초과 변동이 남았다. 모두 파싱 중앙값이 4ms 미만이었다.

해당 15개만 두 소스를 별도 프로세스에 미리 import하고, 한 번씩 준비 변환한 뒤
파일마다 전·후 / 후·전 순서를 번갈아 20회 측정했다. 측정 프로세스는 한 번에 하나만
실행하고 각 요청의 응답을 확인한 후 다음 요청을 보냈다. 최종 파싱 비율은
0.967~1.025배, 총합 비율은 0.973~1.026배였다. **1.2배 초과 회귀는 최종 0개**이며,
두 차례 재검사의 출력 해시·실패 상태 변화도 0이다. 원래 병렬 재검사 수치와
격리 교대 재검사 수치는 서로 다른 로그에 보존했다.

## 판정과 후속 제안

순수 Python 변경으로 전수 -15% 목표, 두 런타임 표본 측정, 출력 불변, 파일별 회귀,
전체 테스트·린트를 모두 통과했다. C 모듈 추가 없이 채택 후보로 남긴다.
작업자 시간은 참고치이며 오케스트레이터의 유휴 장비 합류 측정은 별도다.

공용 모델의 `_find_recursive`는 최종 프로파일에서도 148,482회, 누적 0.445초다.
`_load_image_data`의 `doc.find_all('image')` 등 공통 모델 순회에 재사용 가능한 결과나
대상 축소가 가능한지 별도 작업에서 검토할 수 있다. 이번 작업의 소유 범위 밖이므로
모델·리더·출력 코드는 수정하지 않았으며 예상 개선율도 주장하지 않는다.
