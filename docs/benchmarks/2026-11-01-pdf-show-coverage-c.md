# PDF C 글자 경로 3차 검증

기준은 `3df1bc9`의 별도 `base-speed2` 체크아웃이다. 기준 소스는 수정하지
않았다. 커밋·푸시하지 않았으며 README·CHANGELOG·다른 작업자의 파일은
수정하지 않았다. 새 런타임/빌드 의존성은 없다.

## 변경 범위

- 정확한 기본 바이트 디코더, 정확한 WidthMap, 신뢰 가능한 가로 글꼴만
  추가로 C에서 실행한다. cp1252 미정의 바이트 81/8D/8F/90/9D가 있으면
  전체 문자열의 latin-1 전환 및 char_offsets 의미가 달라지므로 연산 전체를
  상태 변경 전에 Python에 맡긴다. TJ의 앞 원소도 먼저 실행하지 않는다.
- 최종 조각 목록의 8개 좌표 필드를 제한 API C 함수로 검사한다. C 조각,
  Python 콜백 조각, Form 조각 모두 검사한다. 삭제 전 order 및 다른 필드는
  보존하고 하나라도 제외되면 기존 한국어 WARN을 같은 위치에서 한 번 추가한다.
  순수 Python 경로는 기존 검사를 유지한다. space_width는 원래 검사 대상이
  아니므로 새로 제외 조건에 넣지 않는다.
- 생성 시 조각을 즉시 버리면 이후 order/마크/콜백에서 관찰되는 목록이
  달라질 수 있어 종료 시점의 필터를 유지했다. 공개 Fragment 필드를 추가하지 않는다.
- 세로·Type3·사용자 디코더/폭 및 신뢰도 낮은 비-Encoding 글꼴은 유지한다.
  FontInfo에 subtype이 없고 reader.py는 수정 금지다. link_metrics_reliable=False를
  일괄 허용해 수용률을 올리지 않았다. 혼합 ToUnicode/가변 Encoding CMap은
  경고·코드 경계·char_offsets를 증명하지 못하므로 기존 위임을 유지한다.
- AES는 선택 과제라 변경하지 않았다. _clines의 안정 정렬 및 할당은 별도 계측한다.

누수 검증을 주장하지 않는다. Linux/Windows 실행은 하지 않았다.

## 글꼴 계측

속도 표본 300개를 Python 경로로 해석하여 `_show`의 글꼴별 기회를 집계했다.
표 준비 가능 여부와 실제 연산 완료 카운터를 구분한다.

| 종류 | 전 C 표/전체 | 후 C 표/전체 |
| --- | ---: | ---: |
| 기본 디코더, 가로 reliable | 0/1,162 | 1,162/1,162 |
| 기본 디코더, 가로 unreliable | 0/17,601 | 0/17,601 |
| ToUnicode 고정 1바이트 reliable | 16,734/16,734 | 동일 |
| ToUnicode 고정 2바이트 reliable | 372,862/372,862 | 동일 |
| ToUnicode 혼합 reliable | 0/112 | 동일 |
| ToUnicode 혼합 unreliable | 0/101,726 | 동일 |
| Core14 reliable | 3,109/3,109 | 동일 |
| Encoding closure | 1/3 | 동일 |
| lambda reliable | 0/996 | 동일 |

전체 분류는 `coverage-before.json`, `coverage-after.json`에 있다. Type3 subtype,
Differences 및 bfrange 원문 표기는 FontInfo에 보존되지 않아 직접 분류했다고
주장하지 않는다. 표본에서 세로 글꼴 기회는 관측되지 않았다.
실제 C 완료 글자 연산은 **148,515/191,901 → 149,118/191,901**이며,
Python yield는 **43,386 → 42,783**이다. C raw show는 392,706 → 393,868이다.

## 남은 C 비용

계측 빌드는 일반 빌드와 별도 복사본이다. 정상 빌드에는 타이머가 없다.
clock CPU 누적에 계측 비용이 포함되므로 아래 값은 속도 판정에 사용하지 않는다.

| C 글자 구간 | 전(초) | 후(초) |
| --- | ---: | ---: |
| 디코딩/폭 | 0.195527 | 0.193937 |
| 위치/offset | 0.228294 | 0.225967 |
| 크기/공백 | 0.181464 | 0.180813 |
| Fragment 구성/strip/전진 | 0.574816 | 0.586064 |

Fragment 구간이 여전히 C 글자 계측의 약 절반이다. Python `_show`도
123,237회에서 122,075회로만 줄었다. 비유한 필터 C 함수는 883회 호출,
cProfile 누적 0.060초다. 기준의 해당 제너레이터는 4,102,047회 호출이었다.
계측 중 정확성 검사들이 병행됐으므로 전후 누적 시간 자체를 처리량 개선으로
해석하지 않는다. 성능 판정은 아래 독립 교대 측정에만 근거한다.

## 속도 및 최종 판정

파일당 양쪽 예열 1회 뒤 전·후·후·전(다음 파일은 역순)으로 각 2회
실행하고 최솟값을 비교했다. 같은 스레드에서 소스 모듈을 전환하고 매 전환
실제 소스/확장 경로 및 새 API 유무를 확인했다. 시간 밖에서 GC 및 소스
전환을 수행했다. 매 측정에서 네 출력 해시를 기준과 비교했다.
측정 중 이 작업의 다른 테스트·퍼징·계측은 실행하지 않았다. 호스트의 다른
작업 부하는 검증하지 못했으며, 독점 장비 결과로 주장하지 않는다.

**PDF 합계 10% 개선 목표는 두 환경 모두 미달**이다. 큰 미수용 집단을
안전성 근거 없이 C로 옮기지 않았으며, 남은 Fragment 구성 및 Python 글꼴
경로가 다음 병목이다. 소음 재검사 중앙값 기준 회귀는 0이지만 원시 초과
기록은 남아 있다. 이 작업에서 합류·커밋은 수행하지 않았다.

_clines는 별도 복사본의 정상 경로에만 clock 계측을 넣었다. 300개 표본에서
버퍼 5개 할당/초기화 0.014982초, Fragment 읽기/검증 0.134032초,
행 정렬 0.031773초, 행 구성 전체 0.598269초였다. 정렬은 행 구성 시간에
포함되므로 합산하지 않는다. 안정 병합 정렬과 행별 공유 scratch를 이미
사용한다. 정렬/할당보다 행 구성 비용이 커서 이 부분을 변경하지 않았다.
실패/위임 경로의 검증 및 cleanup 시간은 위 세부 값에서 빠질 수 있다.

## 재현 및 원자료

- 빌드: `DOCHAN_BUILD_ACCEL=1 /usr/bin/python3 setup.py build_ext --inplace --force`.
- 테스트: `python -m pytest tests/ -q -p no:cacheprovider`; 비가속은
  `DOCHAN_DISABLE_ACCEL=1`로 반복. ruff는 `dochan scripts tests setup.py`.
- 공개 해시: `.codex-work/collect_pdf.py`에서 probe_output_speed 확장자를 PDF로
  제한하고 `--source <기준>` / 현재 / 비가속 수집, `compare`로 대조한다.
- 일반 차등: `python -m scripts.probe_pdf_show_full <pdfjs> <press-pairs> --cases 100000`.
- 집중 차등: `.codex-work/fuzz-new.py <소스> <pdfjs> <press-pairs> --cases 100000`.
- 원자료는 `.codex-work/`의 hash-*, fuzz*, sanitizer*, coverage-*, profile-*,
  tests-*, filewise.log, fix-inprocess.json, fix-bench-results.json이다. 문서 본문은 저장하지 않는다.
