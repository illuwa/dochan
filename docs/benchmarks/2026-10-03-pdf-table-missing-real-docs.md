# PDF 표 미발견 119건의 테두리·선분 검증

## 판정 방법과 범위

내부 HWPX/PDF 79쌍을 읽기 전용으로 검사했다. HWPX 원본 `Contents/header.xml`의 `borderFill`에서 네 변의 선 종류와 굵기를 읽고, 각 셀의 `borderFillIDRef`로 연결했다. 원본 표와 모델 표의 순서·행열 수는 119건 모두 일치했다. PDF에서는 기존 `PathCollector`가 `re`, `m/l` 획과 얇은 채움 사각형에서 수집한 장치 좌표 선분을 표 검출 직전에 관찰했다. 셀 글자를 PDF 글자 줄에 대조해 위치 후보를 찾았다. 파일명과 본문은 출력하지 않았다.

닫힌 외곽선과 표 행·열 수에 맞는 전폭 경계가 모두 확인될 때만 (a)로 판정했다. 한 쪽의 글자 대응 점수가 다른 쪽 합계보다 우세하고 근처에 일부 선분만 있으면 (c), 우세한 대응 위치에 선분이 없으면 (b)로 판정했다. 반복 문구로 여러 쪽이 후보이거나 글자 대응이 없으면 (d)로 남겼다. 여러 쪽 후보의 선분 관찰은 실제 표 위치를 확정하지 못하므로 (b)·(c)로 승격하지 않았다.

## 원인 집계

| 분류 | 건수 | 확인한 사실 |
| --- | ---: | --- |
| (a) 괘선이 그려졌으나 격자를 놓침 | 0 | 우세한 위치 대응 15건에서 닫힌 외곽선과 행·열 경계가 일치하는 표를 확인하지 못했다. |
| (b) PDF 괘선 없음 | 2 | 우세한 글자 위치에 가로·세로 선분이 모두 없었고 HWPX 셀의 네 변도 모두 `NONE`이었다. |
| (c) PDF 선분 일부 | 13 | 우세한 글자 위치에 가로·세로 중 일부만 있거나 선 수·연결이 표 격자와 맞지 않았다. |
| (d) 기타·위치 불명확 | 104 | 반복 문구로 여러 쪽이 후보 94건, 비어 있는 셀 글자 7건, PDF 줄 대응 없음 3건이다. |

HWPX 셀 테두리는 가로선만 있는 표 79건, 가로·세로선 모두 있는 표 26건, 네 변이 모두 없는 표 13건, 세로선만 있는 표 1건이었다. 이 수치는 원본 서식이고 PDF에 실제로 그려진 선의 수와 구별된다. 119건 중 15건만 PDF 한 쪽에 글자 대응이 우세했다. 따라서 나머지 104건을 “PDF에 괘선이 없다”고 단정할 수 없다.

## 안전 기준과 남은 한계

합성 PDF 테스트는 `re` 외곽선·`m/l` 내부선, 가로선만 있는 경우, 얇은 채움 사각형, 괘선이 없는 경우와 선분 2만 개 초과 입력을 검사했다. 전체 테스트는 4,787개 통과, 31개 건너뜀, 14개 예상 실패였고 Ruff도 통과했다. 내부 79쌍의 `compare_pdf_fix2` 측정은 79/79개 완료, 실패 0개였으며 전체 표 서명 일치율 0.6533과 병합 일치율 0.9277을 확인했다.

공개 pdf.js 983개는 983/983개 완료, 문서별 Markdown SHA-256 983개를 기록했다. 기존 표가 있는 문서는 41개이고 표는 250개였다. 이 작업은 `dochan/` 런타임 파일을 수정하지 않았으므로 같은 입력의 표 수·Markdown 해시·나머지 지표는 수정 전후 동일하며 새 오탐은 0개다. 공개 문서의 기존 표 250개를 모두 독립 정답으로 검토한 결과라는 뜻은 아니다.

(c) 13건에서도 닫힌 외곽선과 일관된 행·열 경계를 모두 확인하지 못했다. 가로선만 있는 표의 열 정렬도 빈 셀과 반복 문구 때문에 단일하게 결정되지 않았다. 근거 없이 열을 만들어 기존 문단을 표로 승격하면 오탐 가능성이 있으므로 안전한 회복 수는 0건이다. README의 체크 표시는 바꾸지 않는다. 추가로 회복하려면 원본과 PDF의 쪽·문단 위치를 더 엄격히 대응할 수 있는 공개 실물 표본이나 독립 좌표 정답이 필요하다.
