## 음성 집합을 먼저 측정한 결과

구현 전에 허용 상한을 내부 음성 문서 발화 **0건**, 공개 출력 회귀 **0개**로 정했다.
중첩 정답이 없는 내부 문서는 66개였다. 처음 기하만 검사했을 때 내부 양성 문서에서
2건, 공개 도면에서 1건이 발화했다. 공개 표본을 확인한 뒤 텍스트가 없는 격자를
거부했고, 기존 중첩 표 채택 조건에 미달하는 자식도 부모 변경 전에 거부했다.

공개 983개 중 기준 리더가 표를 출력한 문서는 41개다. 이들은 오탐 감시 집합으로
포함했지만, 전체 공개 코퍼스에 독립적인 중첩 정답이 있다는 뜻은 아니다. 983개 모두
측정을 완료했고 기준·최종에 문서 단위 ERR가 각각 13개 있다. 이 기존 해석 실패를
정상 해석 성공으로 세지 않았다. ERR·경고·Markdown·JSON의 변화는 0개다.

## 연결형 복원의 조건과 한계

괘선 교차 그래프에서 선 하나를 제거했을 때 나뉘는 닫힌 내부 격자를 찾는다.
그 격자가 부모의 한 셀에 들어가고 한 변만 공유하며 나머지 세 변은 셀 안에 있어야 한다.
일반 병합 표, 두 변 이상을 공유한 모서리 격자, 빈 도형과 모호한 경우는 기존 격자를
유지한다. 별도 성분 안에 이미 들어 있는 연결형과 한 성분의 여러 연결형을 재귀적으로
분해하는 경우는 이번 지원 범위에 포함하지 않았다.

반복 DFS로 단절점을 구하며 재귀를 사용하지 않는다. 연결 성분 2,000선, 검사 200만 회,
기존 페이지 50,000셀·문서 200,000셀·후보 1,000개 상한을 지킨다. 부모·자식과 페이지의
다른 성분을 함께 수용할 수 없으면 분리 전 격자를 유지한다. 검사 예산 초과는 경고로
남기며 문서 단위 실패로 전파하지 않는다. 기존 `Cell.paragraphs` 안의 `Table`과
Markdown의 열 ` / `·행 ` ; ` 구분을 그대로 사용했다.

## 병합 불일치의 원인 분류

기준의 235−216=19는 특정 표 19개를 식별한 목록이 아니다. 기존 비교 도구는 크기와
서명의 Counter를 독립적으로 소비한다. 이를 개별 대응이 확정된 19개로 간주하면
분류를 잘못하게 된다. 별도 프로브에서는 같은 크기의 미일치 후보 22개를 찾았다.
그중 1개는 동일 서명 개수만 부족했고, 21개는 span 구성이 달랐다. 21개 중 텍스트
집합이 같은 것은 4개, 일부 공통 셀이 있는 것은 5개, 공통 셀이 없는 것은 12개였다.

| 원인 범주 | 관찰 결과 | 처리 |
| --- | --- | --- |
| 그려지지 않은 경계다. | 텍스트 집합이 같은 4표에서 HWPX가 의도적으로 NONE으로 지정한 경계를 확인했다. | PDF에 없는 경계를 추정해 추가하지 않았다. |
| 짧은 점선 조각의 소실이다. | 양성 표의 누락 구간에 0.36pt 조각 1,320개가 있었고 기존 최소 길이 1pt 필터에서 제외됐다. | 기존 격자 내부 축에서 반복되는 공선 stroke만 보강했다. |
| 얇은 선·겹선·반올림이다. | 기존 후보의 허용오차를 0.25, 0.5, 0.75, 1, 2, 3pt로 바꿔도 서명 복원은 0건이었다. | 수치를 임의로 조절하지 않았다. 별도 확정 원인으로 세지 않았다. |
| 대응이 모호한 나머지다. | 같은 행·열만으로 같은 표임을 보장하지 못한다. | 미해결로 남겼다. |

짧은 stroke 전체를 일반 괘선으로 넣는 초기 실험은 공개 도면과 내부 무테두리 표본의
읽기 순서를 바꾸어 폐기했다. 최종 구현은 짧은 조각을 별도 20,000개 한도 안에 모으고,
길이가 같으며 양의 간격이 두 번 이상 반복되는 공선 구간만 인정한다. 기존 긴 괘선이
정한 내부 x/y축과 영역만 보강하며 새 표·행·열·외곽선을 만들지 않는다. 한도를 넘으면
선택적인 보강을 전부 포기하고 기존 긴 괘선의 예산과 출력을 보존한다.

## 페이지 경계와 무테두리 표의 결정

경계 프로브는 페이지 연결 판정 호출 242회 중 열이 같은 37회를 조사했다. 실제 같은
셀인 양성 2개가 있지만 기존 페이지 연결 승인 3회 안의 양성은 0개다. 두 양성에는 다음
표 위의 본문이 있고 경계도 닫혀 있다. 상단 조건만 느슨하게 만들면 같은 셀의 연속과
새 행을 구별하지 못하므로 결합 구현은 하지 않았다. 기존의 14개 후보 조사와 이번
37회 조사는 분모가 다르다.

명시적 무테두리 1×1 표본의 본문은 문단 25개와 작은 표 셀 안 문단 2개에 걸쳐
보존된다. 이를 단일 문단 또는 1×1 표 복원 성공으로 보고하지 않는다. 짧은 선 전체
보존 실험에서 발생한 순서 회귀를 음성 사례로 삼았고, 최종 출력에서는 다시
정답 전체가 순서대로 포함되는 것을 확인했다.

## 재현과 테스트

코퍼스 경로는 명령 인자로 받는다. 기준 및 단계별 코드는 별도 스냅샷에서 실행하여
실행 중인 변경이 측정 결과에 섞이지 않도록 했다. 아래 명령의 `BASELINE_REPO`와
`PAIRS_DIR`는 각각 기준 체크아웃과 읽기 전용 내부 짝 디렉터리로 치환한다.

```bash
/usr/bin/python3 scripts/compare_pdf_fix2.py BASELINE_REPO corpus/pdfjs-src/test/pdfs .codex-work/public-baseline.json
/usr/bin/python3 scripts/compare_pdf_fix2.py . corpus/pdfjs-src/test/pdfs .codex-work/public-final.json
/usr/bin/python3 scripts/compare_pdf_fix2.py . PAIRS_DIR .codex-work/pairs-final.json --mode pairs

/usr/bin/python3 -m scripts.probe_pdf_connected_tables corpus/pdfjs-src/test/pdfs .codex-work/connected-public-final.json --apply
```

연결형 합성 PDF의 네 방향·기존 출력 계약·일반 병합 음성·빈 도형·예산 부족을
검사했다. 짧은 점선 합성 PDF는 가로·세로 경계, 새 축 생성 금지, 긴 선 예산 보존을
검사했다. 경계 셀과 무테두리 프로브는 합성 PDF/HWPX 및 개인정보 비노출을 검사했다.
기존 테스트 단언은 수정하지 않았다. 공유 모델·출력·공용 reader 파일의 변경과
새 런타임 의존성은 없다. PDF 내부의 PageContent에 짧은 선분 필드만 추가했다.

최종 전체 테스트는 **3,704 passed, 29 skipped, 14 xfailed**이며 전체 Ruff와
`git diff --check`도 통과했다. 겹치는 점선·긴선의 피복 중복 회귀도 합성 PDF로
검증했다. 비교 스크립트는 기존 결과 JSON을 재사용하므로 재측정할 때는 반드시
새 출력 파일명을 사용하거나 이전 결과를 별도로 옮긴다.
