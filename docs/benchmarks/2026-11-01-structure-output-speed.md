# 문서 구조·공용 출력 최적화 검증 (2026-11-01)

기준은 round3의 `73a05cb`다. 새 의존성 없이 소유 범위의 네 런타임 파일과
두 테스트 파일을 수정했다. 커밋·푸시·합류하지 않았다.

## 구현과 보존 계약

- `_cobjects.xref_table`: xref 항목을 C에서 읽고 임시 사전을 반환한다.
  정상 완료 후에만 기존 xref에 최신 항목 우선으로 반영한다. trailer 파싱과
  경고는 기존 경로를 사용한다. 비정상 입력·큰 정수는 Bailout으로 원래
  Python 파서를 처음부터 실행하여 부분 반영, 커서, 오류 메시지를 보존한다.
- `_cobjects.xref_stream`: 폭·구간을 먼저 검사하고 필드별 임시 바이트와 리스트를
  만들지 않고 정수를 읽는다. xref/압축 객체 각각의 순서, 중복 우선순위,
  삭제 표식, 부족한 데이터의 처리와 부분 실패를 Python 거울과 동일하게 유지한다.
- `get_object`: 캐시 조회를 한 번으로 줄이고 cached None과 cache miss를 구별한다.
  참조 해결의 지연 평가와 경고 순서는 그대로다. 참조 일괄 선행 해결은 추가하지 않았다.
- Markdown: 셀에서 불필요한 서식 런 병합·TextRun 복제를 제거하고 링크만 묶는다.
  평문 런은 공백 분리·재조합을 생략한다. 서식 비교 키와 캡션 escape 표를 재사용한다.
- `find_all`: 섹션을 연결해 iterator stack으로 한 번 순회한다. 깊이32, 순서,
  순환·공유 노드 제거, inline equation 동작을 보존한다. 기존 `_find_recursive`는
  직접 호출하는 제목 추정 코드의 계약 때문에 원문 그대로 남기고 새
  `_find_iterative`를 사용한다. 기존 테스트의 호출 횟수 단언을 바꾸지 않았다.

## 이미지 변경을 채택하지 않은 이유

제공된 변경 전 프로파일에서 `_page_images`는 851회/누적0.2766초,
`extract_image_bytes`는 2,781회/0.2516초, Pillow PNG `_save`는 56회/0.1931초였다.
Flate 샘플을 재압축하지 않고 PNG 컨테이너로 감싼 64×64 RGB 시험은 픽셀은 같지만
476바이트였고 기존 Pillow 결과는 243바이트였다. SHA-256도 달랐다.
따라서 PNG 직접 감싸기는 바이트 동일성을 보장하지 못하며 이번에는 제안으로만 남긴다.
이미지·필터·PDF reader 파일은 변경하지 않았다.

## 검증 입력과 방법

공개 PDF 2,281건은 pdf.js 983, LibreOffice 24, press-pairs 375,
press-pairs-holdout 217, holdout2 232, holdout3 233, holdout4 217건이다.
HWP/HWPX/DOC/DOCX/PPT/PPTX/XLS/XLSX는 공개 코퍼스에서 seed20261101로 각각110건,
총880건을 선택했다. 내부 문서는 사용하지 않았으며 코퍼스는 읽기만 했다.

`.codex-work/validate.py`는 저장소의 `scripts.probe_output_speed.measure_file`로
Markdown·JSON·평문·진단 SHA-256을 수집하고 공식 `compare` 명령으로 비교한다.
전수 성능은 파일별2회 최솟값, 10ms 미만 의심 파일은20회 중앙값으로 재검사한다.
배치 성능은 Python3.9/3.12 각각 전·후·후·전·전·후 순서로
같은 PDF300건과 HWP/DOCX/XLSX각110건을 측정한다. 파싱 및 네 단계 전체 합계를 모두 기록한다.

## C 안전성과 호환성

실물 표178개·스트림115개에서 가져온 입력과 손상·절단·중복·폭·큰 정수 변형을 포함한
차등100,000건(table50,000 + stream50,000)이 타입·사전순서·반환값·경고·커서 차이 없이 통과했다.
동일100,000건을 최종 C 소스의 ASan+UBSan 빌드로 실행해 통과했다.
C SHA-256은 `820acdc637f9cab63815e50f8ed7a43372eee9191facfc93d3cee614722f3567`이다.

3.13 헤더로 별도 빌드한 최종 `_cobjects`를 Python3.12.12에서 로드하여 PDF300건을
변환했고 기존3.9 헤더 빌드와4종 해시 차이0이었다. 제한 API는0x03090000이며
새 `#` 포맷이나 확장 모듈/빌드 의존성을 추가하지 않았다.

재현 자료는 `.codex-work/fuzz_xref.py`, `sanitize-reproduce.sh`, `abi_check.py`,
`final_sequence.sh`, `run_performance.py`, `final-source-hashes.json`과 각 로그에 보존한다.
ASan은 clang의 `-fsanitize=address,undefined -fno-omit-frame-pointer -ffp-contract=off`를 사용했고
런타임 주입은 자기 프로세스에만 했다. 다른 프로세스 attach나 GUI 조작은 하지 않았다.

### 최종 프로파일

같은 수집 wrapper의 PDF300건 프로파일에서 xref table 누적은0.08450→0.00602초, xref stream은0.10516→0.01314초, 셀 런 렌더는0.08337→0.03221초였다. `_markdown_runs` 호출은36,672→6,240회로 줄었다. 프로파일은 교대 성능 게이트를 대신하지 않는다.

이 PDF 표본의 `_find_recursive` 35,269회는 직접 호출하는 제목 추정 경로에 남아 있으며 `_find_iterative` 호출은0회였다. 기존 단언과 소유 범위를 지키기 위해 그 직접 호출 경로는 바꾸지 않았다. 모델 순회 변경을 이 PDF 배치의 개선 근거로 주장하지 않는다.

**합류 보류.** 정확성·안전성은 통과했으나 PDF −8%, 다른 형식 손해0, 정해진 전수 회귀0, 외부 무부하 조건을 충족했다고 주장할 수 없다. 구현은 미커밋 후보로 남긴다. 다음 합류 판단에는 통제된 부하에서 전체 성능 게이트 재실행과 제목 추정 직접 호출 경로의 소유 범위/호출 계약 검토가 필요하다.

원자료는 `results-summary.json`, `reg-{before,after}.json`, `regression-summary.json`, `reg-recheck-*.json`, `large-recheck-*.json`, `bench-*.json`, `profile-{baseline,after}*`다. 빌드 중간물과 별도 sanitizer/3.13 바이너리는 검증 뒤 정리한다.

최종 정리에서 `build/`와 별도 sanitizer/3.13 바이너리를 제거하고 일반 가속 `.so`와
재현 코드·로그를 보존했다. 3.13 Python으로 `.codex-work/abi313-build.py`를 실행한 뒤
3.12 Python으로 `abi_check.py`를 실행하면 ABI 검증을 재현할 수 있다.
문서 추가 뒤 경로·릴리스 계약11개와 ruff를 재확인했고 최종 소스 해시는 변하지 않았다.
