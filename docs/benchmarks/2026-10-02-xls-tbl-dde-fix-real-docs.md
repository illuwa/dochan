# XLS TABLE·DDE 리뷰 반영 실물 검증

2026년 10월 3일 공개 문서를 읽어 이전 판정을 다시 점검했다. 수식 방향과 DDE 플래그의 명세 근거는 리뷰어가 원문을 확인해 전달한 [MS-XLS] 2.4.319와 2.4.105 조항의 요약이다. 이번 작업에서 원문을 독립적으로 열어 확인하지 않았으므로 이를 **명세의 2차 전달 근거**로 분류한다. 아래의 TABLE 레코드 길이·플래그·셀 수와 DDE 원시 문자열은 공개 문서의 **직접 바이트 관찰**이다. DDE 수식의 작은따옴표 표기는 Excel 화면에 대한 **2차 자료**에 근거하며, 독립 XLSX 짝은 없다.

| 칸 | 표본 파일 | 정답 근거 | 기대 | 실제 | 판정 |
|---|---|---|---|---|---|
| XLS PtgTbl 단일 행 입력 | `testArraysAndTables.xls` | 공개 원시 TABLE의 `fRw=1`(0x0004), 범위 C27:E28, 입력 B26과 캐시 배열을 관찰했다. 예약 비트는 [MS-XLS] 2.4.319 요약에서 무시 대상으로 분류한다. | 6셀의 캐시를 유지하고 `TABLE($B$26,)`를 표시한다. 예약 비트가 추가되어도 방향은 같다. | 공개 6/6셀에 행 입력 수식을 표시했다. 예약 비트 0x0006은 합성 테스트로만 확인했다. | 공개 배치에 6/6셀 일치한다. 예약 비트가 설정된 실물은 없으므로 그 조합의 실물 판정은 미검증이다. |
| XLS PtgTbl 단일 열 입력 | `44958.xls`, `testArraysAndTables.xls`, `data-table/mortgage.xls` | 원시 플래그 0x0000인 세 TABLE의 입력이 각각 B5, B32, B3이다. 머리값과 캐시의 변화 방향도 일치한다. | 18셀, 9셀, 3셀에 열 입력 `TABLE(,입력)`을 표시한다. | 총 30/30셀에 열 입력 수식을 표시하고 캐시를 유지했다. | 직접 바이트 관찰과 30/30셀 일치한다. 동명 XLSX 수식 정답은 없다. |
| XLS PtgTbl 두 입력 | `44958.xls`, `testArraysAndTables.xls`, `data-table/mortgage.xls` | 원시 플래그 0x0008 또는 0x000c인 세 TABLE의 행·열 입력 좌표와 머리값·캐시를 확인했다. | 각각 24셀, 24셀, 6셀에 두 입력 `TABLE(행입력,열입력)`을 표시한다. | 총 54/54셀에 두 입력 수식을 표시하고 캐시를 유지했다. | 직접 바이트 관찰과 54/54셀 일치한다. 동명 XLSX 수식 정답은 없다. |
| XLS PtgTbl 손상 | `44958_1.xls` | 원시 TABLE은 18바이트이며 플래그 0x0003이다. [MS-XLS] 2.4.319 요약의 TABLE 길이는 16바이트다. | E4의 캐시를 유지하고 길이 경고를 남긴다. | 1/1셀에서 캐시를 유지한다. | 손상 표본으로 판정하며 수식 복원에 포함하지 않는다. |
| XLS DDE NameX | `49219.xls` | SupBook의 서비스·토픽, ExternName의 항목, NameX 인덱스를 직접 대조했다. 쉼표가 있는 항목 144셀의 원시 문자열도 확인했다. | DDE 1,399셀을 표시하고 쉼표 등 구분자가 있는 토픽·항목은 인용한다. | 1,399/1,399셀에 수식을 표시했다. 쉼표 항목은 예를 들어 `IDT|IMKB!'SAGYO.IS,Son,1,0,2'`처럼 인용한다. | 원시 구성 요소와 셀 수는 1,399/1,399 일치한다. 인용 표기의 독립 실물 정답은 없어 표기까지 검증됐다고 판단하지 않는다. |
| XLS DDE `fOle` 및 OLE `fOleLink` | `49219.xls` | 원시 `fOle` 이름 두 개를 확인했다. 두 플래그의 차이는 [MS-XLS] 2.4.105 요약에 근거한다. | `fOle`은 DDE `StdDocumentName` 항목으로 분류하고 `fOleLink`는 OLE 링크로 분류한다. | 공개 이름 두 개를 DDE로 분류했다. 이 이름을 참조한 수식은 0셀이다. | 실제 참조 수식과 OLE 표기는 미검증이다. |
| XLS PtgElf `18 0a` | `forum-mso-de-49320.xls` | 원시 토큰 `18 0a 02 00 01 80`을 확인했다. | 피연산자 구조가 확정되기 전까지 캐시를 유지한다. | 1/1셀에서 캐시와 경고를 유지한다. | 미지원·미검증이다. |
| XLSX `dataTable` 삭제 입력 | 공개 POI XLSX 352파일 | ZIP으로 열 수 있는 335파일의 워크시트 XML에 `f t="dataTable"` 수식이 없다. `del1`·`del2` 분기는 합성 OOXML로 확인했다. | 삭제된 입력을 정상 좌표로 표시하지 않는다. | 합성 테스트에서 캐시를 유지한다. | 실물 표본이 없어 미검증이다. |

공개 XLS 721파일의 FORMULA 95,932셀 중 95,922셀에 수식을 표시했고 10셀은 미표시다. 미표시 10셀은 손상 TABLE 1셀, PtgElf 1셀, 기존 밀집 격자 상한 8셀이다. 원시 TABLE 보조 집계는 비 OLE 입력 46파일에서 읽지 못했지만, 문서 리더 전수 프로브의 예외는 0개다. 공개 POI 동명 XLS/XLSX 36쌍의 1,070 수식은 정확 일치 986셀, 공백 차이만 있는 73셀로 총 1,059셀 일치를 유지했다. 직전 HEAD 소스와 최종 코드를 각각 실행해 비교한 공개 XLS 721파일의 Markdown·JSON 해시와 오류 수는 719파일에서 동일하다. 변경된 두 파일 중 `49219.xls`는 DDE 표기가 달라졌고 `44958_1.xls`는 경고 JSON만 달라졌다. 공개 XLSX 356파일의 Markdown·JSON 해시와 오류 수는 356/356 동일하다. 합성 공격 입력의 TABLE·ARRAY 각 2만 셀 × 레코드 1,000개는 테스트에서 각각 1초 이내로 처리했다. 공개 문서를 저장소에 복사하지 않았고 비교 산출물에는 해시와 요약만 저장했다.
