# HWP 차트 리뷰 반영 실물 검증

`python -m scripts.verify_hwp_charts HWP_DIR HWPX_DIR --internal INTERNAL_DIR`로 공개 HWP와 HWPX를 대조했다. 프로브는 `olefile`로 HWP의 DocInfo 슬롯·저장소 ID와 GSO 참조 순서를 독립 판독한다. XML은 DOCTYPE·ENTITY를 사전 거부한 뒤 별도로 읽는다. 출력은 계열마다 범주·값의 순서를 비교하며, HWP/HWPX 짝은 차트 표·캡션·제목과 같은 컨테이너의 앞뒤 문단을 비교한다. `olefile`은 실물 검증 도구에만 필요하며 dochan 런타임 의존성이 아니다.

| 차트 제목/데이터 · HWP | `rhwp-곡선이있는분산형.hwp`와 `곡선이있는분산형.hwpx` | DocInfo 슬롯 1의 STORAGE ID는 3이며, `BIN0003.OLE`의 차트 XML과 HWPX `Chart/chart1.xml`의 SHA-256이 같다. | 편집 전 `BIN0001`이 아니라 현재 저장소 ID 3을 사용한다. | 원문 XML과 출력 차트가 일치했다. | 통과 |

공개 차트 문서는 총 46개로, OOXML 캐시 35문서 38참조, `Excel.Chart.8` 5문서 8참조, 구형 한컴 차트 7문서 33참조다. 범주별 문서 수는 겹칠 수 있다. 공개 OLE 참조 중 그 밖의 26개는 일반 개체이며, 1개는 길이 접두어가 맞지 않는 짧은 자리표시자다. 후자는 실제 손상 차트가 아니므로 공격 입력 검증 수치에 넣지 않았다. 압축 해제·CFB 길이·수만 개 OLE·셀 예산·BinData 실패는 합성 테스트로 확인했다.

공개 HWP 5,364개 파일(소문자 `.hwp` 5,363개와 대문자 확장자 1개)을 차트 구현 전 기록과 최종 구현에서 Markdown SHA-256으로 비교했다. 해시가 달라진 40문서는 모두 독립 조사에서 차트 OLE가 확인된 문서였다. 앞선 차트 구현과 비교하면 5문서가 더 달라졌으며, 이는 Excel 차트 5문서다. 최종 문서 단위 예외는 0개, 새 `ERR`는 0개, 기존 `ERR`는 3줄·3문서 그대로다. 새 `WARN` 11줄은 빈 범주 번호 채움 8줄, 읽을 수 없는 OLE 크기·머리글 2줄, 없는 BinData 참조 1줄이다. 출력 차트 표는 46개이며, 최상위 42개와 표 셀 안 4개다. 남은 임시 `ChartReference`는 0개다.

내부 HWP/HWPX 76쌍에는 이 기능의 양성 표본이 없었다. 쌍 비교 지표는 HEAD와 최종 구현에서 같았다. 내부 파일명과 내용은 기록하지 않았다.
