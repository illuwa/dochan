# XLS 숫자 서식 리뷰 반영 실물 검증 (2026-10-03)

대상은 README `Supported Elements`의 XLS `날짜/숫자 서식` 칸이다. 비교 기준은 v1.12.0과 리뷰 반영본이다. XLS/XLSX 짝 출력은 두 형식이 같은 서식기를 사용하므로 보조 지표로만 사용했다. 주 기준은 공개 POI 파일 안에 Excel이 저장한 `TEXT()` 수식 캐시와 `54686_fraction_formats.txt`의 표시 문자열이다. 분수 표의 열 너비 맞춤 공백은 Markdown 표시 계약에 없으므로 공백을 제거해 비교했고, 원문 공백까지 같은 경우도 별도로 셌다.

`TEXT()` 캐시는 `NumberFormatTests.xlsx`, `DateFormatTests.xlsx`, `ElapsedFormatTests.xlsx`, `FormatChoiceTests.xlsx`, `FormatConditionTests.xlsx`, `GeneralFormatTests.xlsx`, `TextFormatTests.xlsx`, `NumberFormatApproxTests.xlsx`, `DateFormatNumberTests.xlsx`의 832행을 모두 검사했다. 이 중 숫자 입력 802행과 비숫자 입력 30행이 있다. 591행은 수정본도 Excel 캐시와 다르므로 정확 일치로 세지 않았다. 이 수치는 서식 전체의 일치율이며, 리뷰가 지적한 사례의 통과율과 혼동하지 않는다. `TEXT()` 원시 값 폴백 111행도 정확 일치로 세지 않았다.

분수 표의 총 3,540셀은 v1.12.0에서 30셀, 수정본에서 3,424셀이 공백 정규화 후 일치했다. 개선은 3,394셀이고 기존 일치의 회귀는 0셀이다. 공백까지 포함한 표시 문자열을 양끝만 자른 정확 일치는 2,112셀이다. 남은 116셀은 모두 가변 분모이다. 고정 분모에는 남은 불일치가 없다.

공개 XLS 720개와 XLSX 352개의 전체 Markdown SHA-256을 v1.12.0과 비교했다. XLS는 553개 유지·167개 변경, XLSX는 328개 유지·24개 변경이었고 양쪽 파싱 실패는 0건이었다. 원시 숫자 셀의 표시 문자열도 디스크에 쓰지 않고 셀별 SHA-256만 저장해 변경 원인을 분류했다. 해시 자료는 벤치마크 요약에만 사용하고, 문서 본문이나 복호화한 패키지는 디스크에 저장하지 않았다.

XLS 원시 셀 705,679개 중 174,746개 표시 해시가 바뀌었다. 서식별로 통화·회계 81,754, 일반 소수 83,634, 분수 3,512, 백분율 2,424, 시각 1,423, 날짜 1,387, 앞자리 채움 350, General 198, 경과 시각 50, 과학 표기 14셀이다. XLSX 원시 셀 887,477개 중 2,130개 표시 해시가 바뀌었다. 서식별로 일반 소수 1,791, 통화·회계 78, General 261셀이다. 원시 셀 추출기는 XLS 39개와 XLSX 18개의 손상 파일에서 셀 좌표를 얻지 못했으므로 이 파일들은 전체 Markdown 해시에 포함하되 셀 종류별 집계에서는 제외했다. 이 57개 파일의 전체 Markdown 해시는 모두 동일했다. 암호화된 `58616.xlsx`는 복호화한 패키지를 메모리에서만 읽어 셀 해시 분류에 포함했다.

공백이 포함된 조건식, 정수 `0`, 앞자리 채움, 고정 분모, BIFF5 FORMAT, 빈 서식 구역, 회계 음수, 통화 기호 위치와 과학 표기 지수 폭은 합성 단위 테스트로 확인했다. 남은 가변 분모 116셀과 `TEXT()` 캐시 미일치 591행은 지원 한계다. 이 한계를 명시하는 조건으로 XLS `날짜/숫자 서식` 칸에 ✅를 제안한다.
