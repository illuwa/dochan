# PDF 선분 배열·해석기 왕복·줄 조립 검증

## 판정

구현과 출력 동일성 검증은 완료했지만 **성능 합류는 보류**한다.
300개 교대 측정은 Python 3.9에서 5.69%, 3.12에서 2.40% 단축되어
목표 12%에 못 미쳤다. 전수 파일별 최소 시간 게이트에도 회귀가 남았다.
GC 수집 시점이 파일별 시간에 영향을 준다는 진단 결과로 원래 실패 판정을
통과로 바꾸지 않았다.

## 변경

- `_cinterp`의 `SegmentList`는 정규화된 좌표와 정수/실수 태그를 C 배열에 저장한다.
  인덱스 접근 때만 `paths.Segment`를 만들고 캐시한다. 길이, 음수 인덱스,
  반복, 슬라이스, 비교, `clear()`를 지원한다. 기존 리스트를 넘기는 직접 호출도 유지한다.
- `_csegments.h`와 모듈 capsule로 `_ctables`가 배열을 직접 읽는다.
  외부로 노출된 캐시 원소는 변경된 속성을 읽는다. 미노출 원소는 안전한 수치 범위에서
  축 판정과 평균 계산도 C로 처리한다. 정수 합·차가 정확한 범위를 벗어나면 기존 객체
  연산을 사용한다. 짧은 선분도 직접 읽으며 기존 점선 조립 순서를 유지한다.
- 생성자나 속성 접근에서 배열을 비우는 재진입은 generation 검사와 참조 보유로 보호한다.
  GC 순환 참조, 생성 실패 후 재시도, 상한 초과 및 이미 출력한 짧은 선분 제거를 검증했다.
- 표준 추출기의 BDC/BMC/EMC/gs는 C 내부에서 처리한다. 마킹 집합은 해석기 속성으로,
  스택과 overflow는 기존 추출기 속성으로 읽을 수 있다. 경고, 중복 ID,
  resolver 호출·예외, 링크 신뢰 상태와 콜백 재정의를 보존한다.
  Do/BI/비네이티브 글자 연산은 기존 Python 경로를 유지한다.
- `_clines`는 출력 필드가 아닌 방향 선택에만 쓰는 정수 방향 성분을 C 경로에서 받는다.
  전체 조각이 유지되고 타입·IEEE 비트가 바뀌지 않는 경우에만 클리핑 원소를 재사용한다.
- 새 헤더를 sdist 목록과 빌드 의존성에 등록했다. 런타임 의존성 추가는 없다.

`tables.py`, `reader.py`, `_ctables_text.h`, `layout.py`, README와 CHANGELOG는 수정하지 않았다.
기존 차등 테스트의 단언은 유지하고, 비교 도우미에서 의도적으로 바뀐 `SegmentList`
컨테이너만 리스트로 정규화했다. 모든 원소 필드·타입·비트 비교는 유지된다.

## 기준과 재현

기준은 수정하지 않은 `base-round3`, HEAD `73a05cb`이다.
작업 브랜치의 시작 HEAD도 같다. 공개 PDF 2,281개만 읽었다.

| 묶음 | PDF 수 |
|---|---:|
| pdf.js | 983 |
| LibreOffice | 24 |
| press-pairs | 375 |
| holdout / holdout2 / holdout3 / holdout4 | 217 / 232 / 233 / 217 |

본문과 내부 문서는 저장하지 않았다. 검증 산출물에는 공개 경로·해시·시간·개수만 남겼다.
작업 로그와 재현 스크립트는 `.codex-work/`에 있다.

```sh
DOCHAN_BUILD_ACCEL=1 python setup.py build_ext --inplace --force
python -m pytest tests/ -q -p no:cacheprovider
DOCHAN_DISABLE_ACCEL=1 python -m pytest tests/ -q -p no:cacheprovider
python -m ruff check dochan scripts tests setup.py
python .codex-work/run_sample.py
python .codex-work/verify_corpus.py --execute
```

빌드·전체 테스트는 Xcode Python 3.9.6, 전수 게이트는 bench Python 3.12.12로 실행했다.
`verify_corpus.py`는 기존 `scripts.probe_output_speed`를 PDF만 대상으로 호출한다.
가속 켬·끔 각각 전→후→후→전으로 두 번씩 측정하고, 파일별 최솟값을 비교한다.
1.2배 이상 후보 중 10ms 미만 파일은 각 소스에서 20회 재검사한 중앙값으로 판정한다.
300개는 제공된 `sample-pdf-300.json`을 그대로 쓰며 Dochan 생성과 Markdown 변환 합계를
전→후→후→전→전→후로 측정했다. 해당 측정 중 다른 자체 검증 작업은 실행하지 않았다.

## 전수 게이트

| 모드 | 파일 수 | 네 출력 해시 차이 | 변환 실패 | 최종 1.2배 회귀 | 작은 파일 재검사 |
|---|---:|---:|---:|---:|---:|
| 가속 켬 | 2,281 | 0 | 0 | 35 | 98개 모두 해제 |
| 가속 끔 | 2,281 | 0 | 0 | 1 | 7개 모두 해제 |

네 출력은 Markdown, JSON, 일반 텍스트, 진단이다. 증거는
`corpus-gate/summary.json`, 모드별 summary 및 원본 측정 JSON이다.
가속 켬 최종 전수 실행 시간은 25.2→23.9→23.9→25.1초였다.
이전 26.6→25.2→30.7→35.6초 및 회귀 47건 기록은 `corpus-gate-pre-capi/`에 보존했다.
가속 끔 최종 실행 시간은 111.3→110.9→110.3→111.4초였다.

가장 큰 켬 회귀인 공개 `156782521.pdf`는 최종 최소 합계 53.31→110.41ms였다.
원래 파일 순서의 앞 48개를 재생한 GC 진단에서는 계측으로 수집 시점이 이동하여
기준 구현에 56.28/57.30ms의 2세대 GC가 붙었다.
파일 직전 GC를 수행한 최종 별도 진단은 파싱 48.09→58.67ms였다.
이전 진단의 49.65→46.62ms와도 방향이 달라 GC만으로 전체 회귀를 설명할 수 없다.
이 결과는 GC 수집 시점에 민감함을 보여 주지만, 계측이 원래 실행을 바꾸므로
전체 회귀를 거짓 회귀로 판단하거나 합류 게이트를 면제하는 근거로 쓰지 않는다.
끔의 남은 공개 표본 `156782416.pdf`는 15.32→18.55ms, 1.210배였다.
진단 스크립트와 원자료는 `trace_gc_prefix.py`, `gc-diagnostic-summary.json`에 있다.

## 프로파일에서 확인한 범위

| 항목 | 기준 | 변경 |
|---|---:|---:|
| Interpreter.next 호출 | 40,784 | 6,102 |
| Segment.__post_init__ | 395,206 | 2,682 |
| Python _Line 생성 | 1,576 | 13 |
| dataclasses.replace | 47,159 | 46,680 |

줄 조립은 실제 계측 29,316회에서 `None` bailout이 처음부터 0회였다.
Python 프레임 시간만으로 bailout을 단정한 초기 가정은 성립하지 않았다.
정수 방향 때문에 Python 행 생성으로 넘어가던 경로를 줄였으며,
남은 13행은 링크 12행·주석 1행이다.

`replace`의 기준 호출자는 `_cheadings.sized_runs` 42,041회, Markdown 2,812회,
주석 연결 1,827회, 클리핑 479회였다. 소유 범위의 479회만 제거했다.
다른 작업자의 `_cheadings`를 수정하거나 전체 47,159회를 없앴다고 주장하지 않는다.
최종 프로파일은 `profile-after-tottime.txt/.prof`, 새 기준 프로파일은
`profile-baseline-current.txt/.prof`이며, 제공된 원본 프로파일도 보존했다.

## 정확성·메모리·ABI 검증

- 선분: 공개 PDF 40개의 경로 연산 3,532개를 포함해 100,000개 스트림 변형.
  긴 선분 172,159개·짧은 선분 6,940개의 좌표 타입·IEEE 비트·순서·경고 차이 0.
- 마킹: 100,000개 스트림, 1,853,539개 연산의 집합·스택·overflow·경고·링크 상태 차이 0.
- 표 입력: 배열과 객체 리스트 100,000건 비교, 비어 있지 않은 표 37,954건과
  짧은 선분 71,571개 포함. 중첩 출력 필드·타입·비트·경고·예산 차이 0.
- 줄 방향 및 클리핑: 각각 100,000건 차등 비교, 차이 0. 표본 300개에서
  클리핑 479개도 기준 함수와 일치했다.
- 선분/표 경계 테스트 128개는 양 모드 통과. 재진입 누수와 입력 변이 회귀는
  먼저 실패를 확인한 뒤 수정했다. 새 마킹 20개와 줄 방향 7개도 실패→통과를 확인했다.
  C의 `PySequence_GetItem`과 Python 인덱싱이 음수 인덱스를 한 번씩만 보정하는지도 검증했다.
- 최종 `_cinterp`, `_ctables`, `_clines`를 Python 3.9 헤더로 엄격 컴파일했다.
  ASan+UBSan 격리 빌드로 696개 테스트 통과, 진단 0. LSan은 활성화하지 않았다.
- 세 모듈을 Python 3.13 헤더로 별도 빌드하고 Python 3.12.12에서 실제 import했다.
  기존 3.9 빌드와 공개 PDF 300개의 네 출력 해시 차이 0, 실패 0.
- 최종 전체 테스트는 켬 7,261 passed/39 skipped/14 xfailed,
  끔 7,251 passed/49 skipped/14 xfailed이다. ruff도 통과했다.
  sanitizer 및 교차 ABI 검증 종료 후 소스 해시도 대조했다.

## 남은 판단

출력 동일성과 안전성 결과는 성능 목표 달성을 뜻하지 않는다.
12% 단축 목표와 전수 파일별 회귀 0 조건은 충족하지 못했다.
GC 시점에 민감한 회귀를 어떻게 재검증할지 합류 담당자가 판단해야 한다.
전역 GC 설정을 바꾸거나 실패 파일을 제외해 통과시키지 않았다.
커밋·푸시·릴리스는 하지 않았다.
